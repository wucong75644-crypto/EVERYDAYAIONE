# 淘宝主图输出尺寸

## 已确认行为

图像高级设置的「输出格式」下方增加「输出尺寸 / 淘宝主图 1440×1440」按钮。
仅在宽高比为 1:1 时可选，与 1K、2K、4K 分辨率独立。切换非方形比例或 Auto
时同时取消选中并保存；改变分辨率、格式或生成数量不取消选中。

默认关闭，旧对话缺少字段时关闭。当前对话自动保存到 chat_settings；刷新、退出重进、
切换对话均恢复自己的选择。「保存为默认」在当前浏览器保存新对话默认值，不覆盖旧对话；
「恢复默认」关闭按钮并同步保存当前对话。

## 状态与参数

- 前端 ImageSettings.taobaoMainImage：按钮状态。
- 对话 chat_settings.image_taobao_main_image：对话持久化状态。
- 生成 params.taobao_main_image / task.request_params.taobao_main_image：发送时的任务快照。
- generation_params.taobao_main_image：随消息保存，供重新生成 / 重试提取。

设置变化先同步暂存完整快照，按用户和对话隔离，再通过原更新接口保存。
保留 500ms 合并窗口，同一对话的写入串行执行，旧响应不能删除新快照。
保存失败提示并保留快照，重开对话时恢复并补交。新对话创建前也保存浏览器草稿，
创建时携带设置，并将待保存状态交接到新对话，避免异步详情响应覆盖用户选择。
浏览器禁用或耗尽本地存储时提示用户等待后台保存后再刷新。

生成任务使用发送时的开关，生成期间再修改设置只影响后续任务。
前端及任务创建层按请求宽高比约束按钮；批次覆盖为非方形的单张任务关闭转换。

## 处理链路

模型生成 → 原有下载与 MIME 校验 → 可选本地缩放 → 原有 NAS 保存 → 原有 CDN 上传与缩略图 → 原有消息返回。

处理位置：services.file_upload.download_url_to_workspace，写盘前。
由 TaskCompletionService 从任务快照将开关传给共享持久化 helper。
未开启时不解码、不重编码图片，继续原有字节与上传路径；视频不处理。

开启时使用 Pillow Lanczos 直接 resize 到 1440×1440，不检测源图片宽高、
不根据源尺寸分流、不裁切。保留文件格式及 PNG 透明通道。
1K 放大会增加像素而不增加真实细节，JPEG 会重新编码。
不重新调用模型，不改变生成分辨率、数量或积分计算。

转换失败时用原始字节再尝试一次；两次均失败，继续以原始字节保存、上传和返回。
该降级不取消设置、不重新生成、不额外扣模型积分。
仅转换成功时写入 width/height=1440，防止调用方的估算尺寸覆盖真实输出尺寸。
转换失败、下载失败或上传失败继续沿用现有降级，不误标为 1440。

## 定向验证

- 1K、2K、4K、已为 1440 以及不同源宽高的输入均直接转换为 1440。
- 实际写入文件、上传文件、返回尺寸与文件大小、sidecar 元数据一致。
- PNG 透明通道及 JPEG 格式保留；未选中及两次失败的原图字节保持不变。
- 首次失败后第二次成功、两次失败原图降级、视频不处理。
- 刷新合并窗口、保存失败恢复、对话与用户隔离、连续操作、默认保存/恢复、首次创建状态交接。
- 任务快照及消息重新生成携带开关；模型提交参数和计费不携带该后处理选项。
