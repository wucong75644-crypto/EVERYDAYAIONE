## 已实现的约束

- 新聊天执行检查点使用 v2。组合包含本轮动作、不可变参与版本与正文哈希、选择来源、当前作用域控制者、工具交集、领域工作流链接和组合修订号。
- `coordination.py` 做确定性组合校验。加载不等于控制当前步骤；同一步骤的同一作用域只能有一个控制者。声明不授予工具和业务权限。
- 手选和固定集合整体加载；失败不提交部分集合。自动候选只拒绝冲突候选及不能满足依赖的候选，保留独立兼容辅助。相邻激活调用按声明依赖排序，不跨越退出或业务调用屏障。
- 原手选加载失败的安全反馈保留；固定方法失败继续明确停止，不降级成没有工具限制的聊天。
- 首次暂停前保存动作与配置，恢复不重新发现或重新路由；v1 检查点仍按原格式恢复，不补入新协调声明或升级格式。当前权限仍可收窄，不会因退出方法恢复原快照之外的权限。
- 电商入口读取当前控制方法。手选内联策划方法时不再强制加载服务器策划方法；使用已登记协议的自定义 Skill 可成为服务器控制者，无须另加规范名称 Skill。解释和无关话题不占用策划控制权。
- 策划/生成混合批次、动作转换冲突返回工具错误，不执行业务请求；模型可读取拒绝事实调整调用。
- 会话固定写入在原事务锁内检查整个配置；计划任务仍使用原 v1 配置快照并保留历史身份，新组合校验不改变数据库既有调度格式。直接图片媒体入口按策划动作检查固定与手选方法，保持原生媒体参数为执行依据。
- 作者可通过可读选项声明已有执行协议；导入和发布共享契约校验。旧 metadata 未声明时原样序列化；契约不修改旧正文或旧版本哈希，不增加管理员审批要求。
- 配置写入的确定拒绝与网络不确定分开。确定冲突保留选择且可打开固定方法管理；不自动解绑。网络结果不确定仍先核对服务器状态。

## 原子性和受理边界

迁移 `339_skill_composition.sql` 保留原有任务、执行令牌、租约、Actor 与数据库范围约束，在同一 PostgreSQL 事务内写入检查点、组合投影和电商工作流投影。工作流链接必须与组合内的链接完全相同；同一组合可幂等保存，新组合须携带当前 expected revision 且修订号递增。

模型正文、工具范围与领域受理使用同一组合。服务器策划回写方案链接通过 Actor 的检查点保存回调，链接变化会推进组合修订号。图片受理使用受信任 executor 传入的组合版本，数据库再次核对父任务版本；模型参数不能指定该版本。既有受理重放在新请求检查之前识别，保留原结果，不重复扣费或重发。

控制批次先修改副本；准备或保存失败恢复内存中的方法、消息、工具上下文和领域投影。保存响应丢失时读取当前执行者的检查点，仅完整 payload 相同才承认已保存；仅组合号相同不足以继续。没有检查点写入器时，新组合不能进入模型或业务执行。

## 两项独立故障修复

1. 商品参考角色统一由 `reference_roles.py` 判断，三处校验复用同一语义。兼容已知 `product/商品图`、detail 等写法；风格图和未知值不自动当商品证据。工具说明使用规范 `product` 示例。
2. DashScope 传输层为超过 64 字符等不适用的内部调用 ID 生成稳定摘要 ID，调用和结果成对转换，两种协议使用同一算法；内部存储、审计 ID 不变，消息不原地修改。保留供应商内置工具 replay 项，不截断内部 ID。

## 发布与回滚

- 新写入依赖迁移 339，不能先启动新 worker 再补函数。所有消费者必须能够双读 v1/v2；不能让旧 worker 消费新检查点。
- 生产发布仍仅走项目本地 `deploy/release.sh`，本任务未获得发布指令，没有执行生产迁移或重启。
- 首选回滚到保留双读能力的代码版本，并保留迁移，已有 v2 任务继续按保存身份完成或受控停止。
- SQL 回滚文件检测任一 v2 任务投影存在即拒绝恢复旧函数。不能为回滚删除历史任务或组合，不能直接回到仅支持 v1 的 worker。
