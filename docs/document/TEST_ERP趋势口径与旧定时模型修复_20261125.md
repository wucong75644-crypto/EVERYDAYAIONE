# ERP 趋势口径与旧定时模型修复及真实复测（2026-11-25）

状态：仅本地，未提交、未部署，原工作树保留。既有聊天/图片/Skill 修复保留；本次修改集中于 ERP 参数合同、订单趋势聚合和旧定时解析的模型调用。

## 已证实原因与调用链

### ERP

入口 `tool_executor._erp_agent` → `ERPAgent.execute/_extract_plan` → ModelGateway → `submit_query_plan` → `_sanitize_params/normalize_order_scope` → 部门 `execute` → `params_to_filters` → `UnifiedQueryEngine` → RPC → `OrderClassifier` → ToolOutput → `_build_multi_result` → 主聊天引用。

发现三个衔接缺口：

1. 计划合同要求 order 和 daily_stats 都返回 order_scope；查询引擎却只允许 order 的 scope，且不允许 scoped trend。预聚合 daily_stats 不能恢复逐单租户分类，不能通过删掉 scope 或改用日统计来“成功”。
2. 原生工具 params 只声明 doc_type/scope，其余字段仅存在提示词和样例中，模型字段与执行接口不完整对齐。实验中强制少量字段导致时间、指标等缺失；一次扩大到全部转换器字段的实验又引入虚构仓库和 work_order_id。这两个候选均未保留。最终复用既有 local_data 的查询字段，只显式补充计划所需的时间、分析和依赖字段，不增加语义分类器。
3. 真实模型常返回合法的 `time_type=pay_time`。转换器只读取 time_col，先生成 doc_created_at 范围；extract_time_range 随后以该范围决定时间列，覆盖了原本正确的付款时间意图。最终统一已有别名的编译：显式 time_col 优先，其次 time_type，最后沿用原表默认值。没有从用户文字猜时间列。

### 旧定时

`/api/scheduled-tasks/parse` → 组织和 task.create 权限 → 旧预填/显式字段/结构化预填 → `_call_llm` → 共享字段校验 → 表单。聊天主模型已经给出 definition 时仍直接进入既有 task_definition_input/ChangeSet，不产生第二次解析。

原 `_call_llm` 绕过统一网关并写死 qwen-turbo。真实探针 HTTP 429，code/type 均为 `limit_requests`，消息为当前请求额度限制。此证据不代表 SSL 过期，也不能断言是余额或全账号限流。

最终旧辅助解析复用现有 ModelGateway、`intent_router_fallback_model`（实测 qwen3.8-flash）和现有超时配置，关闭思考，关闭时释放会话。没有增加重试循环、备用解析器、关键字周期推断或新任务审批。供应商在其他模型上的未来限流仍可能发生。

## 修复职责与兼容范围

- 模型提取业务范围、指标、筛选、时间列及口径；后台编译明确字段，保留租户分类与组织过滤。
- scoped order trend 使用新增的七参数 `erp_order_stats_grouped` 重载，一次数据库聚合出时间桶、维度和原分类字段，再复用原 OrderClassifier 选择有效/全部/排除刷单/仅刷单。
- 六参数 RPC 原样保留，summary/compare 的现有调用不迁移；不改表、不写订单。新增 SQL 仍为 invoker，非授权角色不能读取订单表；有仅删除新重载的 rollback。
- 按上海时区聚合日/周/月，保留半开时间范围、归档表、店铺/平台/商品等维度。其他时间列筛选不会被丢弃，整数 in/not_in 按实际数据库类型执行；无数据时间桶补零，包含结束于中午的当天。
- daily_stats 不再被要求携带无法执行的订单分类口径；其原有预聚合查询保留。需要分类或付款时间的订单趋势由 order 路径执行。
- 未新增用户词表、词法路由、审批模型、存储系统或聊天状态机。运行中追加、图像派发、按编号执行、权限和恢复代码未在本轮再改。

## 开发中失败与撤销候选

- 第一真实批次12项定时通过；ERP测试的8项因测试脚本错误地强求 order_count、且冻结时间在当天下午与预期晚间订单不一致而失败，另1项是真实 DashScopeAPIError。未把这些原始pytest标记改成通过。随后按“销售额趋势”校验实际所需指标，固定会话时间以覆盖已声明数据，保留金额、时间列和scope断言。
- 仅两字段的强制 schema 候选丢失实际查询参数，9/9 ERP未完成；撤销。
- 扩展所有转换器字段的候选引入未经用户指定的 main/auto 筛选，8项被执行层拒绝，另1项供应商错误；撤销。
- 收敛为执行合同后，发现8次付款时间退回创建时间；据此修复 time_type/time_col 编译，而非改用户话术或放宽测试。
- 首次周粒度测试范围仅3天，触发既有 week→day 自动规则；改为完整周测试区间后保留原周起点/金额断言。
- 新增多时间列筛选测试发现新RPC投影缺少原时间字段，已补齐并验证；整数数组筛选、空日、午夜和归档也验证。
- 开发中一次工具字典括号错误导致测试收集失败，修正后重跑，未放行失败候选。

最初把一次长时间提取失败描述成“未返回口径”不够准确；后续已捕获原始错误，确认该次类型是 DashScopeAPIError。最终明确捕获的失败为供应商工具 grammar 编译超时。
