# Xmind 导入请求生命周期与可见性确认

2026-10-29，本地修复；实际生产状态以受控发布结果为准。本次不改导图原文、结构、归属空间、AI 处理或后台幂等约束，不自动部署。

根因证据：前端按账号/组织、空间、文件 SHA 保存 sessionStorage 请求编号。完成后既未清除记录，也未结束内存 attempt，后续同文件的新导入继续复用旧编号。后台正确返回旧操作的 `replayed + hidden`，不会擅自恢复已撤销/删除的数据；前端却无条件显示“框架与节点已建立，可以立即查看”与“完成”。新增两项回归在修复前均失败。

修复规则：

- 未确认的请求保留编号及原始空间 revision；每次发送前都必须成功保存重试记录，包含首次持久化失败之后的重试。丢响应、刷新重进、后端已提交但画布未确认时继续核对同一请求，避免重复添加。
- 后端结果与当前有权访问的画布 scene 一起确认：根节点必须出现在返回的目标空间中，才显示成功说明和“完成”。scene 未确认时保留请求编号并提供“重新核对导入结果”，禁止把静默 locate 失败视为可见。
- 确认完成后结束并移除浏览器待核对请求；用户之后主动导入同一文件使用新编号、当前空间 revision，仍新增在当前空间。
- 兼容旧浏览器记录。旧操作已撤销/删除时明确显示“本次没有新增内容”，不展示成功说明或附件进度，不显示“完成”；提供“重新导入为新导图”。该操作明确创建新编号，采用当前空间 revision，不自动恢复或修改旧导入。
- 准备、显示核对、成功和失败反馈分开；浏览器重试记录清理异常不伪装成画布同步失败。切换账号、空间后的迟到响应仍不进入新页面。

验证：组件覆盖旧隐藏记录、明确新导入、成功后的新编号、未知结果同编号、场景核对失败/重试、当前 revision、不同空间隔离与存储失败；完整画布回归覆盖导入后根节点实际可见与缺失时不报完成。

独立本地数据库验证旧请求隐藏、新请求新增、旧请求仍保持隐藏、重试新请求不重复。真实培训文件同样经过首次导入→撤销→核对旧记录 hidden→新请求重新导入→重放；可见新导图 85 个主题、36 张图片、21 个链接、6 个概要、37 个绑定文件（包含原件备份）。画布可见性使用 scene，而非历史详情读取 object 接口判断。

本地界面夹具实际操作“旧记录→重新导入→完成后查看库”，界面夹具与真实数据库验证分别记录，不冒充生产数据复验。无需数据库迁移；回滚本次前端代码即可，原内容和导入审计记录不删除。

最终验证：前端相关回归 433 项通过；后端导入与真实文件重新导入 13 项通过；类型检查、相关 ESLint 与生产构建通过。临时界面与服务已移除，其他暂停的五个文件哈希不变。
