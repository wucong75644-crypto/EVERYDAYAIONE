# 第一个 Skill 示例：参考图多方案提示词

本示例采用用户于 2026-09-19 提供的“基于参考图的多方案生图提示词生成器”。[原文](reference-image-prompts.source.md)保留用户内容，仅统一换行；[运行版 SKILL.md](catalog/platform/reference-image-prompts/v1/SKILL.md)合并重复要求，保留模式 A/B、动态主题推导、六套完整方案和各自负面提示词。

原文正文为 19,815 UTF-8 字节，超过现有 16,384 字节运行上限；运行版为 13,587 字节。没有放大运行上限或修改 Runtime。运行版补充无图/图不可读时请求上传、多图未指定时确认主图、尺寸未知不猜测，并将填写占位符改为读取当条聊天要求。指定主题时围绕该主题形成六个不同子主题。

## 用户使用

功能启用且组织分配完成后：

1. 在该组织的聊天中选择支持图片输入的聊天模型，上传一张参考图。
2. 点击输入栏 Skill 入口，选择“参考图多方案提示词 · v1”。
3. 输入“根据这张参考图生成六套方案”；模式、主题或配色等额外要求可以直接写在同一条消息中。
4. 发送后先看到“已启用 Skill · 参考图多方案提示词 · v1”，再收到参考图判断和六套完整方案。
5. 每套提示词可与原参考图一起复制到生图功能使用。此 Skill 自身只输出文字，不自动生成六张图片。
6. 下一条消息默认不再启用，需要时重新选择。

## 发布边界

- 稳定标识 `reference-image-prompts`，版本 `v1`，平台包。平台包身份不会自动授权所有组织；必须通过现有服务端 assignment 分配给明确组织。
- 仅在个人会话的 general / interactive 模式中手动选择；`model_selectable=false`，不触发模型自动选择、企微群或计划任务。
- `allowed_tool_names=[]`，不申请任何业务工具。图片由既有聊天多模态输入提供，Skill 不读取 NAS 中的用户图片或自行查询历史文件。
- 当前仓库示例不是自动种子数据。提交、代码部署不会自动导入包、写入 assignment 或开启任何开关。
- 用户已指定“蓝创”，对应组织 `eadc4c11-7e83-4279-a849-cfe0cbf6982b`，上线时仅为该组织创建启用的 assignment。

## 运维准备与验收

以下由当前任务完成，使用者不需要手工执行 SQL 或操作服务器：

1. 先确认目标组织，再核对独立受控 Skill 存储根和 backend 只读权限，与用户文件工作空间互不包含。不要把本示例目录直接放入用户工作空间。

3. 经受控发布流程开启后端 catalog/runtime 和前端 UI 构建开关。前端开关在构建时注入；仅改服务器后端环境不会打开界面。保留完整发布日志和任务工作树。
4. 用目标组织已有授权测试账号检查目录只出现获授权条目、手动激活反馈、图片输入仍存在和下一条清空。用一张素材图和一张产品摄影图分别检查六套输出；无图时提示上传，不编造内容。
5. 验证未分配组织无法发现或激活，关闭 UI 不改变后端行为。真实模型输出质量与生产授权账号的端到端验收另行记录，模拟模型单测不代替此证据。
