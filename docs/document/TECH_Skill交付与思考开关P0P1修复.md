## 已实现的行为

| 缺口 | 当前行为 |
| --- | --- |
| D01 说明遮住方案 | 不再因为文本非空跳过保存。说明与 `document.display_prefix` 逐字相同时，按原权威正文登记、展示。 |
| D02 虚假结束 | 即使只有 bootstrap、尚无 TaskState，失败的结构化登记也不能由“已完成”一句话关闭。失败明确标记 `content_incomplete`，不产生可执行成果。普通问答保持直接回复。 |
| D03 提议缺失 | 保存分支前写入私有、有版本、有大小上限的提议记录，原文、稳定调用 ID、参数、输入版本和处理结果分开保留，不伪造未配对的模型历史。 |
| D04 思考关闭失效 | 新版前端明确发送 `disabled`，低强度不能覆盖关闭；Qwen Chat 使用 `enable_thinking=false`，Responses 使用 `reasoning.effort=none` 并移除仅思考模式可用的网页抓取。OpenRouter 使用 `reasoning.enabled=false`，要求参数支持。 |
| D05 历史假成功 | 下一轮历史根据真实块记录“已登记并展示正文”或“正文未完整交付”；不能仅据模型自称保存而认定已执行。 |
| D06 时长缺失 | Actor 思考块落入实际观测到的 `duration_ms`，刷新后不再只能依赖页面临时时钟。未收到真实思考内容时页面显示“正在处理”，不制造空思考状态；首正文和模型总耗时仍独立记录。 |
| D07 最终请求不可核对 | 在各 Provider 转换完成后采集本地函数/托管工具计数、schema 字节/hash、输入与角色字节、历史/当前输入/工具循环/Skill 消息分解、图片部件数及有效 reasoning 设置；提议持久化、登记提交与发布分别记录耗时。 |
| D08 大输入与缓存 | 已补齐最终请求测量入口；保留现有按需附件、预算和工具按需发现。禁止依据约 1.9 万总 token 盲删聊天、素材或图片编辑能力。进一步裁剪与缓存收益仍须真实请求数据验证。 |

| D10 链路测试缺口 | 前后端共用 Actor 事件样本，校验流式、回放去重、页面正文、刷新持久化，以及下一轮逐条原文/素材引用。 |

### 冲突与恢复

- 无法确定普通文字与稿件的关系时返回明确冲突，最多补正一次；不能把另一份草稿静默覆盖到已显示正文。其他已有参数修复仍维持原次数上限。
- 补正稿必须保留之前可见的原文，不能悄悄改成另一份内容。前言被权威成果接管时，服务端、流式 Store 和恢复快照均去重；中间有思考块也一致。
- `_content_response_v1` 最多 1 MiB，保存原始提议及其处置。超限明确拒绝，不截断参数继续保存。思考原文不进入新增诊断记录。
- 只有同输入版本、单独的待登记调用可恢复执行；读取私有记录后仍走当前工具、版本、素材和权限校验。新输入使旧提议失效；混合业务调用不从此记录自动重放。
- 提议记录在模型历史之外；业务调用继续由原生操作账本恢复。登记成功的 phase、artifact 和可见块同一检查点提交，`projected` 只表示正文投影已形成，不表示用户已经读到、WebSocket 已确认或媒体已生成。
- 未确认的检查点失败回滚；已确认保存后遇到暂停、取消或交付异常不撤销成果，不重复外部效果。

### 思考参数的适用性

`disabled`、开启、旧请求未提供模式三个状态保持区分。旧检查点未提供模式时沿原参数恢复，不把旧 `low` 请求偷偷改义。关闭是实际推理参数，不能用隐藏返回的 thought 文字冒充。

当前接口/SDK没有经验证的关闭路径时，在请求发出前明确拒绝关闭，并在直接选择的模型中显示“固定思考”。包括当前 KIE 力度接口、Kimi K3、DeepSeek R1、固定推理的 OpenRouter 模型，以及本项目当前 Google SDK 接口。固定模型仍保留原有标准/深度模式和强度设置，不把不能关闭等同于取消其深度模式。特别是本地真实 SDK 校验拒绝旧的 `thinking_budget=0` 字段，因此没有假装支持 Google 的关闭能力，也没有擅自升级共享依赖。普通旧请求与内部核对可继续使用其原有默认模式。

智能重试把不适用模型单独排除，不将其伪记为一次失败；Gateway 对替代模型再次校验。不会为了换模可用性而偷偷打开推理。内部交付核对也根据能力选择模式，避免固定推理模型原本可工作的核对流程被拦住。

参考：[OpenRouter 推理参数](https://openrouter.ai/docs/guides/best-practices/reasoning-tokens)。依赖实际 Provider/SDK 的能力，而不是仅依据模型营销名称。

### 诊断数据边界

最终函数工具和托管工具分开计数；旧策略工具上限不代表实际发送数量。每轮最多保留 8 份测量，单份工具 schema 超过 64 KiB 时只留计数、大小与 hash。完整 schema 仅在原有私有检查点中保留；日志没有用户正文、工具参数、图片地址或 schema 正文。采集失败与日志队列饱和不得改变业务结果。

字节分解不是供应商 token 计数；图片、Skill 与角色字节存在包含关系，不能简单相加。输入 token、缓存读取和缓存创建沿现有真实 usage 分别统计。没有新建跨组织的权限、素材或提示词缓存。
