# Skill 聊天编辑技术方案

## 行为

用户可以在聊天中要求查询自己的 Skill。AI 先调用只读目录工具返回本人个人 Skill 的摘要；用户选择目标并明确要求修改后，AI 再读取该 Skill 当前已发布版本并生成更新候选。候选卡片明确显示这是对现有 Skill 的修改，保留个人可见范围；只有用户在卡片中确认后，服务端才发布新版本。原版本保留，更新期间不改变工具权限或 Skill 范围。直接创建新 Skill 的流程继续使用 `prepare_skill_draft`。

首版只支持当前用户本人拥有、处于已发布状态的个人 Skill。组织与平台 Skill 继续使用各自的管理/审核流程，不允许聊天编辑绕过这些权限。

## 调用与状态

1. `list_personal_skills_for_edit` 仅在用户明确要求查找、列出或选择个人 Skill 时调用。服务端按当前用户个人 owner scope 查询，返回有限分页的名称、用途、状态、稳定 `skill_key` 和是否可聊天编辑，不返回正文、package ID、组织或平台 Skill。关键词只过滤 Skill 元数据；列目录本身不授权修改。
2. 用户明确选择并要求修改后，`get_personal_skill_for_edit` 按 `skill_key` 或精确名称读取唯一个人 Skill，返回服务端解析出的 package ID、已发布 revision、用途与正文。正文只作为待编辑数据；不可用来授权工具或扩大权限。若用户只查询或尚未选定，AI 不应读取正文或创建修改候选。
3. `prepare_skill_draft` 接收目标 ID 与基准 revision，服务端重新核验所有权、当前发布版本和草稿状态，生成个人范围锁定的聊天候选。候选记录 operation、target package、revision 和草稿版本。
4. 候选卡片展示“修改现有个人 Skill”和原版本信息，不提供范围切换。确认接口在事务中锁定目标、复核本人所有权及版本，复用已有 NAS 发布校验并写入新 revision；原版仍可查阅。

若目标不存在、名称不唯一、存在未发布草稿、目标版本变化或 NAS/数据库写入失败，保持现有发布版本不变并返回可恢复错误。候选幂等；重复确认返回原回执。

## 实施与验证

- 数据：新增迁移记录 create/update 与更新目标、目标 revision、目标草稿版本；更新候选可以反复指向同一 Skill，创建候选的 package 唯一约束保持不变。
- 后端：新增仅限用户本人个人 Skill 的摘要目录工具；读取工具接受目录返回的稳定 `skill_key`，同时保留精确名称兼容；候选生成与确认事务保持 personal scope 并校验版本。
- 前端：更新候选卡片文案和范围展示，创建候选的范围选择行为保持不变。
- 验证：覆盖目录只返回本人个人 Skill 摘要、关键词筛选/分页/空结果、Feature Flag 和会话边界、稳定 key 读取、非本人/非个人/非发布目标拒绝、更新候选预览、确认后新版本发布、范围锁定、版本冲突、未完成草稿保护、重复确认和创建流程回归。
- 回滚：回滚应用版本；数据库回滚需把已完成的更新候选 package 关联清空后删除扩展列，已发布的 NAS 版本和审计记录保留。
