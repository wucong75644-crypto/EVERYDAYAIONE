# 三阶段固定框架 v3 实施记录

日期：2026-10-09。状态：Agent内部主图／详情内容链路已本地实施；未部署，专用页面真实入口尚未接入。

## 1. 基线与职责

以用户的`最新提示词包-20261009.zip`为唯一新基线，ZIP SHA256为`9f9076f3adaeeda852a4de8571c0b2f2274ef4fa1b6fbbde2f0ec1ec7e1dd539`。manifest中的五份Skill／Schema逐份核验后，原文件保留在`backend/config/ecommerce_planner_prompts/source-20261009/`；平台适配资源另存`v3/`，继续固定哈希校验，旧资源未覆盖。

前三阶段串行运行：商品与卖点 → 共用视觉及用途适配 → 按main_images／detail_page选择对应第三阶段。没有注册三个内部Skill为平台入口，没有新建供应商适配器、切换底层模型或新增独立评审调用。

程序负责固定配置、参考图身份与顺序、完整执行文本；模型负责事实和设计判断。用户原文逐字读取，页面固定配置通过服务器的`run(args, fixed_settings=...)`关键字传入，不增加需要聊天主AI复制的技术字段。该关键字仍受原有身份、任务、积分与租约边界保护，不能直接从无认证页面请求调用。

## 2. 【修改】固定输入与来源

`FixedSettings`包含task_type、platform、language、aspect_ratio、resolution、image_count。张数1至15；清晰度1K／2K／4K；比例与清晰度还通过现有Image能力校验。字段不参与模型回写。与用户尺寸声明有冲突时反馈，不能静默改参数。

输入快照保存原始消息、真实参考定位、版本和摘要，以及程序派生的source_bindings。模型只收到固定配置、image_N／text_N、参考角色与原始文本。带图消息顺序与实际发送的图像顺序一致，链接只作为模型图片部件传入，不写入需AI复制的JSON绑定。

【保留】事实ID、卖点ID、SKU及声明边界。第一阶段改为product-selling-points.v3，sources使用source_ref、kind、locator。来源编号必须存在，图像／文字kind须对应；风格图不能成为商品事实证据。结构检查不证明模型的全部事实判断正确。

【修改】第二阶段保持八节专业视觉规范，按固定用途适配；不采用固定10张或7＋7默认。第三阶段读取完整第二阶段；程序将其第八节「统一规则与变化范围」原文复用到每张执行稿，已确定逐张画面仍是实际执行对象，可选建议不变成必须添加全部元素。

## 3. 【修改】唯一设计交付

第三阶段协议为ecom-design.v3，外层为schema_version、status、questions、page_plan、images、review_records。

每张唯一内容为：position、name、purpose、fact_ids、reference_usage、scene、layout、props_and_decoration、lighting、text_layout、product_preservation、execution_constraints、negative_additions、page_link。

【删除模型回写要求】references、真实资源ID／URL／消息定位、aspect_ratio、positive_prompt、negative_prompt、scheme_markdown。对应最终信息没有删除，改由程序维护和组装。

【保留】真实商品比例、印刷、配色、材质证据、准确文案及字形、图文对应、自然照射与受光关系、道具销售边界、已指定风格。不能用短标签替代专业设计。

【新增】详情page_plan包含reading_strategy、visual_rhythm、coverage、全部N−1个boundaries与generation_path=independent_screens；逐屏page_link包含content_task、previous、next、edge_treatment。coverage须覆盖全部输出位置并引用相应屏的可用事实。主图的page_plan／page_link为null。

【保留最新版详情原则】独立生成各屏，以内容、阅读节奏和共同视觉语言承接；允许有目的的特写，不强制像素接缝或让下一屏补完被截断的商品。1536×2048／3:4从默认规则改为固定输入的画布；不声称1K／2K／4K接口能保证任意精确像素。

## 4. 【新增】程序组装与校验

assembly.py按固定模板生成主图九栏目、详情增加「上下边界与整页承接」。原文设计字段、共同边界、固定等比例保真句与通用防变形负面规则共同形成唯一request_text。

展示稿、保存稿及现有Image桥接发送复用同一正文，记录SHA256及fixed-frame.v3组装版本。参考图始终完整保持输入顺序，reference_usage只说明本张利用哪些内容；未利用的图由程序注明，不重新排序或创建资源身份。

【修改】校验集中收集可定位Schema错误及多张问题；检查数量、位置、来源编号、可用事实引用、用途结构、详情覆盖与全部相邻关系、真实自检，以及明确画布／清晰度冲突。ready仅在完整校验并原子保存成功后产生。

【边界】事实内容、风格遵循、文字语言和布局语义依靠专业规则及模型自检；程序字段与引用检查不等于独立语义评审，也不能证明生图质量。没有新增总分放行或第四阶段评分器。

## 5. 【修改】修补与恢复

第三阶段返回限定path的patches及复查记录，程序只接受全部指定路径，不允许扩大到其他字段、整张或整组；审核记录可以更新。仅extra_forbidden多余字段可remove，不允许删除必填项。

修补请求只传出错字段、受影响图片和必要的商品事实、视觉规范、原图与用户要求，不传整组有效稿。共性问题一次收集、一起修补。JSON无法解析时保留完整首次原稿，修复包装；不截断文本、挑选多个对象或伪造缺失设计。

【新增】282迁移的stage_drafts与finish_ecom_plan_draft_attempt，将正常完成但校验失败的原稿、错误路径、计费与回执原子保存。草稿不进入stage_outputs，不推进阶段，不授权生图；重放同一结算只扣一次，不同草稿不能覆盖同一回执。有效上游阶段、同任务有效稿和已受理图片继续保留。

【保留】租约、用户／组织隔离、持久化三次调用上限、600秒总窗口与父预算；认证、额度和执行不确定不能盲目重发。阶段3只处理内容修补，不能靠重新调用前三阶段绕过预算。
