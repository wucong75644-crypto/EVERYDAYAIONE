# 视频流畅预览与缓冲

2026-10-29，实现与本地验收记录，生产状态以受控发布记录为准。

用户确认：默认流畅预览，可切原画；原文件保留。本次不修改导图节点、导入结构、AI 查询或文档预览，不自动部署。

## 诊断证据与边界

此前上传 MP4 直接按原片 Range 传输，播放器获取地址后立即 autoplay；分段读取不等于降低码率。截图同名本地原片长 15 秒，19,282,997 字节、平均约 10.28Mbps，H.264/AAC，moov 在文件开头，未发现需要等待尾部索引的问题。公开静态资源链路实测约 3.2～7.1Mbps（含网络波动，非私有视频直接测速）；生产文件元数据读连接受到角色权限限制，未绕过，不能据此宣称实际用户现场只有一个瓶颈。

使用实际原片和应用预览生成函数做本地实验；后续用相同 4Mbps 条件对照原片与预览，分别验证缺少低码率播放版本、缺少起播/重缓冲门槛的影响。不把修改 preload 单独认作根治。预加载是浏览器提示，autoplay 可覆盖该提示，依据 [HTML 标准](https://html.spec.whatwg.org/multipage/media.html) 与 [媒体缓冲说明](https://developer.mozilla.org/en-US/docs/Web/Media/Guides/Audio_and_video_delivery/buffering_seeking_time_ranges)。

## 实现

- 前端显式请求 `quality=preview`，原画可选；旧客户端未指定画质时仍返回原画，兼容已发布接口。切换保留观看位置与用户暂停意图。
- 原件不改写。点击播放时按需生成 H.264/AAC、长边最多 1280、短边最多 720 的预览，目标视频峰值约 2.5Mbps、音频 128kbps，faststart。低码率且兼容的原片可直接复用。
- `video_preview.py` 与 AI 媒体解析分离，无模型调用，无数据库迁移。派生版本使用每进程有界内存缓存：最多 16 项 / 64MiB，重启、淘汰后可重建；首次准备有编码等待。每进程最多一个编码任务，繁忙明确返回 429，可重试或选原画。未引入 CDN、对象存储、持久化转码队列或多档自适应流。
- 编码沿用受 OS 限制的现有媒体进程入口，单线程、编码超时 35 秒、输出最多 20MB，编码候选时长最多 180 秒；超界、缺少依赖或失败明确提示选择原画。FFmpeg/FFprobe 已通过生产只读命令确认存在。当前机器生成本地真实样本约 8 秒，不代表生产 SLA。
- 原画和预览继续经同一绑定、版本、HttpOnly 期限 Cookie 与实时 ACL 校验；准备完成后再次校验，撤权不会发布新播放授权。预览使用自己的长度、摘要/ETag、Range/206/416，原画接口字节不变。缓存命中也检查源文件完整性，不缓存授权。
- 播放器以当前时间所在连续 buffered 区间计算可播秒数，起播先积累约 4 秒；缓冲耗尽后暂停，积累约 6 秒再继续。尾段按实际剩余时长判断，不能跨 seek 间隙计算；用户暂停、取消、切换账号、离屏或卸载后不自动复活播放，释放 src 和定时器。浏览器拒绝自动播放时提示点击继续。

## 验证与限制

本地真实原件校验保持不变；实际服务生成预览 4,924,656 字节，15.018 秒，约 2.62Mbps，视频与音频可完整解码。该样本体积下降约 74.5%，预览为有损压缩，不声称无损。首次生成时间与网络起播等待分别记录。

定向检查覆盖：原片/预览字节隔离、真实编码、预览 Range 和 HEAD、缓存不重复编码、撤权、准备期间撤权、生成失败/繁忙释放编码容量、缓存上限、原画兜底，以及起播/断流/用户暂停/seek/尾段/播放权限拒绝/取消/画质切换位置。保留导入、画布与展开记忆回归。

即便使用预览，低于预览码率的网络也可能等待，不承诺所有网络下零卡顿。长视频、编码繁忙或首播冷缓存可以选原画；原画仍可能因带宽不足缓冲。回滚本次应用代码即可，无需回滚原件或数据表。


最终本地结果：前端相关回归 416 项、后端 121 项通过，类型检查、相关 ESLint 与生产构建通过。延伸的缓存命中后源文件被破坏仍拒绝读取用例再次通过。相同 4Mbps 连接限速下，原片播放中出现 1 次等待；流畅预览完整结束且播放中等待 0 次。浏览器夹具使用真实原片、实际服务生成的预览及实际播放器；生成耗时与权限接口测试独立记录，未把夹具伪装为生产实测。原件未改、无生产业务写入、无数据库迁移；生产版本以受控发布结果为准。
