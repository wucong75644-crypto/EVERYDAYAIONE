# Skill 图片阶段路由修复

## 目标

未明确电商用途默认普通图片；执行已有最终提示词不重跑商品分析。只有明确的电商策划或服务器已保存方案续接进入电商工作流。商品出现在图片中不构成电商策划意图。

## 根因和修改

- `ecommerce_planner/workflow.py` 原先把分类缺配置、超时、格式错误统一返回 `needs_input`，执行引擎在主模型运行前输出固定用途问题并终止。本次技术故障改为 `unavailable`；普通生图继续，明确电商策划服务不可用时如实报告。旧分类的用途不确定结果归普通路径。
- 原先自动激活电商 Skill 可直接创建主图绑定。本次自动激活前校验工作流意图，不能用加载方法替代用户意图；策划工具在普通路径也被拒绝。
- 手动选择电商 Skill 仍是明确用途输入，但用户要求执行最终提示词时允许进入普通执行路径。已保存任务/重试绑定保持版本及方案身份，不能通过退出方法绕过受理去重与恢复约束。
- 通用方法上下文改为当前动作优先，仅检查该阶段需要的输入。移除旧的聊天不能生图规则以及单凭多步骤、积分成本重复确认的规则；实际工具审批继续有效。
- 增加 `deactivate_skill` 控制工具，仅可退出模型自动选择的可选方法。手动选择、会话固定、计划任务和已经绑定的电商工作流不能被模型解除。退出和激活一样是批次屏障，同批业务工具必须下一轮重新请求。
- 退出前保存原始主机授权上限；根据仍激活方法重新计算交集，恢复工具不超过原有主机权限。checkpoint 保存可恢复的 `host_allowed_tool_names`；旧 checkpoint 没有该字段时保守保留旧的窄授权。退出后移除原方法 system 消息并重新投影当前工具。
- 自动推荐仍只提供可忽略候选，不把权限、工具交集和文件类型当作用户意图；不新增一套关键词评分或额外模型分类服务。

## Skill 新版本

保留历史文件和哈希，新增以下版本：

| 标识 | 新版本 | 变化 |
| --- | --- | --- |
| chat-image-orchestration | v2 | 承接现成提示词和参考图，默认普通生图 |
| reference-image-prompts | v3 | 文字方案完成后交接生图，不重复生成方案；仍仅手动选择 |
| ecommerce-main-images | v4 | 明确电商策划触发条件和排除场景，直接执行提示词不进入策划 |
| ecommerce-image-prompts | v3 | 复用已有阶段，按当前动作检查资料；仍仅手动选择 |

完整融合版的专业正文和商品分析附件保持原内容，仅增加阶段边界。参考图 Skill 依然没有业务工具权限，后续生图在新的请求中交给图片编排；不能通过提示词解除手动/固定权限限制。

仓库示例不自动写入生产数据库，部署代码也不自动更新 assignment。正式启用需通过现有 Skill authoring 审核发布入口发布新 revision，再更新目标组织分配；固定到旧 revision 的会话不自动升级。此任务没有执行生产发布、分配或模型生图。

## 验证与回退

定向覆盖：普通/电商入口、分类异常、误激活、可选方法退出、同批业务调用屏障、原主机授权上限、旧 checkpoint 恢复、手动/固定/计划任务保护、新 Skill 文件和附件校验。既有电商恢复 PostgreSQL 测试核验原方案、版本、RLS 与受理链路。

模型路由测试使用模拟回包，不能代表生产模型语义准确率；上线验收需用“六个提示词直接生成”“商品表面换图案”“明确淘宝主图策划”“不再策划直接生图”等正反例观察实际路由和工具调用。

回退时保留所有不可变 Skill 文件和已受理任务。新 checkpoint 含可恢复主机授权字段，旧代码不认识该字段；应先完成/停止本次版本的活跃聊天任务，再回退代码和组织分配，不能直接改写运行中 checkpoint 或扩大权限。

## 本地验证记录（2026-10-13）

384 项相关测试通过，包含 30 项独立 Unix socket PostgreSQL 电商恢复测试，以及四个新 Skill 版本的真实文件、元数据与附件校验。未使用生产数据库、真实生图供应商或生产模型请求；`git diff --check` 通过。
