## 依据与边界

此前真实模型面对“第三个做成一张图，正方形，一千就行”，看到了旧稿3:4/2K、新要求1:1/1K以及先读再改的工具说明，却直接调用旧稿generate_image。该JSON符合当轮schema，但业务阶段不允许派发。后台正确拦截后才完成读、存、执行。

同时确认读取工具描述中的具体JSON案例只将artifact_id字段名替换为content_ref，值仍为content-真实ID，无法通过当轮短引用enum校验。该案例当次未被照抄，不能认定为首次跳过读取的直接原因。

方案依据为OpenAI Agents SDK的运行时条件工具开放、工具内部继续核验资源，以及OpenAI函数调用指南关于通过结构避免无效状态、用代码处理确定性约束的建议。不是声称所有厂商内部实现相同。

## 实现

- saved_image_revision.execution_requirement只读计算结构化差异，由调用前工具开放和执行前校验共同使用；包括规格、明确输入素材、当前已批准但需修订的旧版本，以及明确修订稿件的动作。没有客户话术关键词判断。
- pending_execution仅处理已解析且版本匹配的content目标。选择继续由模型按真实用户意图完成，不自动选择其他历史稿或最新稿。
- content_revision.offer在read_required阶段隐藏保存工具和不可执行的旧稿生成入口；读取成功后为revision_required，开放修订工具；保存新版本后恢复生成。混合选中的条目只在公开schema限制待修订item_index，ready条目保持可执行。
- 原样执行未变化的旧稿仍可直接生成，保留普通新建、历史图展示和直接编辑成图入口。只看原文不要求修订或生成，只改文字不授权生图。
- read_calls和流程状态先构造成原生对象，经ModelReferenceBoundary一次转换，再序列化进工具说明。具体JSON案例与schema共享同一当前输入下的短引用。
- find_available_tools不能重新向模型开放当前被修订流程隐藏的生成入口；执行前原有来源、读取、版本、批准及修订屏障保持。能力可见性不替代实际校验。
- 无数据库迁移、前端调整或新增公共工具。
