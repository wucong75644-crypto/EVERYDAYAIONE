## 1. 素材引用错误及提示冲突

真实调用选中了正确灯塔底图，但把materials[0].reference写成字符串；合同要求reference对象。该工具Schema中MaterialReference.type=object，定义正确。离线校验：只有image_ref/edit_instruction通过；reference字符串失败；reference:{image_ref:...}通过。

文字说明写“图片复制当前目录的image_ref”，全局说明写“素材reference、view_image、show_image也填写image_ref”。这没有说明三个位置的JSON层级不同。编辑示例只覆盖底图，未给其他参考素材的嵌套示例。模型同时把同一底图放进materials，违背工具已有“不重复填写底图”说明。无法证明其内部思考，但不能排除提示歧义的影响。

确定的程序缺口：工具结果由错误JSON + 换行 + platform_metadata JSON组成；ImageReferences.text仅尝试解析整个字符串或最后一行。整个字符串不是单个JSON，最后一行解析成功后，原错误正文原样保留。因此投影后仍出现旧allowed_fields和“编辑统一填写source_message_id/source_content_index”的指令，和当前工具image_ref接口矛盾。离线同版重放确认这一行为。即使单独转换错误JSON，allowed_fields数组也仍保留原生字段名称，文字替换不能覆盖结构化字段名列表。

此次模型下一次调用移除了多余materials，成功派发并出图；不能据此认定提示冲突已消失。

## 2. 尺寸冲突是auto与1:1，不是锁定竖版枚举

用户原话：第一个帮我做成一张图，正方形，一千像素就好。

真实需求解析结果：aspect_ratio=1:1、resolution=1K。旧稿options.aspect_ratio=auto；正文写竖版并禁止正方形。执行仍传旧content_source，未先修订旧稿。

chat_image_preparation把旧稿aspect_ratio计入bound_specs；解析新要求得到1:1后，与auto不等即抛出IMAGE_SIZE_CONFLICT。直接原因是旧保存值auto和新请求1:1不同，并非供应商不支持正方形，也不是精确1000像素拒绝。

工具文字强调“直接提交content_source，无需重新保存”；保存工具另有base/updates及options修订能力，但没有在执行入口明确说明：用户修改旧方案规格时应先更新规格与冲突正文，再提交新版本。后台有安全门禁，模型侧缺少对应操作分支说明。后台对于auto这个缺省策略是否应与已确认规格同样冻结，也需要单独确认行为，不能在诊断中静默放宽。

## 3. 目标纠错仍有不匹配

同一尺寸请求期间，实际还出现过：先提交未绑定的content_source；目标纠正缺artifact_id/revision/source_message_id；补齐后focus=current_request被拒；再改selected_target通过。

focus字段只列枚举，没有局部说明content+execute_saved必须selected_target。REQUEST_TARGET_FOCUS_CONFLICT回执没有指出focus字段及正确值。selection_repair虽然正确指出缺失的稿件字段，通用message仍强调image目标字段，未按content分支解释。这些回执缺口会增加猜测与重试，不宜归为纯模型问题。
