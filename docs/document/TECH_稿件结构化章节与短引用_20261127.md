# 稿件结构化章节与短引用

## 问题与边界

修复生产验收中首次参考图方案的格式拒绝，以及第三项改清晰度时长稿件编号抄错。仅修改当前工作树；保留历史选择、原对象版本、先读取再修订、确认条件、幂等和原执行路径。无需数据库迁移，也不修改前端或供应商配置。

## 一个模型格式合同

`reference_prompt_format.py`集中定义模型字段、章节名称、JSON schema、说明及后台组装；`methods.py`保存校验和读取合同使用同一章节定义，Skill平台补充说明也引用同一指导。模型工具最终投影同时转换参数、JSON案例、描述、读取回执及可核实的历史成功调用。无法核实或失败的历史调用保留证据，不猜测修复。

|模型字段|后台保存及展示|
|---|---|
|`document.reference_analysis`|参考图判断章节，保存为document.display_prefix|
|`items[].title`|方案标题行|
|`items[].presentation.scheme_content`|方案内容章节|
|`items[].presentation.visual_settings`|视觉设定章节|
|`items[].presentation.reference_usage`|参考图使用方式章节|
|`items[].prompt.positive`与`negative`|完整生图提示词、负面提示词两章，保存为item.body|

模型只填写各章节完整正文，后台生成固定标题及顺序，不要求模型重复拼写Markdown结构。省略的修订字段与未选条目保持原样；改变规格时同步修改正文及展示说明中的冲突规格。普通文字稿继续使用原body协议。已有参考图稿按其保存profile读取、修订，不依赖当前是否激活Skill。

读取回执给出完整结构化章节、素材、规格和format_contract；content_source只包含下一步允许的选择器，校验哈希放独立content_sha256。后台仍保存原生Markdown记录，不改写历史记录，执行正文仍从实际保存版本取得。

## 稿件引用

新增模型字段content_ref，与image_ref分开，复用同一当前输入快照的投影入口。后台映射到真实artifact_id，继续验证object_key、revision、条目编号、来源消息、轮次和权限。目录仅来自服务端已核验成果，不依据用户关键词、模型自报编号或文本相似度扩充。

引用包括当前输入作用域和不可变稿件身份摘要；不同版本的编号不复用。工具schema枚举当前可选引用；历史旧版本仍能在历史中标注，但不能再次作为可修改版本。读取、修订、执行、确认条件和目标纠正使用同一content_ref协议。

错误区分CONTENT_REFERENCE_UNKNOWN、CONTENT_REFERENCE_EXPIRED、CONTENT_REFERENCE_VERSION_CHANGED、CONTENT_REFERENCE_IDENTITY_CONFLICT；返回字段路径和可选引用，不自动选其他稿件。有效引用与当前选定目标不一致时，原目标检查仍拒绝，并返回expected_target。

## JSON案例来源

工具实际案例由原新建/修订案例经过相同公开投影生成，随当前可选引用枚举变化；原生SaveContent只接收完成精确解码后的参数。下方案例由当前代码生成，示例编号不代表替用户选择目标，实际调用必须从当轮目录或读取回执复制。
