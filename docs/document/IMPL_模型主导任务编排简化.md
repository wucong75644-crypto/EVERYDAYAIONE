## 最终执行方式

1. 原消息受理、Actor、上下文准备及 Gateway 保持。新任务由主模型选择行动；普通聊天、只读工具不被强制创建完整任务图，也不固定增加提案、分类、独立评审模型调用。
2. `update_task_plan` 是可选工作记录。首次真实操作前也能保存并恢复；同批独立业务调用不因更新计划被强制延后一轮。计划不能授予权限、清除原操作或冒充成果证明。
3. 支持的原生操作在原 TaskState/检查点内绑定真实 call ID、原参数摘要、当前输入版本及稳定执行槽，再经过原 ToolRuntime 权限、确认、资源与预算边界。文件解析参数另作不可更换的宿主绑定，不改变模型原参数身份。
4. 图片原生发布回调、视频、代码、计划任务、Reach 和文件操作的原生证明由宿主接入原成果登记器；主模型不再逐个调用 import/complete。读取类和其他原有工具仍由原 Actor/工具账本执行，不虚构尚未适配的业务终态。
5. 模型读到真实工具结果后决定后续步骤。图片/视频受理不再强制截断新模式中独立的后续工作；确认表单等原终止边界保留。模型结束本轮时，宿主按物理操作事实记录完成、等待或部分状态，不宣称全部自然语言目标已经独立验证。
6. 异步完成通过原事件消费者、原队列和检查点接续，保留上下文和既有成果；不是新增执行器或轮询模型。新消息归属由主模型决定；需要接回历史任务时仍用原 fenced ownership transfer。
7. 新消息只有被主模型实际读到后，持久输入游标才能推进。旧调用参数不能因此自动取得新派发权。后台图片/视频及文件逐项派发还检查对应操作是否衔接到当前输入；主模型读取消息本身不会释放旧队列。继续原操作通过原参数绑定回同一槽，不另开付费任务。

## 数据与界面

- `TaskState.model_directed` 冻结执行语义；`call_bindings`、宿主解析绑定与执行记录追加且不可改写；`working_plan` 可变。只允许撤下明确未派发的记录，已受理或结果不明的操作不能借改计划消失。
- 原上下文、检查点不透明扩展、成果来源、权限、确认、预算、原生回执和防重复执行机制保留。当前资源或真实成果无法核实时不登记成功，不退回盲目重跑原操作。
- 前端仅对有新模式标记的消息隐藏正常内部管理卡片，归并成果查找/复用；保留真实业务工具、正文、图片/视频/文件、确认表单、失败与取消、Skill 提示、思考折叠、原暂停/继续/停止。
- 一个进度卡区分工作计划和真实图片完成数；结束文案为“本轮执行结束”，不以 todo 或宿主具体调用数量冒充全部用户要求覆盖。旧消息显示不变，后台原始事件与记录不删除。
