### 诊断过程中的失败与修复

这些失败保留，不计为通过，不与上述代表性集合合并：

- JSONB重排临时来源编号，导致正确旧回执恢复失败：已改为封存解析后的来源字符串，恢复不重解释临时ID；第1条实际作业无新增提交恢复成功。
- 正确灰色成图因使用 actual_output/image-N 外观证据被拒绝：成图只可证明可见外观，不能证明真实规格/性能；正式回归与两轮实图复测通过。
- 完整 ready 后主模型重新建工作计划、手工保存失败：已改后台直接投影持久化全文，断点恢复不重复调用模型。
- 原生方案卡被页面Zod旧协议丢弃：已补真实字段联合协议，严格方案ID/版本校验和事件→状态→页面→刷新测试。
- 核验器返回 null、漏引证据、把缺席类当错误、错误片段格式：有界格式纠正；没有有效结果保留草稿，不伪造批准、不重新作者循环。
- 试验Flash未列入模型白名单：只补已登记且支持关闭的模型选项，不在供应商失败后自动切模型。
- 早期原稿全文片段同时含配色/摄影数字，引发页数式校验误拒：明确区分展示参数，仍保留80页、价格、含棉量、优惠与SKU偷换断言。
- 测试驱动早期按未编译选择器读取哈希、误把 pytest 单项通过当业务成功的问题已修；严格验收模式断言失败会返回非零。
- 真实默认轮返回JSON缺逗号后完成，但仍多一轮：发现策划分支未请求JSON模式，且Qwen适配器也丢弃显式response_format（包括核验请求）。补实际参数和透传，严格解析/有界纠错不删，普通未请求JSON的聊天不改变。最终真实请求另断言阶段1/3为json_object、阶段2不强制。
- 前端全量暴露 ECharts 动态导入测试竞态：固定同一mock工厂和失败后模块缓存，保留原重试/实例化断言，未改生产代码或降低断言。

## 剩余限制

1. 商品核验依赖视觉模型，会有漏判与误拒；无法承诺完全可靠。供应商确实可能把文字改错，不能通过放松验收消除这个事实。
2. 十套长稿仍需几分钟，已将通过三轮独立完整测试的Flash设为本地关闭思考默认值，实际默认配置最终完整交付188.31秒；同版本另有一轮核验不完整停止，事实核验新增调用成本与延迟。普通五套短稿的14.6秒不是十套Skill的耗时承诺。
3. 原始会话有真实用途歧义时仍需用户澄清，不能默认把卡册当可写同学录，也不能用操作者补充范围后的成功冒充原文成功。
4. 本轮候选不构成上线稳定率、视觉准确率或SLA证明；未部署，未进行线上员工验收。
