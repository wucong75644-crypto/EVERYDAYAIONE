# Skill 管理体验优化方案

日期：2026-09-20。状态：用户已确认，实际界面已实现并完成本地验证，尚未部署本次 UI 改动。

## 已核实的问题与边界

截图选中 `reference-image-prompts`，属于平台 Skill。组织管理员只能查看，这是权限边界，不是草稿不能编辑。现有页面将新建表单、列表、详情、编辑和版本按钮同时排列，默认又不显示平台正文，容易让用户误以为整页不可编辑。

本方案优化现有组织管理体验，保留管理后台主导航、蓝色强调色及浅色/深色主题。不改变组织与平台权限，不增加个人 Skill 或自动触发能力。生产 NAS 的组织发布写入权限是独立部署事项，界面调整不能消除该限制。

## 推荐的信息结构

1. **Skill 库**：默认组织 Skill，平台 Skill 独立分区。右上角唯一主操作为“新建 Skill”。列表显示名称、用途、工作状态、可用版本和更新时间；支持名称/标识搜索及状态筛选。没有组织 Skill 时显示引导创建的空状态，不自动选中平台条目。
2. **内容详情**：点击条目进入独立内容区域，保留返回列表入口。默认展示正文，版本历史独立标签。名称优先，技术标识降为辅助信息；没有名称时回退至标识，不从技术标识推断业务名称。
3. **草稿编辑**：名称、用途说明、操作说明组成表单。正文提供 Markdown 编辑/预览，明确已保存或未保存。技术目录配置不再占据主编辑区；完整配置需在高级区域保留并维护，普通编辑不得清空已有值。实际界面的高级表单覆盖触发提示、模型选择、会话范围、领域、执行场景、成员限定、权限、功能开关和允许工具；未修改的声明保持原值。
4. **新建**：对话框填写名称与唯一标识，创建后直接进入草稿。标识规则及创建后不可修改的限制就地说明。平台分区的新建入口仍明确创建“组织 Skill”，不会创建平台条目。

## 状态与主要操作

| 状态 | 主要操作 | 必须显示的信息 |
| --- | --- | --- |
| 草稿 | 提交审核；有未保存修改时为保存并提交审核 | 是否已保存；原发布版本仍在使用 |
| 审核中 | 审核通过 | 正文锁定；退回修改为次要操作 |
| 已审核通过 | 发布新版本 | 尚未生效；它仍属于 in_review，不新增后端状态 |
| 已发布 | 编辑新版本 | 当前内容只读；编辑将创建草稿 |
| 已废弃 | 查看内容/历史 | 阻止新解析与激活；已激活任务仍可恢复 |
| 已停用 | 查看内容/历史 | 阻止新解析、激活及恢复 |
| 平台条目 | 查看内容/历史 | 平台维护，组织管理员只读 |

废弃、停用收进“更多操作”，确认框分别说明影响及目前没有直接恢复入口。审核与发布仍是两个明确步骤；原型没有引入新审批人规则。

工作状态和可用版本必须分开。已有发布版本的草稿不应呈现为整个 Skill 不可用；废弃/停用条目不能在“可用版本”列继续显示可用。版本历史中的“第 N 版”仅是按发布顺序生成的易读标签，不替代不可变 revision 标识，完整标识需可查看。

## 反馈、异常与适配

- 列表与详情随成功操作刷新，手动刷新退为辅助操作，不作为常用按钮。
- 保存失败保留输入；未保存离开时提供继续编辑/放弃返回。保存成功但提交失败时分别反馈，不能声称已提交。
- 并发冲突保留本地编辑，提示先复制需要保留的内容再刷新，不静默覆盖。列表返回、详情刷新、后台页签切换和页面返回有未保存确认；浏览器刷新/关闭使用 beforeunload。当前后台没有组织切换控件；外部组织上下文变化会清空旧视图、忽略过期结果并中止后续提交请求，避免串入新组织。
- 发布失败保留审核通过状态，明确“尚未发布”，允许重试；不得使用成功样式掩盖 NAS 写入错误。
- 请求进行中防止重复提交；加载、空列表、权限不足和网络错误分别显示真实状态。
- 长正文和长标识自然换行。窄屏折叠辅助栏和低优先级列表列，状态、正文和主要操作始终可达。对话框具备键盘焦点管理。

## 实施记录

对话内原型使用示例数据，操作仅在本地模拟，未连接生产接口。可演示搜索、新建、编辑/预览、保存、审核、发布、历史查看、废弃、平台只读和未保存离开；并发冲突与网络故障按上述方案定义，未在原型模拟。

列表服务已增加 name、working_description、updated_at、available_revision、available_revision_number；详情增加 available_revision。可用版本来自当前组织 enabled assignment，且 revision 必须为 published；发布历史按相同 created_at/id 排序生成展示序号。原 description 和 published_revision 保持原义。创建名称和模板正文通过既有 CreateSkill.content 一次写入，避免创建后第二次保存失败留下无名草稿。

正文预览复用 react-markdown / remark-gfm，不执行原始 HTML，不自动加载正文外部图片，链接使用安全协议处理。复用 Button/Input/Badge/Dialog/Dropdown 组件；经典主题深色变量适配仅作用于 Skill 区域及其弹窗、菜单，不调整全局主题。

验收重点：从空组织创建到发布的完整链路；平台正文开箱可读且不可编辑；编辑不修改旧版；未保存及并发冲突不丢内容；发布失败可重试；废弃新旧任务差异不变。本次没有迁移、权限变更或生产写入。

## 验证与生产验收

本地验证：管理界面 17 项、后台离开保护 2 项；后端 authoring PostgreSQL/API 60 项。类型、改动文件 ESLint 和生产构建通过（保留已有大包提示）。真实组件使用本地模拟接口检查了桌面浅色、360px 深色列表/编辑/新建弹窗；模拟接口未连接生产。新增投影没有改变发布事务、权限或运行时语义。

发布后人工验收：
1. 打开管理后台 → Skill 管理：默认组织分区；平台条目进入即显示只读正文。
2. 新建组织 Skill，填写用途与正文；编辑/预览/保存/重新进入一致；高级设置不因普通编辑丢失。
3. 提交审核 → 审核通过 → 发布确认；编辑新版本后旧版仍可用，历史正文不变。
4. 两个浏览器同时编辑，过期保存提示冲突并保留本地内容；未保存返回或刷新需确认；窄屏、明暗模式与键盘弹窗可操作。
5. 废弃后列表不再显示可用版本，新任务不得激活，已激活任务按原版本恢复。

第 3/5 步生产发布链路仍依赖另行授权的组织 NAS 可写挂载，UI 改动不替代该基础设施授权。尚未执行本次生产验收。
