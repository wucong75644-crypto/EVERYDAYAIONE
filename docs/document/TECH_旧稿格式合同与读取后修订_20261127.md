# 旧稿格式合同与读取后修订

状态：当前任务工作树本地实现并验证，未提交、未部署。旧稿修订主链通过真实模型重放；历史展示扩展验收仍有未通过项，不作全业务通过结论。

## 已确认根因

实际wire中的保存工具提供通用修订说明和带两个正文标题的描述案例，但没有旧参考图稿件生效的专用格式要求。后台save_schema原来只看当前激活Skill，真正保存却继承ContentRecord.presentation_profile。模型先跳过完整读取，提交缺少“完整生图提示词”标题的body。其JSON及所选第三项/1:1/1K合法，方法格式校验失败；只补标题即可通过，前缀缩写不是当次拒绝的直接触发点。

私有原始证据：`/private/tmp/skill-supplier-action-contract-verified-20261127/evidence.json`。原模型调用与接回后的重放参数相同，后台没有替模型删改正文。

## 实现范围

- `methods.content_format_contract`集中定义现有参考图格式的正文、展示和文档章节。模型说明、读取回执、保存校验使用该定义。格式版本与稿件revision不是同一概念。格式检查仍是Markdown章节语法验证，不扫描用户关键词决定业务动作。
- `content_revision.selected_format`优先使用真实选定保存稿的presentation_profile；无当前激活Skill也保留旧稿要求。选定普通稿件不会因无关参考图Skill而改用图片章节。未知历史候选先按原权限读取，不根据标题猜格式。
- `read_saved_item`继续执行原会话/用户/组织/工作区权限、真实来源和版本/哈希检查，返回完整item、content_source及format_contract。仅模型READ控制成功时登记后台读取凭据；模型不能填写一个“已读取”开关伪造它。
- 读取凭据保存为检查点`_content_revision_reads_v1`，绑定当前输入、当前owner、真实稿件、版本、哈希和条目。任务接续复制本输入凭据；忽略继承任务的旧owner事件，以及接续时为同一认证输入新增的那一个合成事件。后续真实steer，即使文本相同，也使原读取失效。
- 所选content的待修改条目尚未读取时，模型工具列表暂不提供save_task_text，READ说明附真实读取参数；成功读取后恢复保存工具。工具发现也遵守此门槛。原样执行仍可使用generate_image，不新增文字读取要求。
- 模型发起的base/updates修订在任务接回、批准决策记录及实际保存之前共同核验读取凭据。缺失返回CONTENT_READ_REQUIRED和准确读取JSON。失败不保存、不产生生图或批准，也不重放尚未读取的修改。已经完成的调用保留原幂等校验。当前版本已变化时明确返回候选版本供核对，不自动替换原目标。
- `content_objects.save_schema`、`content_tools.model_tools`及短引用修复回执同步旧稿格式说明、body/display_prefix字段要求、完整案例。write与execute_saved两条投影都提供parameters.examples；参考图案例满足真实方法校验，普通稿件案例不添加图片章节。修订不再附加“保存整组新方案”的矛盾等待说明。
- 保存工具的confirmation.approved投影为只能省略或空数组，与SaveContent原本已存在的禁止批准规则一致。未修改批准、等待或版本桥接政策；不把JSON Schema修订当成新增授权。
- 格式失败返回ContentPresentationError，包含format_contract及准确字段位置，例如`$.updates[0].item.body`缺少哪个章节。后台不自动补写正文，不缩写原稿，不移除校验。

本批不改前端、历史图片身份/短引用、选图方式或实际图片编辑参数；不新建数据库表、不重写历史稿件。此前同任务的386迁移不属于本批新增迁移。
