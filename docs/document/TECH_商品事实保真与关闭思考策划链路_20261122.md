# 商品事实保真与关闭思考策划链路（本地候选）

> 后续收敛：本文记录的是已撤回的强制商品核验候选。`product_fidelity`和未发布迁移382已从当前本地候选移除，不应依据本文安装或部署核验功能。最新诊断、保留边界和修改见 [限制收敛方案](REVIEW_Skill相关限制收敛与大厂对照_20261122.md)。历史测试计数与失败证据不改写。

Grok公开代码已核对的调度、工具契约、渐进加载与恢复原则沿用前一轮固定源码证据；商品事实核验是本项目新增的业务机制，不宣称Grok公开实现了同一商品核验器。

本轮承接员工20组复测，不能把此前“14组完成、6组未完整成功”改写为全部通过。未部署。事实判断仍使用可出错的视觉模型；后台负责证据与执行边界，不将模型返回的 JSON 当作事实或权限本身。

## 职责与调用链

1. 聊天模型理解需求、观察原图、创作方案。普通新增多套图片提示词写作在满足现有权限、非执行、非历史修订、非专门方法、非逐项确认的边界内，直接输出正文。后台按完整段落登记；补齐连续中文编号，不删除未经证明是展示内容的限制。写作阶段不提供保存或购买图片的工具。已有稿件修订、单套或数量未明的写作、专门 Skill、逐项确认继续使用原协议。
2. `content_groups` / `content_objects` 保留正文、展示间隔、版本、编号与当前唯一明确原图。下一轮仍按原条目编译。双图明确编辑在原鉴权解析后转发用户原文及图号映射，不让模型扩写材质、类别或商业条件。
3. 电商三阶段策划按持久化父任务的 thinking_mode 选模型。关闭时使用独立登记且实际支持关闭的 `ecom_image_planning_non_thinking_model`，默认 Qwen3.8-Flash；事实核验独立使用 Qwen3.8-Max，开启、页面专用模型保持原路径。模型注册、视觉能力、凭据及关闭支持在付费预留前核验，不在网络失败后自动换模型。模型身份进入快照、复用键和工具回执。思考关闭实际发送 disabled，非把 effort 调成 low。关闭思考的结构化阶段1/3实际提交供应商 JSON object 参数，第二阶段文字不强加JSON；Qwen适配器不能丢弃显式格式要求，不支持的格式明确拒绝。详情页既有选项不改变。原生三阶段 ready 后，纯策划任务由后台核对哈希并直接展示每条完整 request_text；不让主模型再次制定工作计划或手动保存。完整正文通过所有者/输入版本绑定的私有投影日志恢复，不重复采样或派发。复合文件、发送、知识库等交付继续走原工具循环。
4. `product_fidelity` 从原 scoped resolver、当前用户消息、已闭合用户历史和同根同所有者的真实追加要求采集证据；助手旧稿不能证明现实商品事实。文本上限50k：完整保留当前原文、追加要求及已载入的直接引用消息，再按新近顺序纳入完整历史消息，记录排除清单；必要消息本身超限时保留草稿并明确要求缩小资料范围，不静默截断。来源显式记录时序和本轮身份，不能由 JSONB 键顺序推断新旧。生成图不能独立证明规格、价格或性能；继承已有事实须核对原生冻结合同、所有者/组织/会话，以及合同哈希和实际输出文件哈希绑定的批准回执。旧资产无此证据时不继承事实，不撤销原本合法的素材使用权限。
5. 核验器只观察，无工具且关闭思考。后台提供精确原文片段与来源编号，解析后绑定真实字符串，核对范围、引用、数值、全部方案编号及必须检查的商品声明。数字、原文和来源不由核验器改写。身份背景与草稿声明分开；新创意无需已存在于修改前的图片。JSONB 会重排对象键，因此批准回执保存已解析的来源字符串并去掉临时来源序号；恢复不能重新解释这些序号。实际成图可以证明其可见外观，不能证明现实商品身份、规格或性能。
6. 三阶段在商品分析及最终完整组进入可执行状态前核验；非执行的第二阶段全文进入最终核验，避免重复收费核验相同公共段落。真实矛盾允许原有有界局部纠错；协议无效或网络结果未知保留完成的草稿，停止，不能重写正文循环。相同任务恢复不再次调用未知核验，用户在新任务明确 retry/regenerate 才继续核验原稿。`product-planning-fidelity.v2` 防止把旧未核验 ready 当新版本复用。
7. `ImageHandler.accept_chat_image` 在原权限、冻结素材和操作账本校验后，未创建/预扣图片前核验；批准才附加服务端合同并走原生受理。原调用重放使用同一冻结回执，不能再买一次核验。模型工具参数不能提供批准合同。
8. `ChatImageLifecycle` 在真实文件下载、原尺寸/透明度验收后，发布成功和资产结算前核对实际成图。先持久化 checking，后写批准/拒绝/未知；恢复复用回执。拒绝或未知保留文件，使用已有输出合同失败结算，不自动重买图，不伪装成功。页面保留原尺寸质量信息并展示核验状态，私有观察正文不进入页面协议。

## 兼容、权限与恢复

- 聊天、输入队列、运行中追加、Skill 激活/权限、编号交接、媒体确认、素材鉴权和图像供应商派发仍走既有状态机。新核验不授予任何执行权限。
- 已受理但没有事实合同的旧图片保持旧解码。已完成的旧回执不补调用；新手动重做是新受理，先做核验。详情页执行保留原合同，不强行套用聊天策划参数。
- 核验调用计入父任务剩余时间和取消信号，最多90秒/空闲45秒；仅完整的协议错误允许一次格式修复，真实拒绝和未知网络结果不自动重发。新增核验有供应商成本和等待，不能称为免费或零延迟。
- 新增迁移382仅增加 `complete_chat_product_review`，不用仅限详情页的格式恢复函数。真实 actor/org/conversation、活跃父任务、租约、原稿 CAS、原尝试确定性和 ready 条目数量都须匹配。只完成已结算草稿，零新增策划扣款；同回执幂等。无新表/列，不改旧函数。
- 若将来获准发布，需先按项目发布入口执行382；本轮未执行生产迁移。回滚应用后仅可在确认没有新核验恢复调用的受控窗口删除新增函数，回滚SQL已提供。关闭开关只影响新受理，不能把已冻结核验合同的拒绝改成批准。

## 验证与限制

见同日期测试记录。单元与数据库覆盖精确引用、数字偷换、生成图证据、缺失方案、中文编号、原文/素材保留、追加作用域、JSONB往返、核验异常不重写、原稿继续与不重复扣费、取消/越权/租约、既有图片恢复。真实模型测试的拒绝、澄清、格式失败、脚本错误和完成必须分开计数。

这不是通用 OCR、实物测量或商品数据库。供应商审核拒绝不能通过换模型绕过；原图没有提供的事实仍可能需要真实用户澄清。模型辅助观察无法承诺100%准确，尤其细字、材质和商品用途；未经实物核验的批准只能表示未发现明确矛盾。所有真实失败和剩余延迟必须记录，不能据首字速度宣布完整交付提速。

## 最终复测发现的额外根因

- 原生策划卡片的组件支持 `item_id/position/name/purpose`，页面入口 Zod 却只接受旧卡片字段。补齐联合协议；原生卡片必须有已保存方案编号和版本，旧有效卡片兼容。真实事件回放覆盖页面、刷新和编号保留。
- 全文 ready 后主模型再次保存会引入等待和失败。后台从已持久化条目投影完整正文，用任务所有者、输入版本与哈希恢复；有运行中追加或复合交付时仍走原循环，不能覆盖新要求。
- 实际核验中配色、字体、拍摄角度、画布与清晰度被当成商品规格，导致多余作者纠错。后台按有明确上下文的表达区分执行/表现参数；型号、价格、页数、材料含量仍作为商品事实检查，不删除或重写原稿。
- 模型显式引用本轮用户消息时，旧入口将其当非法历史重复拒绝。先严格校验列表，再将已鉴权本轮消息纳入一次；其他历史消息不被丢弃，继续逐条原生鉴权。
- Qwen3.8-Flash 经三轮十套完整交付独立实测后设为本地关闭思考默认值，Max继续独立核验；另用不覆盖模型配置的完整真实任务核验最终默认值。环境变量显式配置仍优先，不能在发布时假定一定使用缺省值。
