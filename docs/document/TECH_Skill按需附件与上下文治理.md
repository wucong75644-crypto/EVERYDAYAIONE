# Skill 按需附件与上下文治理

当前接入状态（2026-11-22）：已适配最新主干 `78cbce12`，以 [Skill 与多轮聊天统一接入方案](TECH_Skill与多轮聊天统一接入方案.md) 为当前实施口径；下文保留各历史批次证据。

日期：2026-11-21；沿用 Skill 性能任务工作树。用户已授权补齐并测试实际速度和执行效果。

## 执行契约

- 原 `[[asset:id]]` 引用语法不变。附件新增可选 `loading: on_demand`；缺省 `eager`，序列化省略缺省值，旧草稿、发布哈希和资源清单保持原形。仅作者显式修改并发布新 revision 后生效，不改现有用户内容。
- 交互聊天激活时加载正文、立即附件和按需附件摘要。新增内部只读 `read_skill_asset(skill_id,asset_id)`，只读取当前活跃 Skill、固定 revision、原正文明确引用且标记按需的附件。不能传路径、版本、模板参数；不能加载其他包或临时文件。
- 每次读取重新验证当前身份、分配、业务权限、正文和 manifest；实际正文、原文件与模板沿原存储校验。重复读取不重复追加正文或读取资源，但仍复查授权。未知 ID、漂移、超预算、撤权、取消均不改变状态。
- 内容追加到本轮 Skill 指令，工具结果仅返回有界回执，不重复返回长正文。采用现有整批屏障、staged state 和 AFTER_SKILL_ACTIVATION 检查点；混合业务调用本批不得执行。
- 检查点仅对新按需 Skill 保存 `deferred_asset_ids`；`loaded_asset_ids` 为立即附件加已读取按需附件。恢复验证原版本、清单、已加载附件与所有权；只保留原渲染文本，不重新套用模板或升级版本。未读取附件保持未读取，不能在恢复时突然全量加载。
- 媒体提示词准备、计划任务和 preflight 没有交互资源工具，自动按原完整读取机制加载所有引用，避免缺资料执行。旧 Skill 和旧 checkpoint 行为不变。

## 上下文治理

- 保留现有正文字节、单 Skill/全轮字节预算；新读取累积计入同一预算。不得静默截断核心规则或历史。
- 基于实际模型/重试模型的 context window，在 Gateway 调用 Provider 前对最终 Skill 请求（正文、历史、工具定义、输出预留）做估算预检和私有体积记录；未知窗口不编造硬限制。估算不是供应商精确分词；超限提供可操作错误，不在 Provider 扣费后才发现，也不自动丢必要资料。
- 编辑器明确区分立即/按需读取并展示原始文本体积；立即引用保持现有入口。作者自行决定核心规则与阶段参考资料，运行器不替作者改写方法。

## 实施批次与验证

1. 附件契约、发布/导入与渲染：缺省序列化兼容、摘要、媒体/计划任务完整回退。
2. Runtime 与聊天控制屏障：重新授权、资源读取、去重、预算、取消、原子 checkpoint 与恢复；无业务工具扩权。
3. Gateway 上下文预检：实际模型和重试适用、输出预算、工具定义计量、无副作用；旧非 Skill 请求保持原路径。
4. 编辑器选择与体积显示，补充导入、审核、UI 和跨层回归。
5. 实际本地文件 IO 基准，加最多 6 次真实模型请求、每次最多 512 输出 token 的合成验收；只用本机已配置供应商连接，不访问生产 DB，不执行业务工具或媒体生成。记录 TTFT、总耗时、实际 token 与输出符合性；不重试失败的付费样本来刷通过。

## 回滚与边界

不新增数据库迁移或依赖。旧数据无变更。新 on_demand 清单与带 deferred_asset_ids 的 checkpoint 不能交给旧二进制；回滚前完成/取消这些新任务并保留数据，或部署兼容读取版本，不能抹掉字段迎合旧程序。仅代码测试不能保证模型每次选对附件；真实验收如实报告，包括按需读取必然增加一次模型往返的成本。

## 已完成的验证与实测

本地实现完成，未提交、未部署。最终后端回归 1,475 passed / 20 skipped（58.96 秒），覆盖 Skill、定时 Skill、Gateway、聊天执行、工具策略、任务方法和恢复。末轮新增发布版本往返、旧 context 防伪和实际重试模型窗口检查后，针对性回归 140 passed，计划任务/工具循环/最终总结合并验证 161 passed（各组有重叠，不累加）。前端作者入口、选择器、管理面板与流式状态 157 passed / 4 skipped；TypeScript 构建通过。条件跳过包括付费/外部服务测试，不算执行通过。测试退出仍有既有反馈信号后台协程未收尾提示，本轮未修改该后台机制；不将此提示描述为已解决。付费合成验收独立显式开启，结果如下。

真实本地不可变文件读取，每场景 12 次；8 个长附件，统计含正文与原文件/提取文本校验，非模拟 sleep：

## 源码复审发现的两处边界修复（2026-11-21）

复审依据仍为 Grok Build 官方 `2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`，本次修复恢复本项目原有契约，不复制本地 CLI 的权限或版本模型。

1. **已有活跃版本读取**：`read_skill_asset` 在确认当前活跃、未退休和原正文声明的附件后，以 `source.load(candidate, restoring=True)` 重新验证固定 revision。deprecated 只阻止新激活，不阻止已有任务或其检查点继续；当前身份、组织、必需权限、assignment enabled、版本状态与正文/清单/文件哈希仍逐层校验。disabled/retired/撤权不因 restoring 放行；不读取最新发布版本，不增加工具权限，不修改检查点格式。原激活和计划任务配置校验继续使用新激活模式。
2. **聊天预算总结**：`_finalize_output_parts → _apply_budget_stop → synthesize_wrap_up → ModelGatewaySession._stream_attempt` 传递当前 Skill 上下文标识，覆盖 active 和 phase resident。Gateway 按实际重试模型，在槽位/Provider 调用前检查最终请求；私有标识不发送给 Provider。非 Skill 总结保持原调用参数。总结超限时沿既有失败合同：已有部分答案则保留并提示执行上限，无正文则失败，不伪造完成或再次发出模型请求。计划任务普通轮次/总结和媒体提示词原有检查保留。

两处均在上一轮用临时用例复现失败。本次纳入正式测试：`test_skill_assets_postgres.py` 新增 10 项，覆盖弃用前后已读/未读、原任务/恢复、新旧版本、重复读取、工具上限，以及真实数据库撤权/禁用/退休、文件篡改和当前权限/组织变更；`test_skill_context_budget.py` 新增 9 项，覆盖聊天总结 active/resident/inactive/无 Runtime × 足够/不足窗口、原文不变、无 Provider/槽位、部分答案回退和空答案失败。哈希用例明确区分未读附件：恢复不提前读取，首次使用拒绝篡改；已有加载附件恢复时仍检查哈希。
