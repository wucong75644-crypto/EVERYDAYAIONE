# 稿件工具合同与失败入口对齐

## 问题与边界

原链路在严格 JSON 解析失败后仍可能把原始参数交给另一解析器；重复 `document` 字段能落到最后一份内容并保存。另有公开 schema、参考图章节投影、组合校验、渲染容量和纠错字段不一致。供应商返回缺括号的原始 SSE 也已确认，不能将它误记为客户端丢字或声称提示词能保证零语法错误。

本次不改变历史稿件存储、原生任务/消息/图片 ID、引用快照、数据库和前端缩略图组件。不新增修参模型、关键词选图、括号自动修复或重试额度。

## 当前合同

- 格式使用 `x-content-profile`，图片选择器使用 `x-reference-kind` 的内部结构化声明；最终模型工具定义移除内部标记。文字消息来源和 `source_prompt` 保留真实消息定位，不因字段名和图片一致就转成 `image_ref`。
- 已选保存稿修订只开放 `base + updates`；恢复未登记历史文字时才开放 `message_source`，附完整 JSON 示例、真实读取要求和执行条件。图片仍用快照绑定的 `image_ref`，稿件用 `content_ref`。
- 修订阶段通过 `_content_workflow` 传递结构化事实，最终渲染说明和案例，不再从中文说明前缀或片段推导阶段。无图片引用目录的原生工具路径也保留阶段说明，移除内部元数据。
- 空 updates、空补丁、显式 null、混用新建和修订、恢复文字的执行条件、保存工具的确认条件，与原生校验对齐。共享 schema 校验器支持条件规则 `if/then/else`。
- 改规格所需字段复用后台修订屏障的 `required_update_fields`；素材变更保留已有引用。案例使用当前目标/规格/动作，过滤不属于当前开放合同的示例。示例只说明结构，不能替代读取原稿和完整正文。
- 参考图 `prompt` 渲染后总长不超过 20,000 字符，展示前缀及参考图判断渲染后各不超过 12,000，含固定标题和分隔。存储字段、读取合同、模型指导和渲染预检共享额度；跨章节总长由同一渲染器精确检查，不截断原稿。
- 调用先严格解码，按当轮实际提供给模型的合同准入，再保留引用、读取证明、版本、权限及执行批准校验。解码失败不回落到宽松解析执行。未转换的原生调用保留原始参数字节，避免影响调用哈希和重放。
- 语法拒绝提供容器路径、字符位置、UTF-8 字节位置、附近原文和未执行事实；解析器未提供位置时明确为空。字段错误使用当前公开字段。纠错必填提示从附带 schema 取得。
- 保存沿用原有三次失败上限；其他工具沿用现有纠错计数和停止机制。同批坏 JSON 不阻止独立合法调用，不重复记助手调用消息或执行已闭合的失败调用。

## 验证口径

`test_save_contract_failure_paths.py` 覆盖两格式、六场景、Chat/Responses 最终合同，公开与原生约束反例、实际保存入口的重复键/缺括号/非有限数字、容量合成、文字定位碰撞、纠错合同一致性、同批独立调用、无目录路径和素材保持。既有修订、停止/虚报、历史图片、编辑、纠错重放和数据库测试一并回归。

真实客户话术通过现有私有 HTTP 验收入口调用实际模型，独立保留完整请求、工具、参数、原始 SSE、拒绝回执和数据库证据；不属于默认 pytest 自动发现，也不以单测通过替代真实模型验收。

最终验证结果：

- 主要受影响模块：389 通过、4 条件跳过；其他工具边界及最终失败入口：185 通过；数据库与历史图链路：94 通过、18 条件跳过。前两组有重复覆盖，不直接相加。
- 两次开发过程中的历史稿回放未完成：供应商返回缺括号或空对象，入口安全拒绝并在原限次内停止。第一次还发现动态阶段规则加严后，旧的局部示例不再合法；已同步改为当前阶段示例并加入最终合同正反向回归。不能把旧示例与某个缺失字符说成已证实的因果关系。
- 第二次历史改稿回放中，公开 schema 和全部案例有效，仍出现供应商语法失败；该失败证据保留。一次独立的“展示上传图 → 展示旧成图 → 编辑”回放通过，历史底图字节哈希相符。
- 最终完整新对话七项业务动作完成：上传并选 Skill 写三个方案、第三项改成正方形 1K 实际出图、只改成 2K 不出图、新写绿叶方案不出图、展示上传图、展示旧成图、继续编辑旧图实际出图。两张实际新图均为 1024×1024；旧稿原对象连续修订，前两个条目保持不变；新任务使用不同对象；历史编辑使用正确底图哈希。
- 完整新对话有一次 `REQUEST_TARGET_IMAGE_REQUIRES_VIEW` 核图前置拒绝，模型纠正后交付。因此七项业务动作虽然完成，严格“全程无拦截”的验收断言仍失败，未放宽断言。
- 完整新对话实际发给供应商的 16 次请求中有 10 份保存工具合同、12 个 JSON 案例：schema 检查和全部案例校验均通过。该证据不等于供应商今后绝不返回非法 JSON。

## 后续完整入口对齐：图片可见性、候选与阶段

前述“上传图已进入模型视觉输入，选择时仍被要求核图”的拒绝进一步证实了后台缺口：同一图片被分页收录后走了第二套独立核图检查；当前上传目录未提供与历史目录一致的候选状态；分页总回执、拒绝回执和案例曾无条件建议先选择。只读识别失败还会丢失原候选或用户动作，编辑目标未确定时仍能过早调用生成工具。

本次统一实现：

- 当前输入、历史消息、工具核图输出、已验证追加附件在宿主侧声明真实图片身份。只有同一模型消息确实带图片部分，且身份属于当前冻结快照或宿主验证附件，才形成待确认视觉凭据。文字目录、URL 文本和模型声明不能制造凭据。
- 待确认凭据只影响本次模型工具合同及候选说明；正常完成模型响应后才写入当前任务、当前快照范围的读取凭据。失败、取消、未完成流不写入。内部声明在最终模型协议投影中移除。
- 当前上传、近期成图、分页与缓存、目标纠错、展示恢复共用 `requires_view` 与候选 `next_step`。需要核图时只提供读取下一步；条件已满足才提供完整选择参数。后台选择和生成准入复用同一判定，删除分页收录后的第二套矛盾检查。
- 重新展示的宿主验证别名归一到原图身份；原任务、消息、图片、稿件引用和权限机制保持。保留用户明确请求/稿件的唯一图片关联能力。
- 核图、选择、展示和生成仍是独立阶段。恢复保留 analyze / display_existing / edit 等用户动作；未绑定编辑目标时不提供生成工具。成功核图回执明确下一步；已绑定时继续原动作，不重复选择。
- 未确定目标时，全局案例不再默认填第一张已就绪图片；候选各自给出当前合法调用。选择工具、Chat/Responses JSON、提示词、例子及后台准入共同验证。没有关键词选图、新模型纠错通道或自动补括号。

### 补充验证与限制

- 定向及受影响模块最终 **637 通过、7 条件跳过**；数据库/历史链路 **94 通过、18 条件跳过**。分组有重复，不相加为唯一测试数。
- 新增反例覆盖分页收录不能改变上传图资格、缓存候选状态、未附图/文本 URL/未知身份不得形成凭据、失败/取消/未完成流不提交、跨快照失效、别名一致、动作保持、不默认第一图及未选目标不能跳过到生成。
- 真实供应商完整七步客户对话最终通过，全程零工具错误：选参考图 Skill 写三个方案；“第三个做成一张图，正方形，一千就行”；只改成两千不出图；新增绿叶任务不出图；展示上传原图；展示最早灯塔成图；“还是最早那张灯塔图，只把桌布换成浅蓝色，封面的图案和文字别动”。两次实际生图均完成，稿件修订与新任务隔离、历史底图哈希验证通过。
- 研发中的额外回放发现过 ambiguous 编辑被改成 other，以及跳过核图/选择直接生成；失败原始请求与 SSE 保留，促成上述阶段修复。最终独立三步回放 **37.03 秒通过**，上传原图展示、旧成图展示、继续编辑任务受理均零工具错误。该回放不发送供应商生图 POST，不能算额外真实成图；完整七步对话已覆盖两次真实成图。
- 对完整对话 14 次、最终回放 6 次实际模型请求逐份核对：316 份工具定义与 128 个 JSON 案例全部有效，内部图片身份/格式标记泄漏数为零。完整对话在最后的阶段/案例收紧前完成，最终回放覆盖收紧后的阶段；相关自动测试在最终代码上通过。
- 上述结果证明这些反例和实际话术通过，不保证模型以后绝不返回坏 JSON 或忽略工具合同。校验失败仍安全停止或使用原有有限纠错，不放宽权限、批准和版本屏障。

## 发布门禁发现的共享入口回归与修复

`719ace94` 首次发布在 tests_and_build 停止：前端 2818 通过/4 跳过；后端 16639 通过/259 跳过/4 xfailed，但另有 21 失败。生产未更新。相同21个用例在上一部署 `8e84b675` 全部通过，本次全部失败，排除供应商和偶发波动。

13 个真实回归：7 个普通生图坏 JSON 被通用纠错提前消费，绕过原“无法保意即停止”的策略；2 个坏激活调用被移除，业务兄弟调用绕过 Skill 批次屏障；4 个任务控制/工作计划的专用错误回执被通用错误取代。另8个测试未同步：4个固定内部schema快照、1个内部/最终模型schema比较、1个旧文案分割取JSON、2个已确认的编辑/分析场景预期。

修复保留公共严格解析，错误仍交原工具入口处理；原始控制调用留在批次内。Skill激活、停用、附件读取及任务控制/工作计划的实际解析也使用严格解码器，不能为恢复屏障退回重复键最后值生效的旧解析。结构化稿件保存（包括模型主导恢复入口）继续由严格保存合同处理，不混入旧任务控制的同名工具。普通生图仍使用原图片纠错策略与单次额度；新结构化图片路径保留原有有界参数纠错。

测试同步保留完整schema比较：内部快照显式登记 `x-reference-kind`，最终Chat/Responses校验该标记被移除。案例从parameters.examples读取并逐份校验；场景分别验证模糊编辑保留动作而不存在的明确图片拒绝、展示阶段和分析阶段各自案例。

新增 `test_argument_error_ownership.py` 覆盖控制+业务正反序、坏JSON/重复字段/非有限值、配对回执和检查点、领域回执与无业务执行，及最终协议无内部标记。最初221项定向验证通过；包含此前18个合同/历史图片文件、此次漏掉的7个既有文件及Skill等相关调用方的扩大验证为942通过、8条件跳过。此次不以单测替代发布门禁与线上业务验收。

此前637通过的范围没有包含这7个原有调用方文件，属于共享执行入口回归选择遗漏；不是全部失败都能通过更新测试处理。完整失败对照、隔离业务探针和修复定向日志保留在 `/private/tmp/release-719ace94-failure-diagnosis/`；未调用真实供应商的探针不能当作实际成图证据。
