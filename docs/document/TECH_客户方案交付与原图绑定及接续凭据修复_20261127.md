## 根因与对应修改

1. 首次参考图方案只回复 test。实际模型选了 `respond_without_execution(purpose=explanation)`，不是后台替换了正常方案。同时原方法禁止工具的文字与平台保存要求冲突；新建投影删掉 base/updates，却保留修订案例；短引用投影另加的新建案例缺少必填展示前缀。现增加已核验方法的宿主交付说明，明确文字保存与实际生图不同；新建与修订案例分开，所有可见案例用最终投影 Schema 校验。原 Skill 内容和发布身份不改写。
2. 补问时丢失规格和参考图。模型按允许的形式只保存正文；后台结构化上下文已有原图和逐项规格，但保存入口只收本轮附件及既存保存稿的来源。当本轮没有附件、上轮也没有稿件时，来源为空，并连带跳过规格绑定。现把明确选中且在服务端会话快照/核验历史中出现的原图加入来源；不根据最近一张图片猜选图。规格绑定不再依赖当前附件存在。执行前若旧稿缺少本次已选的执行参考，则返回读取→修订→执行回执，不能静默改成文生图。
3. 正确读取第三稿并提交 2K 后接续失败。Python 用本轮 `_content_revision_reads_v1` 替换旧记录，SQL 却把它视为必须不变的历史字段。迁移 387 同步本轮字段边界；六项接续上下文必须等于新检查点，旧读取/恢复记录仍随原检查点保留。历史成果、操作、归属和修订保护均不放宽。

另移除图片等待确认分支误追加的视频专属说明：图片实际参考使用 input；只有仅供理解的素材使用 analysis。不是将所有素材自动绑定，也不改变显式逐项的分析用途。

## 失败行为与兼容边界

- 待交付文字方案不能由 explanation 直接结束；按当前输入、已保存对象及等待条目统计实际交付。允许有限纠正，两次仍没有完成则明确说明未完成。澄清、普通解释和历史图展示保留。
- 未核验或不存在的图片身份拒绝保存；没有选图时不自动选最近图片。
- 修改旧稿继续要求本轮读取凭据、同一对象新版及保留未选条目。素材缺口使用同一修订恢复流程，不偷偷拼接原图或改变执行原文。
