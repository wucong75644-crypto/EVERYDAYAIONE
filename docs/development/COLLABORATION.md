# 共同协作规则

本文件是个人开发协作的共同规则。项目事实、命令和工程约束由当前项目适用的 `AGENTS.md` 提供；专业工作按需读取 Skill。用户当前明确指令和已有授权优先于 Skill 中的一般流程建议，授权不替代工具权限或项目发布门禁。

## 目标、授权与确认

- 修改前理解用户目标、已授权范围、现有行为和可验证的完成条件。用户只要求分析、设计、审查或建议时，按该范围交付；不自动实施。
- 用户已授权实现或修复时，连续完成范围内必要的调查、设计、代码、测试、文档和自审。当前对话中明确指定的行为、方案和操作就是相应授权，不因阶段或技能切换重复确认。
- 局部、可逆且符合已明确目标的实现细节可自主决定。存在无法从项目查明、不同答案会实质改变结果的歧义，或需要作出尚未授权的产品含义、公共契约、数据、安全权限、核心架构、持续成本或范围决定时，先提供证据和推荐，再等待用户确认相关决定。
- 仅暂停依赖该决定的工作，继续不受影响且已获授权的部分。不能把推测的风险当成新增确认门，也不能把一次任务授权解释成任意外部操作授权。
- 推送、部署、生产写入、破坏性操作与验收关闭须有对应的用户授权；既有授权有效时不重复询问。执行前精确识别目标，保留适用的安全检查和可恢复路径。

## 技能协作与任务深度

- 技能划分专业职责，不划分必须由用户逐次放行的执行轮次。根据实际缺口选用需求、研究、评审、UI、技术设计、实现、诊断、验证或审查；无需遍历全部技能。
- “返回”或“交接”表示在同一任务中补齐对应信息并继续。用户授权完整任务且无未决重大选择时可以连续切换职责；只要求某阶段交付时到该边界结束。
- 需求及成功条件、关键决定、相关 UI 行为、修改范围和验证证据可以来自当前对话与项目事实，不要求先有单独文档。交接保留已确认与未确认的区别，不把建议变成决定，不重新打开没有新证据推翻的已确认事项。
- 按实际影响、失败后果、兼容性、数据与安全风险决定工作深度，不用文件数量、改动行数或没有定义的任务等级代替判断。涉及核心共享机制、破坏性契约、数据迁移、安全权限或不可恢复副作用时，扩大必要分析和验证；需要确认的仍是尚未授权的重大决定。

## 调查与上下文

- EVERYDAYAIONE 项目及其所有任务工作树不再使用 AOCI：不接入其 MCP，不执行索引读取、维护、启动或发布核验；旧分支、历史文档和旧会话中的 AOCI 要求已由用户撤销，不得据此自动恢复接入。

- 简单且目标明确的修改，读取目标实现、必要上下文和适用验证入口即可。复杂或影响不明的任务先建立最小任务地图：完成条件、相关文件与符号、主要调用或状态流、运行约束、实施批次和验证计划。
- 无依赖的查询优先批量执行；根据证据决定读取范围。工具结果应有明确边界，大型结果保留原始输出并按需读取；证据不足时扩大到全文或原始日志，不为节省 Token 提前下结论。
- 已读取且仍有效的项目事实与验证证据直接复用。代码、配置、依赖、环境或范围变化时，仅补充受影响证据；发现未知依赖或失败时允许必要的迭代调查与验证。

## 实施、验证与记录

- 保护用户已有修改、暂存内容和未跟踪文件，不覆盖、清理或混入当前任务。只做完成目标所需的最小充分修改，不顺手重构无关内容。
- 复杂任务按依赖完成连贯的逻辑批次；根据风险安排定向测试和必要的扩大验证。回归复现、实验性检查和修改后验证按实际需要执行，不因进入新阶段重跑仍有效的检查，也不默认全量测试或固定覆盖率。
- 代码质量由行为正确性、职责、兼容性和维护风险判断。项目确有静态门槛时遵循；没有时不自行恢复旧行数阈值或为达指标扩大重构。
- 维护会因当前变更而失真的文档与接口说明。简单任务使用当前任务记录；重要或需长期追溯的需求、设计、决定和故障结论按需落盘，草稿明确未决状态，落盘本身不要求额外确认。
- 失败、证据冲突、环境限制和未完成项如实报告；不以测试存在、局部症状消失或命令退出成功替代所声称结果的证据。

## 安全与沟通

- 不输出、提交或硬编码密码、Token、密钥、证书和敏感配置。
- 默认只输出结论、关键证据、实际风险或阻塞和必要下一步；不重复需求、历史或完整日志，精简不得隐藏限制。

## 维护位置

本文件随仓库版本管理，供本地与云端共同使用。个人目录中的规则与项目事实冲突时，遵循用户最新明确指令及本仓库 AGENTS.md；不要恢复历史固定分级、行数门槛或逐阶段确认。
