## 全链路模型

普通聊天：选择器摘要 → POST 消息与 SkillIntent → 持久 Actor 队列/唤醒 → Worker claim → 历史、附件、知识上下文与工具权限准备 → Skill 目录与固定候选 → 原子激活依赖集合 → 正文/资源校验展开 → checkpoint → 原模型循环 → 工具策略、审批、结果 → 流式持久交付 → 终态提交。

图片/视频模式：消息预检 → Skill 激活 → **额外模型生成媒体提示词** → 真正媒体生成。这个提示词模型调用属于当前功能语义，不是普通聊天手动激活的必经开销。电商策划还经过当前任务引擎、来源、已保存方案与组合协议；不能重建一套 Skill 专属执行器绕过这些约束。

计划任务：使用任务明确锁定的 revision snapshot，禁止继承当前会话绑定和动态选技能。恢复：只用原 checkpoint，重新核验当前权限及文件哈希，不自动升级版本。

## 系统侧的额外等待与正确性边界

- HTTP 前置还有 IP 定位：配置高德且 Redis 缓存未命中时，会等待外部 API，默认超时 3 秒；这发生在 Skill/Actor 前，不能把它算成激活耗时。当前定位影响位置相关回答，未基于无样本假设移除。
- Actor 有 Redis 唤醒和扫描兜底（worker 构造默认扫描间隔 2 秒、并发 5，实际运行配置需现场核验）；唤醒失败或 worker 饱和会延长等待，Skill 本身无法消除此段。enqueue RPC 为异步入口中的同步 DB 写调用。曾尝试线程化，但复核发现取消可早于后台写完成，会扩大受理、slot 交接和幂等的未确认窗口，已撤回；当前保留原入队实现。要进一步优化需要独立设计受理与取消协议。
- PromptBuilder 装配历史、文件、记忆/知识资料，属于 Skill 前的共享成本。最新主分支已有 context/history/knowledge/answer.prepare 阶段计时，本次复用，不另建上下文引擎。
- Model Gateway 有槽位准入、实际模型路由、超时、重试和 provider 采样；不能把槽位等待算成 Skill 正文读取。actual request token/cache usage 仍从 provider usage 判断。
- 任务引擎可能进行需求、完成性审查；知识回答可能为证据/引用验证暂存正文，再交付。这些按模式发生的模型回合与持有输出不等于 Skill 多调了一次模型；不能为了首字指标跳过任务正确性和知识校验。
- 每次业务工具仍由统一 ToolPolicy、审批与重放屏障控制。已有重复工具调用保护、预算与参数修正；本次不提高循环上限或关闭校验。
- Actor outbox、持久化、fencing、checkpoint 和网络推送均有成本；已有首次正文/首次持久化/首推与交付统计。启动确认前移不会缩短模型计算，也不代表激活已成功。

## 本次实施决策与批次

P1（公共权限读取）：提供 `check_many`，一批只读取一次新鲜任职事实；复用同一权限判断函数，组织/个人边界一致。Skill 目录、会话绑定、推荐和每次工具分派共享批量检查。同步 LocalDB 读取在线程执行，不能阻塞事件循环。不做跨请求授权缓存，激活/工具分派仍复查。

P2（定向解析与版本锁定）：HTTP 先沿既有入口验证会话访问与图片积分预检，再在消息写入前捕获明确选择，只查询该 key 的当前可见候选；失效选择作为可幂等重放的业务 409 返回，不留下孤立消息，保留原优先级和最新目录语义。媒体 explicit_only 只解析选中及固定 Skill。Actor 保留其他技能自动发现，但显式选择恢复 enqueue 时捕获的 package/revision；同名覆盖、发布或排队不能替换目标，撤权仍拒绝。

P3（缩短关键路径与反馈）：显式选择或固定 Skill 时跳过可选规则推荐；普通自动发现仍保留推荐。尽早发送现有 message_start，让准备工作可见；此事件不表示激活或任务成功。依赖激活失败、取消、恢复语义不变。

P4（可观测性）：复用已有有界、异步、私有生命周期采样。增加 intent、绑定、发现、身份/权限、正文、附件、初始化、激活和媒体提示词阶段，记录时间、成功/取消与数量/字节，不记录正文、路径、SQL、密钥。与现有 Actor claim、Model Gateway 槽位排队/路由/采样、模型首字、工具和 sink 首次持久化/推送关联，不能将嵌套耗时相加。

P5（验证与内容治理）：建立权限批量和事件循环响应、显式解析、排队发布版本锁、推荐旁路、异常/取消、重放与体积回归；用可控模拟 IO 基准报告查询次数与机制收益，不冒充线上 TTFT。保留所有现有正文和附件预算，先测真实请求大小。

以下第 1、2 项已在后续实现并完成本地及真实模型合成验证，具体契约、兼容边界和速度取舍见 [Skill 按需附件与上下文治理](TECH_Skill按需附件与上下文治理.md)。其余项保留为后续方向。

2. **上下文预算**：在各实际模型分词/上下文能力上增加预检与清晰错误；发布阶段提示大正文/重复附件，支持作者把阶段无关例子拆成参考资料。不得自动删必需规则或把字节当 token。先依据实际样本选择软阈值，不凭上限直接下调并破坏已发布内容。
3. **目录缓存**：只缓存内容/摘要或带版本的授权投影。跨请求缓存授权需要成员、assignment、发布、禁用和组织状态的一致失效机制；当前无充分失效保障，不引入 TTL 授权缓存。
4. **模型调度**：已有模型槽位、超时、重试、熔断与流式统计；根据 queue_wait / routing / first_body 判断需要调整哪一层。媒体提示词生成若想省掉，必须定义用户明确已提供可执行提示词的直通行为，不能一律跳过 Skill 方法。
5. **模型与上下文组织**：Grok 的格式还允许 model/effort 声明；本项目继续由用户/宿主选择模型与预算，不能让导入文本自行提高持续费用。稳定方法与动态历史的放置可结合 provider cache token 比率优化，但不凭缓存假设移动指令优先级。
6. **使用体验**：继续复用选择、仅本条/固定会话、版本冲突/撤权反馈、依赖能力展示。后续可做目录搜索/最近使用、加载阶段状态，但应有端到端恢复兼容，不用“已启用”冒充业务完成。

## 2026-11-21 用户要求的完整逻辑复核

复核结论：发现并修正两处边界问题，撤回一项未充分保证取消语义的写入优化。当前差异未发现尚未解决的高置信阻塞性回归；这不等于真实模型或生产验收通过。

### 发现与修正

1. **会话鉴权顺序（已修正）**：前置 Skill 捕获原先在 `get_conversation` 前执行，无权/不存在会话可能先被返回 Skill 409，破坏原 404 行为。新增 `prepare_generation_request.before_message` 内部只读预检钩子：先原会话鉴权、图片积分预检，再捕获 Skill，最后写消息。保留现有 retry/regenerate_single 不创建用户消息的规则。没有重复查询会话；普通入口为了正确性不再并行鉴权和消息写入。
2. **Skill 拒绝的幂等错误（已修正）**：捕获抛出的 FastAPI HTTPException 会落入外层 `fail_unexpected`，首次 409 的重放被记录为 500。捕获边界现在转换为标准 AppException，保留 4xx 状态、安全提示和稳定 `SKILL_SELECTION_UNAVAILABLE` 代码。没有变更其他 HTTP 入口或未捕获异常的契约。
3. **后台入队写与取消（已撤回尝试）**：`asyncio.to_thread` 不能中止已经开始的数据库写，调用协程取消后，线程仍可能提交，而 HTTP slot 交接与幂等仍未完成。本轮不引入额外受理协议，恢复 `actor_enqueue.py` 的原实现。仅保留可安全丢弃结果的只读权限查询线程化；已验证取消后的读取结果不会继续派发业务。
