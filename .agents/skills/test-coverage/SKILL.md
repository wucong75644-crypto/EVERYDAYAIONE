# 测试覆盖与验证

共同约定：[共同协作规则](../../../docs/development/COLLABORATION.md)。本 Skill 的职责边界不构成新的用户确认门；已有授权与证据按共同规则继承。

## 目标

证明本次变更实现了已确认行为，并对最可能、影响最大的回归提供有效保护。

测试覆盖不是测试文件数量或单一覆盖率数字。根据变更性质自由选择验证方式，不把所有问题强行转成单元测试。

## 输入与范围

先使用同一任务已有的任务地图、需求、决策、设计、验收条件、变更范围、调用链和测试证据。只有证据缺失、相互冲突或相关状态变化时，才通过 Git 状态、差异或目标文件定向补充，不因进入本 Skill 重新调查、重新读取全部变更文件或重建调用链。

识别现有测试、项目测试约定和已知基线问题。不能只按文件名猜测覆盖情况，也不能把测试存在等同于行为已经覆盖。

用户已经授权实现或补充测试时，不为正常范围内的测试修改重复请求确认。需要扩大业务范围、访问尚未授权的真实外部系统、产生明显成本或执行未授权的高风险操作时才暂停相关部分。若已授权完整实现，测试暴露的业务缺陷可在同一任务交给实施或诊断职责修复；仅授权测试时不修改业务实现。

## 风险判断

根据实际行为和失败后果判断验证深度。考虑哪些行为发生了变化、哪些调用方依赖它、错误会如何暴露、是否涉及状态、并发、数据、安全、兼容或不可恢复副作用，以及现有测试在哪些层次最有能力发现问题。

不要机械套用固定风险分类。简单纯函数可能只需定向单元测试；跨边界契约、状态迁移或用户流程可能需要不同层次的验证。

## 设计测试

测试用户或调用方可以观察的行为、已确认验收条件和关键失败方式。避免绑定无关实现细节。

对于Bug修复，测试不能只证明用户报告的单个操作不再报错。应根据已验证根因覆盖被破坏的系统约束和合理范围内的同类入口，并确认修复没有把错误转换成静默失败。

回归验证应尽可能在修复前暴露问题、修复后通过；做不到时说明限制和替代证据。

选择能够以最低维护成本提供真实信心的测试层次。Mock 只用于隔离当前测试不应依赖的边界；需要验证适配、序列化、协议或集成行为时，不得用 Mock 掩盖目标行为。

复用项目现有测试风格和基础设施，不为单个测试引入不必要的框架。

覆盖率工具可以帮助发现遗漏，但只有项目已有明确门槛时才作为硬条件。没有统一门槛时，用风险、行为和验收条件说明为什么覆盖充分。

## 执行顺序

先判断已有验证是否仍对应当前代码内容、配置、依赖、环境和任务范围；commit SHA 可辅助追溯，单纯提交元数据变化不自动使相同代码的证据失效。仍然有效且覆盖当前风险的成功证据直接复用；存在缺口时才运行与改动直接相关的最小测试或检查。

执行前先形成一次验证漏斗，明确静态或结构检查、定向测试以及触发扩大验证的条件。尽量按层批量运行，而不是每修改一个文件或进入一个阶段就重复运行测试。

随后根据调用链和风险判断是否扩大到受影响模块。只有在高风险、共享基础设施、广泛影响、发布门禁或定向结果无法提供足够信心时，才运行更广范围测试。

不得默认运行全量或 External 测试。同一代码与环境状态下已经通过且仍覆盖风险的命令不得重复执行；只有代码、配置、依赖、环境、范围发生相关变化或原证据不足时才补跑受影响部分。确需访问真实外部服务、敏感数据或付费资源时，先核对已有授权；缺少对应授权时再请求，不因技能切换重复询问。

记录实际命令、通过失败数量、跳过项、环境限制和基线差异。

## 失败处理

测试失败时判断它属于：

- 本次改动引入的回归；
- 需求或设计理解错误；
- 测试预期已经过期；
- 测试自身缺陷；
- 环境或依赖问题；
- 与本次任务无关的既有失败。

本 Skill 可以修改测试代码，但不擅自修改业务实现。发现业务缺陷时把复现证据返回 `testing-bugfix` 或 `implementation`。

不得删除断言、扩大容差、过度 Mock、跳过测试或改变需求来制造通过。

## 完成条件

完成报告应使用户能够判断验证范围、关键命令或测试结果、未执行项及原因、基线失败、环境限制和剩余风险。全部成功项合并汇报，失败项才展开。

Bug修复还应说明测试如何对应根因，而不只是对应最终异常位置。

不能因为已执行的测试通过就笼统宣称整个系统没有问题。

## 阶段边界

本 Skill 不负责：

- 修改产品需求；
- 为测试方便改变已确认行为；
- 擅自修复业务代码；
- 默认调用真实外部服务；
- 用固定测试模板替代风险判断。

完成后把精简的验证范围、结果和未覆盖风险留在同一任务证据中，供 `review` 直接复用。

## 交付格式

遵循项目 `AGENTS.md` 的增量精简输出合同。使用“范围 + 结果”汇总成功证据，不重复测试日志和已确认验收条件。
