# AI规则与Skill系统 V4

## 目标

在不降低开发、测试、安全和发布门禁的前提下，减少长期上下文重复、阶段规则冲突和无决策价值的输出。

## 分层

1. 用户级 `AGENTS.md`：跨项目通用安全与协作原则。
2. 项目根 `AGENTS.md`：项目宪法、任务门禁、Skill路由和增量输出合同。
3. `backend/AGENTS.md`、`frontend/AGENTS.md`：按目录加载技术规则。
4. EverydayAI Skills：需求、研究、评审、设计、实施、测试、Review和运维工作流。
5. 脚本：文件长度、Python函数长度、未完成标记和migration/rollback配对等机械门禁。

## 任务等级

- A级由行为、契约、架构、数据、安全和权限影响决定，必须方案确认。
- B级是范围明确、可逆、无公共契约变化的小型修改。
- C级是Git、依赖、环境、部署、重启和已确认迁移执行等操作。

文件数不再单独决定等级。编写migration属于A级，执行已确认migration属于C级。

## 输出合同

默认只输出结论、证据摘要、风险或阻塞、下一步；不复述需求和历史，不复制完整日志。普通回复默认不超过300字，A级方案、事故、安全数据风险、部署失败和用户明确要求详细内容时例外。

## 单任务执行协议

- 一个用户任务默认由同一主 Agent 连续完成，Skill 作为方法按需应用，不作为常规阶段接力。
- A级和复杂任务采用“集中调查 → 任务地图 → 用户确认 → 批量实施 → 集中验证”。任务地图至少包含完成条件、相关文件与符号、主要调用链、运行约束、修改清单、实施批次和验证计划。
- 调查先读取目录、符号、调用方和目标片段；证据不足时逐步扩大，必要时读取全文。任务地图完成前不得开始零散修改。
- B级任务在同一轮形成简短内部任务地图后直接实施；C级任务先进行一次环境和目标预检。
- 实施按完整逻辑批次推进，不把逐文件“读取—修改—测试”作为默认循环。只有新证据推翻计划、暴露未知依赖或使证据失效时才重新调查。
- 同一任务复用范围、文件、调用链、根因、设计、diff 和测试证据；切换 Skill 不触发重复调查。
- 代码、配置、依赖、环境、任务范围或 commit SHA 变化，或者证据不足时，仅使相关证据失效并定向补充。
- 无依赖读取和检查优先并行或批量完成，连续机械步骤优先一次工具调用或项目脚本。
- 跨项目通用读取协议由 `~/.codex/AGENTS.md` 提供：先结构化定位、上下文有界、原始结果保留、证据不足时继续扩大。
- 本项目默认单次工具结果不超过约 10K Token；禁止一次拼接多个完整大文件、完整日志或大范围差异。需要完整上下文时允许并要求继续读取。
- 修改完成后先确定验证漏斗，再按静态检查、定向测试、必要时扩大执行；相同代码状态下仍有效的成功证据不得重复生成。
- B级任务由主 Implementation 或 Testing 在同一执行轮完成实施、验证和自审，不为流程形式单独加载 Test Coverage 或 Review。
- Test Coverage 和 Review 只在用户明确要求、A级或高风险、证据不足，或独立性会显著提高质量时单独使用。
- REQ 文档只用于跨阶段交接、长期引用或稳定编号追踪；TECH 文档只用于 A级、架构变化或长期追溯。简单任务不为流程形式创建文档。
- Git Push 和 Deploy 通过统一脚本单次执行，成功只消费最终摘要，失败或状态不确定时才进入定向诊断。
- 部署脚本将测试、构建、同步和远程操作的完整输出保存在本地日志；成功仅返回阶段结果和结构化发布状态，失败最多展开关键尾部并允许按日志路径继续调查。
- 服务重启依赖 systemd unit 的 cgroup 生命周期，不使用 `pkill -f` 等全局进程匹配。

## 兼容与安全

- 现有12个 EverydayAI Skills 保留；项目路由使用与 Skill frontmatter 完全一致的 `source-command-everydayai-*` 名称。
- Git Push与Deploy继续使用已有失败关闭脚本。
- Restart Skill改为精确PID和端口治理，禁止宽泛进程匹配。
- 机械门禁只检查本次明确文件，避免既有质量债务阻塞无关任务。
- 无法可靠自动判断的复杂度、TypeScript函数长度和文档语义由当前主 Skill 判断；满足独立验证或审查条件时再交给 Test Coverage 或 Review。

## 验证

- 静态核对V3.3规则均有新归属。
- 覆盖新功能、Bug、UI、数据库、推送、部署和重启的Skill路由。
- 运行质量脚本自身单元测试和真实任务文件检查。
- 执行Python/Shell语法、`git diff --check`和完整差异审查。

## 回滚

项目文件通过Git精确回退；用户级规则和个人Skills修改前保留独立备份。任一Skill触发、安全门禁或运维保护缺失时恢复V3.3，不启用V4。
