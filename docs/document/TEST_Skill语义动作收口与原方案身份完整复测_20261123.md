# Skill语义动作收口与原方案身份复测

本轮用户授权统一收口词法门槛，保留聊天、追加、多轮改图、编号执行、权限和恢复；不部署。沿用原任务工作树，未操作用户主工作树。开始日期为2026-11-23，以下实测跨客户端会话持续进行。

## 实际修改

- 复用EcommerceWorkflow原语义路由，识别本轮文字交付、已有方案执行、实际图片编辑、重复生成、解释等动作。新Actor消费者统一读取该结果；旧快照保留原兼容解码，不新增数据库表或审批模型。
- intent、input_revision及明确的image_count作为现有工作流投影的可选字段，随原检查点持久化。旧投影不注入空默认字段；恢复冻结结果不重新理解同一输入。JSON数字字符串只在供应商结构化返回处转为整数，不从用户文字提取数字。
- 服务器已确定的数量不再交给主模型重复填写。模型工具视图隐藏该字段，业务服务读取已核验Actor父任务里的数量；冲突拒绝，不静默覆盖参数。未给数量、旧调用、固定页面配置及原1–15范围保持兼容。
- 撤除执行引擎内词法批量调用捷径；新Actor的工具投影、文字派发拦截、保存/执行选择及编辑入口读取同一动作。普通纯文本聊天没有统一增加分类调用。
- 新输入包括纯文字和素材：已送达后更新动作，连同实际消息写回原检查点；模型读取旧输入后的调用不再派发。追加背景/图片不自动重置原数量。
- 通用稿件接管不改原接管SQL：保留历史根任务、版本、方法和权限上限；从现有_task_followup_input_checkpoint读取本窗口已冻结的动作。核对窗口归属，不吸收未纳入该动作的新补充或取消事件。
- 新声明的prompt代码块作为执行片段边界，块外说明留在显示间隙，整份页面原文字节可重建；旧无代码块稿件保持原登记方式，不按总结词表删除内容。
- 图片顺序标记扩大到通用编辑入口：从真实引用解析出输入位置，添加位置映射；保留图片顺序和模型润色正文。原图/任务ID、权限、哈希、尺寸、受理幂等与恢复链保持不变。
- 知识库快速答复不因一个普通讨论动作被误判为电商执行；既有检索优化及数据权限不扩大。

## 正式入口与真实性

使用正式HTTP /messages/generate、ConversationExecutionService、Actor执行器、WebSocket追加和原资源/恢复链。数据库与Redis均为本测试临时实例，假测试用户；不连接生产数据库。

主模型Qwen3.8-max；关闭思考后的专用三阶段沿原Qwen3.8-flash配置；真实KIE gpt-image-2-image-to-image。Image 2选择仅在测试fixture覆盖，生产默认模型未修改。真实素材取自原失败会话的两张图片。

每条完整链包括：先只写3项、运行中追加参考与浅米灰背景、选择第1和第3项出图、明确引用其中一张改蓝、无引用继续改灰、在新会话重放原双图波点编辑，最后普通聊天确认未多创建图片任务。追加测试使用同一商品的另一份观察图；原双图场景使用两张不同原图。不能据此声称已测试任意新SKU在策划中途替换的所有语义组合。

主图链还在已持久化ready交付pending处模拟工作进程丢失，验证恢复不重调模型。前端业务代码本轮未修改；页面协议/登记、持久化及下一轮引用按正式后台链与已有协议回归验证，本轮没有额外声称重新跑过浏览器UI。

## 验收契约

编号执行必须匹配origin.plan_source的plan_id、revision、item_id、request_text_sha256及原正文；通用稿件必须按保存条目取原稿；灰图来源哈希必须为蓝图输出；双参考图顺序与真实原文件哈希逐项匹配，保留原比例/默认规格和输入位置映射。

供应商提交必须恰为model+input，input仅prompt、input_urls、aspect_ratio、resolution；prompt与冻结请求一致、图片URL顺序对应实际引用。检查内部资源身份未混入prompt，实际修改正文必须保留模型润色，不以用户短句替换。最终聊天不能新增图片任务。
