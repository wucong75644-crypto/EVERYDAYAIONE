## 实现

1. content_revision.public_fields/model_view 是工具阶段、最终系统阶段、模型中途停止的完成纠正及工具发现回执共用的公开字段投影。只转换结构化 required_update_fields，在明确的 items/pending_action/recovery 元数据路径内遍历，不替换用户正文和options，不做关键词意图判断。普通稿件仍用原原生字段；参考图稿件使用 prompt/presentation。读取证明、保存协议和原存储不变。
2. 修订案例提供具体短稿的执行正文、负面要求和展示说明，尺寸来自当前已校验的差异；明确独立短稿仅演示结构，实际修订必须基于读取原稿。局部章节仍允许省略；素材改动不迫使重写正文。案例通过公开schema、短引用还原和原生保存参数校验。
3. argument_syntax_issue 沿已有词法容器栈诊断。只有在解析位置遇到与栈顶不匹配的结束符时，返回 container_not_closed、容器路径、expected_token、actual_token 和具体说明。字符串内的括号不参与容器计数，保留原字符/UTF-8偏移。重复字段、缺逗号、未结束字符串和非有限值不误报“缺对象闭合”。它不修改参数、不自动补括号。
4. ArgumentSyntaxError 的纠错继续返回未保存/未派发、原操作形式、根字段要求及工具名，使用当前 tools 定义，不在该语法回执重复附完整parameters。保留原始错误调用与配对回执。业务格式、引用、普通生图和任务控制的原错误合同仍保留，不统一成另一套通用纠错。重试预算、停止条件、strict、模型/供应商、批准和收费行为不变。
5. 真人验收的写稿步骤必须有本次owner的 committed 保存回执、当前artifact、完整条目及正确来源任务；修订继续验证对象、兄弟条目和规格，新任务验证独立对象。恢复读取旧成功记录或只返回文字不能过关。离线证据审计同步支持七步/含跨任务的八步，并重新核验保存证明。
