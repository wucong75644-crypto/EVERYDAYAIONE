## 设计

1. 原KnowledgeRun.start新增可选defer_default参数，旧调用缺省行为不变。真实持久引用与旧快照优先恢复，绝不降级。仅新的自动默认范围返回DeferredKnowledgeScope：沿原RLS选择可用根范围，只做必要的消息/权限检查，不枚举正文对象、展开引用或保存快照。空范围仍为None，不增加其审核模型调用。
2. stream_setup选择延迟默认范围；保留显式引用和恢复上下文。Deferred策略不作为KnowledgeRun注入工具上下文，旧知识预检不会自动触发；原knowledge_discover由模型根据真实缺口调用，首次真正使用时通过原事务冻结快照。后续重读、恢复、撤权仍用原机制。
3. 按已批准保守边界：明确自包含请求可流式；默认范围可用但请求模糊时，仍由独立的原source-free审核判断候选私有断言，正文和思考不先发。不是回答模型自报免审，不关闭知识校验。原图存在只作为服务器输入类型解释，不证明公司规则/订单或任何知识已读取。实际KnowledgeRun一旦出现，使用其真实原文审核与活权限复核。
4. 仅当独立审核返回有效requires_sources=true，且是延迟默认策略，宿主在原模型循环中给一次补依据反馈。未审草稿绝不进入可见内容或普通模型历史；不复读猜测，不新建执行链。协议错误/供应商故障不触发泛重试。修复标记留在原系统上下文，恢复不重置次数；原模型预算/付费计量有效。预算耗尽交付保留记录的部分状态，不额外调用收尾模型。实际显式知识审核的纠正/摘录/拒绝策略不变。
5. 步骤拆解仍由主模型结合完整用户目标、手选方法、原资料、已有成果、工具说明判断；复用原计划契约，明确输入/产出与真实依赖，按ready步骤/能力门推进。只在原工具并发规则允许时并行，不修改共享资源写入、审批、受理幂等或预算。不把默认知识可用性当所有步骤前置。没有新增每条消息必跑的规划、分类或评审。

## 验收矩阵与证据边界

- 普通聊天/原图分析：真实PromptBuilder与原消息入口，确定边界内增量早于生成结束；无默认快照/检索/知识审核。
- 原两Skill文字规划、成图复用：用原完整包、原素材；新默认策略不抢先切任务或丢手选信息，原方法/事实/完整交付门保持。脚本模型只能证明宿主执行边界，不冒充千问理解测试。
- 知识问答/企业规则/显式引用/空库/工具失败：按需发现，独立审核仍拦私有无依据结论；已读原文与权限撤销检查有效，空结果不能断言整库无资料。
- 多步任务/异步恢复/追加与暂停取消继续：原上下文和结果不变，独立步骤ready，必要依赖不提前执行；中途发现知识后下一生成轮必须先审，取消或撤权不能被fallback吞掉。
- 补依据一次、恢复不重置、预算耗尽无未计量收尾、账单/防重/原ERP边界。
- 记录“首次主模型前是否已展开全量快照”、读/检索次数、模型轮数、首正文/审核/总耗时；本地阻塞控制和合成时钟可验证因果与顺序，不能承诺真实供应商时延或语义成功。

## 兼容、回滚与限制

无数据库迁移、无新外部服务、无新消息协议；defer_default缺省false兼容旧调用，旧持久知识快照先恢复。回滚应用代码恢复原默认快照时机，真实成果与旧检查点保留。只在整套适用检查通过后考虑发布；真实付费验收未授权前不跑，不重生已有图。

模糊请求仍会等待最终独立核验，不能承诺所有问答立即流式；明确企业知识问题在按需路径下可能增加工具往返，不能承诺所有任务总耗时下降。模型错误依赖、工具误选和费用表现仍须真实语义样本验证，不能靠单元测试数量或DAG合法性宣布问题根治。

真实入口采用原PromptBuilder完整工具说明、真实本地RLS消息、实际prepare_chat_stream/Gateway/WebSocket sink，供应商与WebSocket外部传输用可控替身。问候/原图分析在provider结束前发送正文且无知识快照；模糊创作保持原先审策略，首块不可见、审核后交付，没有自动检索。两种路径均只打开一次主模型会话，原计费归属只结算一次。这证明宿主事件顺序，不是浏览器实页或真实千问耗时。

独立审查发现P2“重复缺依据反馈直接结束Actor、逻辑任务仍active”，已修为原review_model_completion收尾；实链负例验证partial与commit_ready一致。第一次补依据决定写入原安全点，暂停/恢复保留次数和上下文；取消中断审核请求，预算耗尽不新增收尾模型调用。复审P2关闭，无新高置信问题。

空可用范围仍沿旧行为None，不给这些普通请求新增审核调用；明确引用或已绑定强制依据不因此降级。是否扩展到空库模糊请求的发布前审核会改变持续费用和等待，已单独询问，尚未得到新决定，不据时间推定同意。此旧边界下不能宣称空库时所有模型私有断言都已统一拦截。

本轮没有生产写入、提交部署、付费模型请求或新图。生产仍为57ddc81a；新代码在原任务树，未关闭任务。后续真实语义/耗时/页面验收须复用原素材和成果，先报价获得对应预算，不把脚本模型或测试数量代替真实验收。


## 386 有条件并行预取设计草案（尚未实施）

用户继续提出“提前检索，主模型按需采用并选择片段/深读”。这是在385按需执行基础上的候选优化，不代表已实现、不替代尚待决定的空库审核边界。本文数目是初始上限建议，不是性能保证；正式参数需用实际负载与命中证据验证。

### 触发与判断

首版仅在消息已受理、Actor持有有效执行权、ContextAnchor和权限范围已绑定后开始。不要默认在打字时上传草稿。输入中预取另有草稿传输、输入法组合、输入变化、成本和同意设置问题，本轮不实施。

程序可以用明确的服务器事实触发：用户持久化知识引用；当前已核对任务中就绪的知识依赖；同一目标/要求版本下已有合法查询可复用。普通问候、仅素材创作不预取；“主图/详情页”等商品词不构成知识依赖。不明确时仍由主模型正常处理并按需使用知识工具，不额外加固定分类模型。权限允许、预取值得做和答案必须审核是三项独立判断。

### 与主执行并行

从现有Actor/PreparedChatStream生命周期挂载一个有界可取消的候选准备任务，主模型不await它。每次输入/要求版本最多一项预取；共享连接池或容量忙时跳过预取，正式读取优先。不新增业务任务队列、顶层编排器或自动续接链。模型调用原knowledge_discover/search/read时，消费点查找匹配的候选Future：已就绪且有效则复用，未就绪则按该步骤真正需要与剩余预算决定短等/走原读取，不让不相关步骤等待。不把结果中途塞进已发出的模型推理请求，使用原工具结果或下一轮上下文边界交接。

### 候选与正式来源

后台候选结果只进当前请求的暂存区，不写实际读取凭据、不修改任务要求、不绑定为handler._knowledge_run、不记为用户已读/模型已用，也不能污染后续恢复的正式快照。资料选用时才通过原KnowledgeRun冻结/恢复和真实读取流程核对来源，再写原凭据与检查点。

复用现有repository/RLS、排序与目录检索原语，不新建搜索索引。retrieval.search_nodes当前会query_embedding且枚举最多10001对象；answer_plan.collect还会做正式读取/写检索状态。因此不能直接调用它们作为后台低成本候选。需提取有界只读候选查询/内容加载部分，显式禁止预取调用embedding、生成、OCR、抓取或其他副作用；第一版只利用已存索引/目录/原文片段。初始可限制3–5候选与总字符/返回字节预算，达到上限只返回partial候选，不能宣称整库缺失。若之后启用新付费检索，必须进入现有预算预留和计量，验收先报价确认。

候选每项包含来源身份、固定版本/内容hash、必要范围、原文位置/偏移及是否截断；摘要/索引词只做导航，不能伪装原文。读取缓存不直接return：必须经过原授权、快照版本、适用规则与读取凭据流程。允许把“加载正文”替换为经验证一致的缓存字节，不能跳过原检查。片段充分时可据此核验；缺必要条件、否定、例外、祖先规则或有冲突时定向展开，不默认读整库。

### 身份、缓存、失效与恢复

首版请求内缓存，键至少包含actor/org、任务/输入消息、要求版本、原查询与相关输入/附件身份、知识范围及来源版本，不能只按query或会话缓存。源文件用稳定资源身份/hash，不用会过期的签名URL作唯一身份。每次正式消费都重新做实时权限检查；TTL或权限指纹不能代替撤权检查。没有假定项目存在统一ACL epoch。

并发的预取和模型正式检索用同一个消费协调点认领，避免同输入同查询发两遍。真实快照仍由现有唯一输入与事务锁冻结，模型返回的范围/已读声明不能授权。若不能验证兼容，丢候选并走原路径。

用户新消息/修改要求、暂停、取消、执行权丢失和重启使未采用候选停止或失效。无法中断的线程返回后也必须核对当前owner和输入版本才能入缓存，过期结果直接丢弃。检查点只保存正式采用来源和原任务状态，不因未采用缓存丢失重跑已完成业务。重启无缓存时回退原按需读取；不重新生图或重发写操作。

### 展示、费用和验收

后台猜测命中不单独刷“知识已核验”或“已读取”卡片；真正采用、读取和审核沿原工具状态显示。预取没结果/失败只代表候选缺失，不能结束整个任务；对确需来源的结论仍须补依据或明确缺口。原保守审核不因预取成功/失败而豁免，普通正文也不因存在一份未采用候选而被暂扣。

验收覆盖：无需知识且预取不触发；明确引用并行准备；模型采用缓存/不采用/未就绪；片段足够与必须补规则；并发正式检索只发一次；跨用户/组织隔离；撤权/改版本/改目标；暂停取消与迟到结果；恢复有正式快照但无候选；空结果和检索故障；零新embedding/生成调用；保留原Skill、成果复用、ERP与写操作安全边界。

测量主模型启动、首次正文、真正需要知识时等待、总耗时、命中采用率、废弃率、查询数量、数据库扫描/容量和费用。使用有无预取的同源可比样本；先做免费本地顺序/故障/并发验证，真实模型与页面性能另报价，不以单次局部毫秒数或模型接口首字冒充完整收益。预取可能浪费资源，未证明收益前不全量开启。


## 387 候选内容筛选与模型协作细化（设计草案，未实施）

目标是“补当前任务缺的资料”，不是将所有相似文本塞给模型，也不把知识检索当作唯一信息来源。

1. 主模型结合原请求、手选方法、历史、附件、已有成果和工具说明，区分最终交付、已知输入、待补事实与必须遵守的约束。商品外观来自用户图片；已确认提示词/成图来自原成果；内部制度来自有权限知识；实时订单库存来自原ERP Agent；外部时效信息走已授权联网工具。找到资料不授权生图/写操作，不替换用户手选方法。
2. 候选先做访问范围、显式引用、保存版本和真实来源身份检查。删除、撤权、越界候选不能交模型再决定是否有权看。真实性/适用性未知与确定不适用分开：某平台专属规则不套另一平台；未写平台不能直接判成通用，也不能一律剔除。商品专有事实需要对应型号/SKU证据；公司通用视觉规范是否适用要按其原文范围，而非要求每条规范都出现商品SKU。
3. 原文召回与排序保留标题、路径、关键词/同义表达及正常已授权语义检索能力；第一版免费预取只用已有目录/文本索引，不偷偷新增query_embedding调用。按任务子问题分别保留少量候选，不能让一个子问题的高分来源占满全部候选；相似度不是正确性、权限或适用性的证明。不为每个候选固定调用评审模型。
4. 保留必要上下文：相关主语、条件、时间、否定、例外、适用规则与相互引用；预算不足时标记不完整并给继续读取入口，不能截断后装成完整条款。正式原文与经验、生成摘要、目录分开，更新时间不能单独证明哪一版生效。真实冲突保留，不按最高相似分静默选一方。
5. 候选包至少包含title/path、来源身份与version/hash、相关原文片段/原文位置、它对应的当前信息缺口、已知适用范围、读取/完整性/截断状态及原工具可继续读取入口。预取缓存内来源ID不能直接作为模型工具句柄；采用时经原快照与权限检查映射为合法root/item handles。不让模型伪造已读、支持或权限标记。
6. 搜索摘录默认只用于定位。模型选择采用后，沿原read流程正式读取/登记：可以复用已核对版本的缓存字节，但授权、适用规则和读取凭据不能省略。已正式读取的片段足以支撑当前结论才可作为依据；缺条件/例外时定向补读，而不是每次整库遍历。给模型的资料始终是数据，不能替换宿主指令、手选Skill或审批/计费限制。
7. 正常循环为：模型判断下一步 → 按需请求已有知识工具 → 系统消费可用候选并正式核对 → 工具结果进入下一轮 → 模型选择使用/丢弃/定向深读/说明缺口 → 原成果与答案审核交付。没有中途向已发模型请求注入资料的假设。检索无结果不意味着整库不存在资料，也不阻塞无依赖工作。
