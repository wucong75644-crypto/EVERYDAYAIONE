# 异步任务占位消息原位更新

## 1. 目标

同一对话内并发提交图片、视频、音频等异步任务时，任务终态必须按
`assistant_message_id` 更新自己的占位消息，并保留发送时的位置。任务完成、失败、
取消或部分完成的先后顺序不得改变对话展示顺序，也不得清除同一对话中的其他文字流。

## 2. 现有职责边界

- 后端 `tasks.placeholder_message_id` 是任务结果与占位消息的稳定身份绑定。
- `streamingMessages: Map<conversationId, messageId>` 只表示每个对话当前的文字流。
- `tasks: Map<taskId, TaskState>` 独立追踪多个媒体任务。
- `optimisticMessages` 保存尚未完全由持久化消息替代的占位消息。

媒体任务不得把对话级 `streamingMessages` 当作任务集合。

## 3. 根因

旧 `completeStreamingWithMessage` 使用对话当前的 `streamingId` 删除占位消息，再把
完成消息追加到数组尾部。第二个任务覆盖同一对话的 streaming 映射后，第一个任务的
响应会误删第二个占位符。WebSocket 终态还会无条件清除整个对话的文字流；持久化结果
按完成顺序追加，而统一消息视图仅在存在新乐观消息时排序，最终形成完成时间顺序。

## 4. 修复约束

1. 占位消息只按传入的 `message.id` 查找并在原数组索引替换。
2. 替换保留原占位消息的 `created_at`，并清理同 ID 的异常重复项。
3. 只有终态消息 ID 等于当前文字流 ID 时，才能清除文字流及其派生 UI 状态。
4. 完成和失败事件不得终止无关文字流。
5. 统一消息视图始终按稳定的 `created_at` 排序；相同时间仍保持用户消息优先规则。
6. 图片部分完成继续使用现有 `message_id + image_index` 精确更新。

## 5. 兼容与失败行为

- 不修改 API、WebSocket 协议、数据库或后端任务回写。
- 普通文字流、停止、思考、工具步骤沿用原对话级 streaming 语义。
- 智能路由从文字转媒体时，只有同 ID 的原文字占位符会转换并结束其文字流。
- 找不到目标占位符时允许按原有恢复语义追加完整消息，随后由稳定排序确定位置。
- 媒体任务失败只更新自己的消息和 task，不影响并行任务或文字流。

## 6. 验证

- 同一对话 A、B 两个占位符，B 为当前文字流映射时，A 完成仍原位替换且 B 保留。
- 持久化结果按 B、A 完成顺序写入时，展示仍为 A、B 发送顺序。
- 媒体任务完成或失败时，无关文字流不被清除。
- 原文字流完成时仍清除 streaming、思考、步骤提示和建议状态。
- 覆盖图片/视频混合、部分图片结果、恢复、重试、取消和前端类型构建。

## 7. 回滚

本变更仅涉及前端状态投影。回滚对应前端提交即可，不涉及数据回滚；后端保存的稳定
消息 ID 与原始 `created_at` 不受影响。
