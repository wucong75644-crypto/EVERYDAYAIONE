# EVERYDAYAI：从聊天创建 Skill

状态：个人、组织和平台三种所有权及审核流程已在任务工作树实现，尚未部署。生产部署仍须用户明确说“提交部署”。

## 用户流程

1. 用户明确要求 AI 将聊天中打磨出的可复用方法整理成 Skill。AI 调用 `prepare_skill_draft`，只生成聊天内候选卡片，不保存 Skill、不发布、不更改权限。
2. 候选展示名称、用途和完整正文。用户选择保存范围并确认；确认前不会创建 Skill。默认选择个人范围。
3. 用户选个人范围时，Skill 立即发布到个人目录，仅本人可见、选择和绑定。用户选组织范围时，系统创建组织待审核内容，由组织管理员走既有审核和发布流程。用户选平台范围时，先建立平台申请，只有平台超级管理员审核通过后才发布。
4. 刷新或重试时，卡片从服务端恢复真实状态。同一候选重复确认返回同一业务结果，不重复创建或发布。取消、拒绝和反馈均保留审计。

聊天正文、上传文件、网页、工具结果和模型输出都不构成发布授权。只有认证用户在候选卡片中提交的范围选择和确认才构成请求；平台发布仍必须由超级管理员审核。模型不能选择或扩大权限。

## 权限和管理设置

个人 Skill 以用户 ID 作为所有者边界：目录查询、正文读取、修改、删除、版本发布、解析和会话固定均按当前用户隔离。用户没有组织上下文时也能访问自己的 Skill；在组织会话中，个人 Skill 仍只对创建者可用。组织管理员不会因管理身份而获得他人的个人 Skill 正文。

组织成员必须处于活跃状态，才能在当前组织会话创建候选或申请组织范围。候选确认时会再次读取用户、会话、组织、成员和策略状态。组织管理员可在管理后台的“企业管理 → Skill 权限”编辑：

| 开关 | 作用 |
| --- | --- |
| 允许成员和 AI 整理 Skill | 控制本组织聊天中的 Skill 候选工具。关闭后仍可使用个人 Skill 管理页，不影响已经发布的 Skill。 |
| 允许申请发布到组织 | 控制成员是否可在候选卡片选择组织范围；申请仍需组织管理员审核发布。 |
| 允许申请发布到平台 | 控制本组织成员是否可提交平台申请；平台审核仍仅由超级管理员完成。 |

设置保存在组织已有 `features` JSON 中。旧组织缺少这几个字段时按开启处理，以兼容现有体验；服务端环境开关 `skill_catalog_enabled` 和 `skill_chat_creation_enabled` 仍是总开关。独立个人会话没有组织策略，个人创建默认可用，平台申请仍进入平台审核队列。

后台“我的 Skill”分区提供当前用户自己的创建、编辑、发布、读取历史与安全删除。个人发布不进入组织或平台目录，也不会自动启用或固定。

## 数据、接口与审计

迁移 `267_skill_personal_ownership.sql` 为 Skill 包增加 `owner_user_id` 与 `personal/{user_id}/{skill_key}/{revision}/SKILL.md` 存储命名空间；增加私有聊天提案表 `skill_chat_proposals`，并更新 RLS、会话绑定可空组织范围及个人绑定约束。未改写历史迁移。

提案记录候选正文和规范化内容 SHA-256，用于冻结和核验用户确认的确切版本；来源只记录助手/用户消息 ID、角色和内容哈希，不复制整段聊天。审计还记录来源范围、用户选定的所有权范围、确认人和时间、平台审核人/结论/原因，以及用户反馈和时间。候选默认 24 小时过期。

主要端点：

- `GET /skills/authoring/proposals/chat/{id}`：仅提案创建者可查看候选和当前可用范围。
- `POST /skills/authoring/proposals/chat/{id}/confirm`：传入版本、内容哈希与用户选择的范围；服务端在业务事务内重查权限并幂等提交。
- `POST /skills/authoring/proposals/chat/{id}/cancel`、`PUT .../feedback`：取消和收集帮助度反馈。
- `GET /skills/admin/platform/chat-proposals`、`POST .../{id}/decision`：仅活跃超级管理员可处理平台申请。
- `PATCH /org/{org_id}/skill-settings`：仅组织 owner/admin 可编辑 AI 创建和申请范围开关。
- `/skills/admin/personal/...`：当前用户个人 Skill 管理；既有组织 Skill 管理与审核路由保持原流程。

## 运行时边界

`SkillResolver` 只返回当前用户、组织、会话模式和功能权限允许的 Skill。个人 Skill 可在组织会话或独立个人会话中手动选择/固定；持久绑定同时保留会话组织边界。绑定写入服务和数据库触发器都会再次核验所有者、发布版本及会话权限。

个人发布沿用现有 NAS 原子写入、不可变 revision、内容哈希、审计和生命周期校验；个人 Skill 不创建组织 assignment。组织和平台 Skill 继续要求相应范围授权。提案卡片只是建议与确认界面，不注入正文、不改变工具权限、不触发自动激活或会话固定。

## 定向验收

- 个人创建后，只能由创建者读取、编辑、解析、绑定和删除；另一个用户无法从目录或包 ID 读取。
- 普通组织成员可准备个人候选；组织发布只有在活跃成员身份和组织开关允许时可选，并且生成待审核内容而非直接发布。
- 平台申请没有直接发布权限；普通用户确认后只能进入队列，平台角色失效或非超级管理员无法处理。
- 用户候选版本/哈希不匹配、会话所有者不符、成员撤权、组织停用或范围策略关闭时，服务端拒绝确认。
- 两个审核范围开关关闭时，候选卡片相应选项不可选；伪造请求仍由服务端拒绝。组织 AI 创建总开关关闭时，模型工具不再展示且后端拒绝。
- 独立个人会话和组织会话都可使用个人 Skill；个人绑定只能固定已发布且属于当前用户的版本。
- 重复确认、取消、平台拒绝/通过和反馈记录均保持真实状态；关闭全局 Skill 开关后创建接口不可用。

## 生产验证与回滚

部署后由用户使用普通成员账号走一次个人创建与第二用户隔离验证；再分别启用/关闭组织创建开关，验证工具入口与确认接口；尝试组织申请并由管理员走现有审核发布；尝试平台申请并用超级管理员审核。确认 Skill 正文只落在对应所有者路径，个人版本不会出现在其他账号或组织目录。

回滚优先关闭全局聊天创建开关或组织 Skill 权限开关，停止新提案并保留既有数据和审计。代码回退到本任务起点 `9e4a4fa06ceb5de6f225d353e76bf65593fbbd6c` 时保留新增列、提案表、个人文件和审计；不直接删除迁移数据。若要撤除迁移，先导出/处置个人 Skill 与提案，再单独准备并审核反向迁移。
