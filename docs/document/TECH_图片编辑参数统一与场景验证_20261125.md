# 图片编辑参数统一与场景验证（2026-11-25）

## 范围与验收依据

用户最初授权统一编辑参数，保留上一轮结果、指定历史图片、原始上传图片、多图用途及现有恢复机制，同时对齐校验与纠错；当时未授权部署。本任务基于 `baf6f68d` 的独立工作树。2026-11-26用户进一步确认模型使用短引用，并授权测试通过后提交部署，最新边界见[短引用与新旧合同兼容](TECH_模型图片短引用与新旧合同兼容_20261126.md)。

原故障：模型同时填写相同的 `edit_instruction` 和 `previous_result_edit`，公开 Schema 可通过，后台按私有严格类型拒绝，随后模型再试成功。验收要求为新请求只看到一份编辑合同；旧等价调用可受控兼容；冲突调用不派发；实际底图及参考图、规格、恢复后的执行与扣费保持一致。

## 现行合同与职责

新窗口的图片编辑公开参数为必填 `image_ref`、`edit_instruction`，可选 `materials`（最多15个其他参考素材，总计最多16图）。短引用由宿主按当前输入快照还原为 `source_message_id`、`source_content_index` 后进入原生合同；旧检查点仍按原有UUID或旧目录引用恢复。不再公开 `previous_result_edit`，也不再按单图/多图把编辑正文切换为 `draft.body`。创作新图的 `draft`、执行已有稿件的 `content_source`、服务器策划的 `plan_source` 保留各自用途。

- 主模型解释用户指代，选取系统实际提供的图片引用，填写完整修改/保留要求；不构造文件路径或伪造 ID。
- 后台的上一轮解析器仍按原任务唯一回执定位唯一已完成的实际输出；只将其引用作为候选提供给模型，不用“数据库最新图”覆盖明确选择。多结果、未完成或不唯一时没有默认候选。
- 当前附件的语义底图与明确引用必须一致。其他主体/风格参考用 `materials` 保留 `input` 用途，分析资料仍可用 `analysis`。
- 原生解析器继续执行会话/组织范围、历史 revision、文件版本及字节指纹核验；模型选图不是授予访问权限。
- 当前多附件保留原上传顺序，明确标注实际供应商输入编号与编辑底图位置。图二为底图时不能一律把图二调到首位。已有真实出图记录显示重排影响保真，因此不在本任务恢复已被否证的顺序调整。
- 明确的输出比例/分辨率从既有冻结语义投影带入执行稿；缺省规格及底图画布继承继续由现有原生规格解析处理，不让模型重复填写规格字段。

界面原有引用附件字段保持兼容。本任务不新增编辑按钮或界面选择协议；“图片被引用”不自动代表其被用户指定为编辑底图。

## 兼容、纠错与恢复

`PreviousResultEdit` 只作旧调用的私有接收类型，不进入新模型工具定义。只有本轮允许编辑的入口才接收这种旧格式：

1. 仅旧字段：按相关任务回执解析唯一已完成输出，转换为统一编辑输入。
2. 同时有两个正文且逐字相同：保留原文，转换一次；不重置纠错预算。
3. 同时有明确底图：必须完整且与该回执输出一致。
4. 两个正文不同、引用缺一半、未知字段、明确底图与上一轮输出冲突：不派发，返回冲突及当前统一字段说明；不静默任选。

公开参数、模型参数接收类型与执行转换共用定义。纠错消息仍返回实际字段问题、`not_dispatched`、当前允许字段及统一编辑指南；重新生成旧稿的纠错不再引导模型填写旧快捷字段。图片来源/宿主绑定错误保留原恢复或停止策略。

原始模型参数不原地改写；记录的参数摘要继续绑定原始调用。已准备检查点沿用原始保存稿、原生配方及字节指纹，恢复时不重新选图，受理后不重发、不重复计费。旧 `draft` 已准备检查点仍走既有恢复路径，新编辑请求不再公开该形式。

## 验证

正式测试位于 `backend/tests/test_unified_image_edit.py`、更新后的模型传输合同、交付回归和 `test_content_objects_postgres.py`，并复用现有来源、尺寸、绑定、语义及 Skill 回归。

重点断言包括：

- 当前编辑工具在 Chat/Responses 投影中保持同一合同，旧快捷字段不公开；允许字段与接收类型一致。
- 单图、历史成图、历史原始上传、上一轮输出，均保留选中的实际引用与编辑正文。
- 多图主体/风格输入保留；图一/图二分别作底图时，供应商输入仍保持原顺序，正文正确标注底图位置。
- 等价旧字段混填，以及等价混填的受理前/受理后崩溃恢复，只得到一次实际受理和一次对应积分流水。
- 正文冲突、底图冲突、缺字段和未知字段在派发前拒绝；没有保存伪稿或原生副作用。
- 不可用/越权/变更/历史边界等情况沿用原生拒绝机制，不替换为其他图片。
- 按旧稿再生成与修改成图仍分开，明确尺寸不因统一接口丢失。

## 发布与回滚

单独的图片编辑参数统一不需要数据库或前端协议迁移。同一任务后续的多任务承接优化新增迁移384，见[实际实现和兼容边界](TECH_多任务对话承接与图片交付优化方案_20261125.md)。新请求绑定明确目标后，旧 previous_result_edit 不能以“默认上一轮图”覆盖该目标，须提供一致的真实引用；部署前的旧检查点仍保留原私有兼容。后续发布仍须用户明确授权并走本地受控入口。若需回滚，应整体回滚工具定义、接收类型及执行转换，不能只回滚其中一层；已受理任务及其原始检查点继续由原生账本核对，不能重新选择底图或重复提交。
