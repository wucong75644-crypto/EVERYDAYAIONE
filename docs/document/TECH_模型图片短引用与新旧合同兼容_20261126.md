# 模型图片短引用与新旧合同兼容

日期：2026-11-26。当前任务继续基于ab38d5b0开发。用户确认“模型用短引用、后台用真实ID”，并授权三项阻断修复、兼容验证及测试通过后提交部署。此前只修旧路径、保留新模型填写UUID的研究建议已由本次确认替代。

## 选择与存储

新模型窗口在既有_request_context_v1快照标记image_reference_version=1。旧检查点没有该标记，继续原来的UUID或旧目录短索引合同。恢复已保存窗口保留原快照及词汇，不根据当前开关或新查询重建编号。

新增image_reference_catalog.py负责模型边界投影，不新建数据库或修改原生工具的身份类型：

- 每个当前可见图片得到img_<快照摘要>_<序号>形式的短引用。摘要来自当前输入快照和已送达补充输入；新输入、图片变化、补充修改会改变标记，旧短号不套用新表。目录保留真实用户轮次、上传/引用/成图及素材名称。
- 模型编辑用image_ref＋edit_instruction；图片target用kind=image＋basis＋image_ref；素材reference、view_image和show_image也用image_ref。真实消息ID仍用于读取整条需求或声明保存稿作者，不能与图片定位混为一谈。
- 模型选中后，宿主将短引用还原为原消息ID/图片位置，或已核验追加附件的resource_ref；随后继续现有Target、保存稿版本、租户/会话、冻结输入、批准和幂等校验。短引用本身不是执行授权。
- 新模型路由的target.image_ref、materials[].reference.image_ref与可选canvas_ref共用同一快照映射，不再另用material_index或image:n编号表。canvas_ref只支持原来可用的当前上传/追加画布，历史编辑直接由目标底图绑定，不能把历史图伪装成本条附件。旧窗口的material_index/canvas合同仍由原宿主映射完成。签名引用不放进新短目录，已送达追加图片可通过短引用用于draft素材；追加图片无消息定位时不能伪装成message_id编辑。
- Native ContentRecord、TaskState、供应商请求、图片交付和历史来源继续存真实身份。用户图片消息不改写为短号。旧canonical调用可继续恢复，新模型只公布短引用图片合同。

模型边界仅投影结构化事实、工具定义、工具返回和工具参数历史；用户文字和提示词body不按字符串替换。不增加用户关键词路由。未知或过期引用、短号与另一真实身份混用时整批不派发，返回可纠正错误。原始JSON重复键仍由严格解析器拒绝，不能由反序列化再序列化悄悄丢掉。

## 三项发布阻断

1. 旧classify_workflow的image_target_references仅返回短索引，原UUID映射留宿主，恢复旧输入合同。新短窗口的路由与主模型采用同一ImageReferences投影；短目录中的成图不再假定仍带source_message_id。
2. 普通图片write/write_then_submit_images不消费策划器retry/reuse控制，明确规范化new/0。测试同步核验模式、复用层级且无plan_id/source_task_id；非法类型、未知字段及策划冲突仍拒绝，不赋予恢复或再次收费授权。
3. 任务启动夹具明确模拟read_agent_request_context，未知RPC仍失败。新增缺少上下文、输入消息不符、版本无效时执行入口停止；验证旧UUID窗口和新短窗口恢复均保留原快照，新窗口才启用短合同。

另外，发现保存提案被短引用/目标预检拒绝后仍处于proposed，主循环反复恢复同一失败调用，未再次调用模型纠错。现在沿用原finish_response记录rejected，错误和拒绝状态在同一安全点保存，下一轮允许模型根据工具结果纠正，不能把此循环错误说成“模型反复填写同样参数”。两个拒绝路径均有回归，原幂等和原生业务恢复不改。

新短窗口的路由只对IMAGE_WORKFLOW_ARGUMENTS_INVALID提供一次只读Schema纠正，返回字段路径并带同一原始输入与候选；最多两次路由调用。旧窗口仍单次；真实歧义、错对象、权限拒绝和供应商业务任务不在此自动重试范围内。媒体等待字段明确非空工具名，不能通过丢弃等待条件修复参数。

实际图片交付的语义动作增加明确模型说明：未要求等待时不能只写提示词或保存后结束；可直接用编辑/draft，或保存时显式continue_execution=true再提交。仍遵守真实用户等待条件，不根据文字猜批准，不自动执行未选历史稿。
