# UI 设计：企业管理整合组织管理

> 版本：V1.0 | 状态：已确认方向 | 日期：2026-07-27
> 依据：[REQ_企业管理整合组织管理.md](./REQ_企业管理整合组织管理.md)

## 一、设计意图

让企业管理员在一个稳定的“企业管理”工作区内完成组织治理，消除成员相关页面的重复，
同时保持企业配置与组织业务数据之间清楚的职责边界。

## 二、信息架构

```text
管理后台
└─ 企业管理
   ├─ 组织管理
   │  ├─ 成员与任职
   │  └─ 群聊管理
   ├─ 企业信息
   ├─ 企业微信
   ├─ ERP 凭证
   └─ AI 配置
```

- “企业管理”继续作为管理后台一级 Tab。
- 企业管理内部使用板块导航；“组织管理”是其中一个板块。
- 进入组织管理后，使用“成员与任职 / 群聊管理”二级切换。
- 不再使用独立 Modal 承载组织管理，避免与整页管理后台形成两种交互范式。

## 三、成员与任职

### 3.1 主视图

统一列表以全部有效企业成员为基础，每名成员只出现一次，至少展示：

| 信息 | 表达 |
|------|------|
| 成员 | 头像、企业内显示名 |
| 企业角色 | 创建者、管理员或成员 |
| 部门与职位 | 部门、标准职位、可选职务名称 |
| 数据范围 | 全公司、本部门或仅自己 |
| 企微状态 | 已关联或未关联 |
| 操作 | 编辑成员与任职 |

列表顶部提供成员总数、“邀请成员”主操作和企微关联状态筛选。筛选只改变当前列表结果，
不进入另一套“企微员工”页面。

### 3.2 编辑行为

点击成员行或“编辑”进入该成员的编辑界面，在同一上下文内组织以下能力：

- 企业内显示名；
- 企业角色；
- 部门、职位和职务名称；
- 数据范围。

保存期间禁用重复提交。成功后关闭编辑态并刷新该成员的权威数据；失败时保留用户输入，
在编辑区域内显示可恢复的错误，不以静默失败结束。

邀请成员仍是独立操作，因为目标用户尚未进入成员列表。邀请成功后给出明确反馈；
成员接受邀请并成为有效成员后才出现在统一列表。

### 3.3 状态

- 加载：列表区域显示加载状态，保留企业管理导航。
- 空状态：提示企业暂无有效成员，并提供邀请入口。
- 筛选为空：说明当前筛选没有匹配项，并允许清除筛选。
- 加载失败：显示错误和“重试”，不得按空列表处理。
- 无企微关联：只显示状态，不阻止成员角色或任职管理。

## 四、群聊管理

群聊管理保持现有业务语义：展示机器人已收集的企业群聊、企微 chatid、最后活跃时间、
消息数量和管理员维护的群名。

- 群名为空时显示“未命名”，并提供编辑入口。
- 列表为空时说明群聊需要在群内触发机器人后才会被收集。
- 更新失败时保留编辑内容并允许重试。
- 群聊管理不展示或修改 Agent ID、Secret 等接入凭证。

## 五、企业微信配置边界

“企业微信”板块只负责企业微信应用或机器人的接入状态、凭证配置和连接测试。
“组织管理 → 群聊管理”只负责接入后产生的群聊业务数据。

两者可以通过说明文案建立关系，但不互相嵌套，也不在群聊页重复凭证表单。

## 六、入口与返回

- 聊天侧边栏保留“管理后台”入口。
- 聊天顶部独立“组织管理”图标移除，减少重复入口。
- 访问旧 `/settings/organization` 时，跳转至企业管理中的组织管理板块。
- 从管理后台返回时沿用现有整页返回行为，不再关闭组织管理 Modal。

技术阶段需要为企业管理内部板块提供可恢复的定位方式，确保旧路由跳转后直接落在
“组织管理”，但本设计不指定具体 URL 参数形式。

## 七、权限可见性

- 当前企业 `owner/admin`：可见企业管理与组织管理板块。
- 其他企业成员或无企业上下文用户：不可见组织管理入口。
- 前端可见性仅用于体验；后端继续作为最终安全边界。

当前聊天顶部入口使用 `sys.member.edit` 判断、后端却只接受 `owner/admin`，实现阶段必须
消除这一不一致，不能将前端权限判断视为扩大授权的依据。

## 八、一致性约束

- 复用管理后台现有整页布局、Tab 语言和语义颜色变量。
- 不引入新的视觉主题或独立 Modal 导航体系。
- 危险或高影响操作继续使用明确确认，不因页面合并而弱化反馈。
- 桌面端列表信息应保持可扫描；窄宽度下允许信息分行，但操作和成员身份不能被隐藏。

## 九、交互验收

1. 管理员能通过“管理后台 → 企业管理 → 组织管理”到达统一成员列表。
2. 同一成员的角色、任职和企微状态可在同一列表理解和管理。
3. “已关联企微”筛选不会切换到另一套员工页面。
4. 群聊管理和企业微信凭证配置在导航与内容上明确分离。
5. 旧组织管理地址直接落入新板块。
6. 加载、空、失败、保存中和保存失败状态均有可见反馈和恢复路径。

## 十、技术设计待决事项

- 企业管理内部板块和深度链接采用何种最小状态模型。
- 统一成员列表复用现有哪一个权威查询，以及企微状态如何合并返回。
- 现有成员、任职和企微员工组件的最小迁移与删除顺序。
- 旧路由兼容跳转和相关测试更新范围。
