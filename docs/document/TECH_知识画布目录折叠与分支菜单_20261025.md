## 项目名称一行无法删除：补齐项目级操作（未部署）

用户验收确认“主分支”指项目名称一行，而非根主题。此前实现只覆盖node目录分支，项目header缺少删除入口，属于范围遗漏；不是根节点禁止删除。补充真实数据库根主题及后代删除/撤销/重做回归，通过。

项目header悬停/聚焦显示删除图标，右键提供“删除项目及全部分支”；操作前确认项目名称、全部分支影响与可撤销。仅project+manager提供可用入口，个人和团队系统空间不提供删除。操作直接绑定点击项目的id/revision，不依赖旧的画布选择或当前激活项目。

增加严格delete_project命令和前向332迁移，Repository分派到kb_delete_project。数据库实时校验actor/org、manage权限、空间类型、版本及幂等回执；按actor历史锁→container行锁顺序执行，锁后重验权限。一次事务将容器和其可见主题undo_hidden，保留全部不可变正文/附件版本、成员及原始文件；记录同一画布历史。旧的已隐藏节点不随项目恢复意外出现。新知识快照不能引用已移除项目，进行中整理无法发布删除前结果。

复用现有kb_canvas_state/patch/restore；给restore及history_list增加针对delete_project的管理者检查，降级为editor也不能恢复/重做项目删除。原内部函数重命名后撤销runtime直接EXECUTE，普通节点编辑撤销不受影响。仍保留现有历史版本及权限语义，不物理清除原件。回滚应用可隐藏入口，不回退已应用迁移或删除数据。
