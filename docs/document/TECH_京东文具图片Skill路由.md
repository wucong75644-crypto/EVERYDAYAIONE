# 京东文具图片 Skill 与页面路由

## 需求

用户要求在现有主图/详情页面选择京东后，后台默认使用独立京东三阶段Skill。输入由客户上传，不预设品类、部件或固定卖点。用户两份参考形成项目制作规范：摄影主导、干净真实、装饰克制；根据品图、信任图、卖点图、场景图、白底图选择任务，主图组包含白底图；保留事实来源、商品保真与整页连续性。尺寸、字号、占比和优化经验不宣称为已核验官方规则。

## 路由与兼容

页面已有目标平台jd选项，保存接口传递该值，无需新建选择器。DetailPageGeneration.start根据冻结platform为新任务选择jd.v1，将资源哈希及prompt_profile保存到现有prompt_versions JSON，无需迁移。

DetailPageWorker.run通过plan_resources加载保存版本，在模型IO前校验适用平台和资源哈希；不静默回退。旧任务无prompt_profile时继续原v3/v4资源，避免重试改变方法。其他平台与auto不变；修改平台后新发起任务才采用对应资源。

## 独立资源

backend/config/ecommerce_planner_prompts/jd-v1为随项目发布的完整三阶段资源包，继承v4全部专业正文并嵌入各阶段京东判断，不依赖服务器的个人Skill目录。原v3/v4不修改。个人jd-stationery-images同步相同阶段内容。

第一阶段识别当前商品，建立事实、收益和适用证据；第二阶段确定摄影、背景、字体、装饰和照明；第三阶段分别规划主图任务与详情连续阅读。白底图作为主图组独立任务保留，但不固定首图；实际白底图无新增文案标识，保留商品原印刷。首图可采用符合当前商品与用户要求的场景和有据文案。至少三张卖点仅在数量和证据允许时适用，不额外增图。纯详情不强制白底首屏。历史品类案例仅为非绑定示例。

既有输出协议、参考图顺序、格式恢复、编译、生图和结果资源入口保持不变。白底图作为独立结果资源，不把下载入口画进图片。没有新增模型、计费、后处理或自动视觉审查；提示词不能保证精确RGB或像素保真。

## 验证与发布边界

定向测试覆盖京东/非京东、三种页面模式、模型与固定比例、独立三阶段和schema兼容、旧任务重试、错误profile/哈希/平台及资源篡改拒绝。校验Skill格式、引用与个人/服务器阶段一致性。

未进行生产部署、付费生图或实际风格稳定性测试。发布遵循受控提交部署流程。回滚时保留已有jd.v1任务所需资源，不应仅删除资源而继续执行这些任务。

## 用户确认的场景与文案方案

三阶段共同接收商品事实、用户创作要求、京东表达原则与固定制作设置。用户指定背景风格优先，平台原则不将整组图片强制白底化；创作要求保留在raw_user_texts，不进入商品事实或新增schema字段。第一阶段区分事实与创作意图，第二阶段落实空间、承托面、材质、配色、配套道具、字体、照明及允许变化，第三阶段按图片任务输出独立完整正文。不能只复述风格词，也不预设某种风格对应固定桌面或商品品类。

品图、卖点图和场景图需要清楚的图文分工，可表达有证据的买家价值；不能一律只贴结构标签，也不能编造性能。原背景按任务保留、整理或替换，商品本体保真不变。只有实际白底图无新增文案；若唯一一张图与白底/场景同时冲突，反馈具体冲突而不是私自增图。纯详情按当前商品组织解释与连续阅读，检查所有相邻边界，不强制白底或固定章节。

本次只修改未发布的jd.v1资源与个人京东Skill，更新manifest哈希，不改变路由、数据协议、模型或计费。原电商Skill和原v4资源不改。测试中的模型回包为模拟，仅验证风格原文和专业规则实际进入三个阶段调用，不代表真实模型风格理解或实际出图已通过；后续需按确认方案展示规划后再做真实模型/图片验证。
