# 员工真实会话20组抽样验证（2026-11-22）

> 后续：同20组已补做真实模型、供应商和隔离原生链路回放，见[完整复测及逐组结论](TEST_员工20组真实模型与供应商完整复测_20261122.md)。本文件保留早期调查的历史口径。

结论：不能说“对话内聊天没有失败过”。抽取20组真实输入，每组进行两轮真实模型回放，发现了长稿件交付超时、图片问答事实错误和供应商审核拒绝。此次不是20组完整业务链全部通过的验收；电商策划后续执行和其中一组跨轮批量方案仍未取得完整闭环证据。

本轮不部署、不提交、不修改业务代码，也未向员工的真实会话发送消息或写入任务、积分、资产。读取生产数据时使用只读事务；新模型调用、素材缓存及测试状态均在本地隔离环境中。

## 数据与验证口径

- 以用户此前真实失败会话所属组织和组织所有者关系确定访问范围，排除所有者本人的会话。
- 只读检索最近活跃的180个员工会话，涉及20名员工。最后选取20组输入，覆盖10名员工；重复任务、同一输入的内部续接不另算一组，排除明显的合成验收数据。
- 近30天员工任务记录：聊天617条 completed、41条 failed、8条 cancelled、19条 paused、1条 pending；图片9469条 completed、471条 failed；视频1条 failed。任务含重试、内部续接和历史版本，不能换算成用户会话失败率，不能归因于当前未部署修改。
- 本地主验证使用真实 `qwen3.8-max`，关闭思考；从原始输入、历史模型上下文和已发布 Skill 的准确版本恢复测试资料。保留真实图片，不用虚构图片替代。
- 运行当前 `_run_loop`、Skill 快照校验、稿件处理及原生图片输入校验。模型请求逐次保留实际协议与参数；Responses 为 `reasoning.effort=none`，Chat Completions 为 `enable_thinking=false`。40轮关闭思考回放均未收到思考增量。
- 图片执行在付费派发前停止。本轮没有为20组重复购买图片，没有将“已选择工具”算成“已出图”。真实图片供应商的既有5场景闭环记录见 [前次验收](TEST_Skill真实图片供应商闭环验收_20261122.md)，不能拿它替代本次20组业务验收。
- 数据库读取和回写使用隔离测试实现，不是完整生产 Actor 数据库。部分测试需要迁移既有登记、引用来源及恢复快照；这些测试环境缺口单列，不算线上产品缺陷。

## 确认存在的问题

1. **手动 Skill 长稿件仍可能迟迟不交付。** 第09组把长文本放进 `save_task_text` 参数，首次内容出现展示结构校验错误后，再次生成整份文档。用户看到正文前，要等待长 JSON 完成且登记通过。一轮235秒未完成，另一轮177.4秒才交付。此结论不依赖被引用图片的素材数据库缺项；不能把它简单称为“思考没关”。
2. **正常回包不保证答案正确。** 第10组模型把宽窄不同的条纹答成等宽；移除历史只保留当前原图后仍这样回答。额外开启思考的对照开始区分条数和宽度，指出白色更宽，但仍不是精确测量结果。不能通过默认重新开启思考解决关闭开关的需求。
3. **供应商的实际拒绝原因被泛化。** 第20组供应商明确返回输入图片内容检查拒绝，而当前 Responses 解析层抛出通用 `DashScope Responses request failed`，上层仅得到通用错误。应改善错误原因的保留与展示；不得绕过供应商审核，也不能承诺改代码就能让同一图片通过。

## 排除的测试假象与未完成项

- 第05组前几轮 `IMAGE_QUOTED_SOURCE_CHANGED` 来自测试快照未包含全部资产、来源任务，最初用了错误的资产存储键查询方式。补齐后，**完全相同的首个调用参数不改动即可通过**。没有因此改动生产校验或降低断言。
- 第08组先后暴露测试数据库缺少 `neq`、本地恢复辅助函数未恢复 Skill 阶段与持久化映射等问题。这些不是线上代码抛出的同类错误，不能拿它们证明线上批量生图坏了。此组仍需独立数据库闭环，不能以 mock 的成功结果冒充。
- 6组进入电商策划工具的样本，仅验证了模型路由/工具选择；没有验证内部 Agent 的最终正文、成图、积分、权限 RPC、页面落库及下一轮引用。
- 本次未对员工线上会话点击、发送或修改。因此没有20组线上前端端到端成功的证据，也没有用重复提交去制造批量成图。
- 固定真实模型的回放没有接入生产智能路由的自动换模策略；供应商拒绝/超时是此次固定模型测试结果，不等同于生产完成全部重试后的用户失败率。

## 优化方向与后续验证

- 对已经校验的文字创作方法，研究沿用现有可见正文自动登记链路，减少整篇正文转 JSON 再重写的负担；必须保留方法展示约束、原文、编号、素材、权限与恢复的校验，不能直接取消结构检查。
- 将图片问答中的数量、面积和宽度明确区分。可测量的需求应使用真实测量证据；不确定时不要让模型给出确定倍数。不能以固定提示词保证所有视觉判断正确。
- 为 Responses 失败事件保留供应商错误类别、可展示原因和关联标识，并补事件解析、前端展示及历史恢复测试；明确供应商内容拒绝与本地参数、权限、积分错误的区别。
- 在隔离真实 Actor 数据库中补齐第08组及6组电商策划后续链路；执行原文哈希、编号、素材来源、尺寸、权限、恢复、页面正文和下一轮引用断言。完成这些之前不发布“20组全部通过”的结论。
