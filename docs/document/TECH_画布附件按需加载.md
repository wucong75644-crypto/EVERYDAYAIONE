# 画布附件按需加载（实现与验证记录）

用户确认：画布先显示轻量信息，图片缩略图、视频点击播放后分段读取，控制并发并释放离屏资源；不修改导图原文、层级和 AI 查询。

现状：所有图片和视频均读取整文件 Blob，媒体 preload 设置在完整下载之后；图片全部挂载即请求，附件观察器只进入不退出，响应禁止缓存。

实施：保留既有受权下载接口；新增受权缩略图（最多 512px，私有缓存、版本校验、每次权限校验），视频启播通过当前 Bearer 身份申请单一绑定/版本的短期 HttpOnly 路径 Cookie，流请求逐次校验签名、时效和当前权限，支持 Range/206/416；不把登录 Token 放入 URL。播放器使用固定地址并在使用期间续期，关闭/离屏卸载暂停并清理 src。同一画布一次只保留一个活动播放器。

前端：可见区域附近才加载缩略图；缩略图请求队列最多 4 个，取消等待/离屏请求；缓存按认证头和空间隔离并重新校验权限，不持久化授权结果。文档仍只在点击后读取并预览，关闭释放 Blob。

验证：请求数与并发上限、离屏取消、视频未点击零内容请求、分段边界、撤权与跨对象/版本/身份拒绝、文件校验、条件缓存、播放释放；真实培训文件和本地合成媒体复验。无数据库迁移；回滚应用代码即可，原件不变。实际限制保持单文件 20MB、MP4 与浏览器编解码支持。


实际边界：视频使用文件名与播放占位按钮，不在进入画布时抽帧或下载原件；外部视频链接的原平台打开逻辑保持不变。文件列表图片也复用缩略图队列；文档在用户点击后仍使用原有整文件预览器。原图点击放大时才读取，关闭后释放。浏览器缩略图私有缓存采用每次重新验证，服务端派生缓存最多 32 张且不超过 8MiB；文件完整性指纹缓存最多 128 个，不缓存授权结果。视频首次打开在服务端校验原件完整性，客户端按 Range 读取；每次请求仍重新核验当前账号、组织与节点权限。

验证结果（2026-10-28）：
- 前端分组定向回归 393 项通过（包括画布 339、视觉编辑 10、媒体与文件 44），类型检查、相关 ESLint 与生产构建通过；保留原有构建体积提示与测试 act 提示。
- 后端 117 项通过，包含新增 16 项分段/授权/缩略图测试、既有文件和 Xmind 导入及媒体解析回归，以及真实培训文件导入、原文/层级/21 条链接/36 张图片、重放与撤销重做验证；零 AI 派生生成。
- 真实培训文件 36 张图片：原件共 4,275,756 字节，512px 缩略图共 491,952 字节，减少约 88.5%；源文件及内容不改写。
- 本地浏览器使用真实播放器与合成 MP4 验证：刷新为零播放申请、零 video 元素；点击后 readyState=4 且播放时间推进；单播放器、离屏释放、续期地址不变和错误重试由组件测试验证。该 UI 夹具不代替生产权限验证，认证与 Range 由后端真实本地数据库测试覆盖。
- 保持现有 20MB 上传上限及 MP4 编码限制；未进行超大节点数量的整体布局压力验收，不承诺任意规模画布都不会卡顿。验证阶段无生产写入、无迁移；实际生产版本以受控发布结果为准；其他暂停修改的五个文件哈希不变。

主要实现：`media_delivery.py` 为独立附件传输模块，不改动既有 `media.py` OCR/视频分析逻辑；现有下载接口保留。回滚本次应用代码即可，缩略图为有界内存派生数据，无需回滚原件或数据库。
