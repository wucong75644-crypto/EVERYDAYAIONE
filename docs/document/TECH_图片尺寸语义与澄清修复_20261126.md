# 图片尺寸语义与澄清修复

日期：2026-11-26。状态：已在独立工作树实现和本地验证；用户已授权提交部署，进入受控发布准备，最终结果以release.sh为准。范围仅为尺寸说明、像素精度不确定的结构化处理及用户反馈；不接入严格JSON纠错、不增加模型请求、不解析用户话术关键词。

## 触发与根因

浏览器真实对话55958085-7604-4123-97bb-053bbe0077cb选择“参考图多方案提示词”后确认生成：

> 就用第一套“晨雾灯塔”这个方案，帮我生成一张图，正方形，一千像素就好。其他方案先不用。

线上候选cd3fd4bb的尺寸识别保存了aspect_ratio=1:1、width=1000、height=1000、resolution=null、approximate_pixels=null。后台将宽高视为精确像素，抛出IMAGE_EXACT_SIZE_UNSUPPORTED，未创建图片任务。错误说明还直接暴露内部指令“请告知用户”，而没有形成正常澄清。

校验模块和当时main完全相同，不能据此把问题归为上一任务改坏了尺寸函数。已证实的缺口是模型尺寸说明不够具体，以及语义精度null在exclude_none后消失，落入旧原生工具“有宽高即精确”的合同。现场只读证据/private/tmp/browser-customer-image-acceptance-20261126/audit-private.json及results.json。用户另行反馈1K可出图；本任务不把用户反馈算作代理已验证的出图结果。

## 修改

- image_size_requirements.py统一补充清晰度档位/精确像素/允许近似/需要澄清的说明，包含自然说法正反例。例子是模型语义提示，没有新增正则或用户关键词分支。
- RequestedCanvas的resolution、width、height、approximate_pixels补充含义和适用条件；路由复用同一尺寸语义说明。原生工具的分辨率/宽高字段说明同步。
- ChatImageInputResolver保留语义尺寸的三态：true允许近似、false明确精确、None未确定。未确定而有完整像素宽高时抛IMAGE_SIZE_PRECISION_UNRESOLVED，询问用户，不自动转1K、不授权派发。
- 旧原生size_requirement.width/height仍按原精确合同拦截。明确approximate_pixels=false的语义要求仍受精确尺寸保护；true继续沿用既有匹配函数和原始请求像素溯源。比例/清晰度继承不变。
- 两类尺寸拒绝在真实Chat执行循环的工具展示和终止说明中使用普通用户问题。内部AgentResult.error_message保留诊断码。仍停止自动派发，不追加纠错/付费调用、不修改其他错误处理。

无数据库迁移、前端变更或新增依赖。选图、轮次、保存正文、执行授权、额度和图片供应商调用未改。
