# F08-05 空白会话原句测试

**结果：本轮 4 次均未给文件名加空格。明确写“工作区”的 2 次均命中原文件；截图原句的 2 次未传 scope，落入空附件范围，没有找到文件。** 当前线上版本本身在这次空白上下文下就能保持原名，不能用此前旧会话失败直接推断新对话必然失败。

## 方法与边界

用户明确确认新增 4 次 DashScope 调用，额度全部使用，0 重试。核验生产发布标记及 23 份相关源文件/模板指纹为 `8428b72c0c8b36481e5fdbc3bcb3e93070c2f1f9`。本轮使用当前生产定义，未加载未提交修复候选。

每次使用独立 UUID、生产 StaticLayer/SessionStableLayer/TurnDynamicLayer/UserLayer、PromptBuilder._compose_messages 和 prepare_tool_turn，重新构建消息和 11 个生产工具。只有 1 条 user 消息、0 条 assistant/tool 历史，摘要为空、附件为空、浏览/工具发现记录为空，日期上下文重新生成。实际 HTTP 请求体与冻结消息逐字核对。

为了控制个人因素，保留原会话相同的个人事实/偏好快照，没有重跑个人记忆检索。**这是在生产运行环境内构造的新会话首轮模型调用，不是通过网页创建并持久化一个真实新会话，也未完整验证 UI/Actor 后续流程。** 因此结论覆盖“无旧聊天历史、相同个人偏好下的原句”，不宣称任意未来会话结果一致。

实际生产 ModelGateway/DashScope adapter，qwen3.5-plus，沿用生产真实生成参数，无 tool_choice/自设温度。任何业务 Handler（含删除）均截断。workspace 搜索只调用该用户范围的原只读查询组件；省略 scope 根据已核验的 current 缺省和空附件清单判断，不扩大搜索。

## 对此前结论的修正

- “旧会话下仍失败”不等于“新对话也会失败”。本轮恰好展示当前生产版本在空历史下 4/4 保留了原名。
- 这使旧上下文成为应进一步检验的因素，但不同测试时间、模型非确定性及小样本限制，尚不足以断言历史是唯一原因。个人偏好保持相同，未将其作为本轮变化变量。
- 范围缺省是独立问题：无 scope 时 current 附件为空，即使名字正确也无法找到工作区文件；并不是文件已被删除。
- 暂不把结构化原文选择器当作必须实施的既定方向；若继续修复，应先围绕上下文差异和范围合同补证，避免仅根据旧会话反复失败扩大架构。
