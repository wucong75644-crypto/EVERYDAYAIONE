用户话术：“更早的图片也翻一下，最早那张蓝白灯塔图再发我看看，不用重新做。”

修前两次记录分别位于`/private/tmp/skill-supplier-format-history-20261127/`、`/private/tmp/skill-supplier-format-history-repeat-20261127/`。前置分类识别explain/display_existing和ambiguous目标，identify却把未定位目标的动作统一改成other。主模型实际收到other/display_existing，原自动展示和交付完整性检查均未启用。首次模型查询后仅承诺核图就结束；第二次独立show_image被拒绝，后来resolve_request_target纠正后才实际展示。

第二次并非同批工具顺序错误。后续请求不包含所有终结调用；核对formal_model_response.raw_sse的response.output_item.done才可还原完整调用。原参数满足捕获的JSON Schema和原生校验，图片短引用有效。根因是应用意图/目标状态混淆及缺失交付闭环，不是供应商生图失败。

## 修复合同

1. 保留合法只读explain意图，未知图片仍用ambiguous。已解析只读动作引用不可见目标时保留展示/分析语义，清除不可信目标；编辑、生成等执行授权继续沿用原保护。
2. 动态投影READ工具：needs_selection时保留查询和view_image，隐藏show_image及对应案例；选择后开放展示。纯分析不开放展示。历史分页仍受当前认证会话冻结范围约束，不默认选第一张、最近图或唯一候选。
3. 查询每个候选返回requires_view_before_selection和完整selection_arguments，短引用统一编码；缓存页面按当前看图凭据重算标记。工具JSON案例与最终可用属性同步，目标工具同时包含explain/display_existing与explain/analyze的完整案例，保留旧稿和编辑案例。
4. 未绑定目标却调用show_image，返回REQUEST_TARGET_SELECTION_REQUIRED与完整恢复参数；已绑定目标继续走既有多图、版本和权限检查。模型示例只是候选，不是后台认定用户选择。
5. 选定目标由原展示dispatcher、权限检查和检查点交付，完成条件同时要求当前输入交付回执及匹配来源的真实image内容块。只说“已发”或看过图片不算完成。
6. 只有口头承诺时不向用户发布，保存模型草稿到内部消息并有限继续；记录当前输入作用域的尝试次数，最多两次且服从既有预算。次数和重放消息持久化，接续不重置。明确澄清正常停止；文件不可用、无权限、次数或预算耗尽如实报告，不换图、不重生成、不用模型自由总结伪装交付。
