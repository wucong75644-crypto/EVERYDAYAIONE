# Skill相关限制诊断与收敛方案（2026-11-22）

范围：当前任务工作树、基线`e084259011dbcbfec739dbc476510696bc0ba265`及本任务修改，覆盖聊天→Skill→模型→方案保存/编号→原生图片受理→供应商→结果展示→追加/恢复的相关调用链。不是全仓所有业务的无缺陷保证。主工作树未修改，未提交、未部署、未执行生产迁移。

## 判断依据

不存在统一的“大厂商品聊天标准”。下面区分官方设计原则、Grok公开源码事实与本项目适配，不能把我们的自定义审批当作大厂原样实现。

- [Anthropic：Building effective agents](https://www.anthropic.com/research/building-effective-agents)建议最简单可行方案，并只在有可测收益时增加复杂度，明确成本/延迟取舍。该文原发布于2024年，当前页面也指向[Managed Agents的演进](https://www.anthropic.com/research/managed-agents)；不能把旧文描述冒充其全部当前产品实现。
- [OpenAI Agents SDK Guardrails](https://openai.github.io/openai-agents-python/guardrails/)区分输入、最终输出及工具边界的检查，提供不同执行方式；允许采用检查器，不要求所有业务在每一步增加一个模型批准。认证授权、不可逆副作用边界仍然必要。
- [Google Check Grounding](https://docs.cloud.google.com/generative-ai-app-builder/docs/check-grounding)核对文本声明与给定来源的支持关系，输出支持度及引用；它不能证明我们用通用视觉模型做四处商品审批能可靠或更快，更不等于实物认证。
- Grok证据沿用已校验的`xai-org/grok-build@2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8`固定源码，见[逐项记录](REVIEW_Grok源码与三个新问题逐项核对_20261122.md)。已核对链路提供流式正文、工具权限、素材预算、真实错误、预算与恢复；没有与本项目同构的商品事实审批实现证据。`image_describe.rs`的额外视觉调用用于不能直接看图的harness，不能据此给本来能看图的模型强加一次审查。未重新声称查询了上游最新提交，也未声称运行过其Rust测试。

本项目采用的收敛原则：**模型理解和创作；后台可靠保存和执行；确定的权限/费用/素材/规格约束严格检查；不确定的质量判断不自动变成通用任务审批。**

## 已确认问题与本地修改

### A. 撤除商品核验的强制运行链

原实现将商品分析、整组方案、受理前、实际出图后都接入视觉模型。历史十套成功样本除三个创作阶段还调用了4次核验（含协议纠正）；最后接口两轮一轮188.31秒成功，另一轮84.10秒因核验器漏类别停止。带参考图的非商品改图也会被覆盖，范围过大。

出图后的模型“不确定”还被送入图片输出合同失败，影响成功状态和结算。这将模型意见与文件损坏/尺寸不合格混为同一种硬失败。它确实拦到过错字图，但这不足以证明适合强制覆盖全部任务。

已删除本轮新增且未发布的`product_fidelity.py`、配置项、四处运行挂接及专用恢复RPC调用，撤回未发布的迁移382及其回滚文件。不是改一个默认开关，也不新加另一个分类器。专用核验协议/恢复测试随被撤销功能移除，以“作者阶段不调用第二个模型”“原生受理不调用语言模型”等行为回归替代；原有权限、规格、收费和恢复断言保留。

旧测试记录/失败样本私有归档保留。旧冻结请求若有实验字段，只作为原始请求的一部分保留以兼容幂等重放，不赋予批准权，也不重新调用核验。历史失败记录不改成成功；没有生产核验数据需要迁移。本轮不安装新后台队列、不新增数据库表或函数、不加用户确认步骤。

新流程：

1. 普通聊天/写提示词：主模型输出，已有后台保存及可引用编号继续工作。
2. 选定专业电商Skill：保留原来的三阶段方法、事实来源、原生格式校验和有界纠错；移除外加评审模型。文案不确定由主模型如实说明，不能宣传为实物认证。
3. 用户要求执行：原ToolPolicy/确认模式/素材鉴权/尺寸和额度检查→持久化受理回执→供应商。
4. 下载结果：原文件、尺寸、透明度及结算检查→展示真实文件。没有商品保真“批准”标记；不对文字准确性作程序已认证的承诺。

### B. 收缩视觉问答的强制追问

复现：`目测图里粗线比细线粗几倍？`因规则只认识“宽/长/厚”等关键词、不认识“粗细”，被附加“本轮只问清口径，不补充任何目测”指令。用户已表达粗细与估计要求，不该机械增加一轮。

已移除该关键词驱动的强制流程。保留简短原则：结合图文/上下文理解口径；目测可给有标注的估计；只有真有歧义才澄清；精确数不能靠猜。新增三种原话回归，确保不改用户输入、不强制追问、不禁止合理估计。不添加测量模型或审查阶段。

### C. 修复重放时尺寸来源自我继承

撤核验的兼容性回归发现：原生同一调用重放会读到自身已保存的尺寸，来源由初次的默认项变为“任务”，最终冻结哈希变化，引发`CHAT_IMAGE_CALL_CONFLICT`。这不是需要新增审批，而是重建来源记录不稳定。

已对相同实际尺寸与参考图保留首次受理的来源元数据；最终RPC仍比较完整冻结请求。新增真实PostgreSQL测试：旧实验字段的请求能原样重放、仍只有一个子任务、受理阶段没有扣款；改变正文仍被拒绝。像素、参考图哈希及实际执行字段没有因此放宽。

## 历史审查的实际触发边界

不能只搜索到`review`就认为全部是每轮都运行的限制，也不能因属于历史代码就宣称合理。

- `handlers/chat/executor.py`为新任务读取`agent_task_model_directed_enabled`，代码默认True；`bootstrap.py`禁止同时开启model_directed和require_coverage_review。旧检查点则按自身保存值恢复，不套新默认。
- 旧非直接执行路径在初始化后通过`requirement_review.py`增加一个需求覆盖回合；追加后通过`requirement_changes.py`独立判断continue/amend等关系；图片规划还可能在`complete_task_step`及素材绑定前要求`plan_facts.py`回执。核验输出不完整可增加回合甚至停止，这与新增核验器具有类似的成本风险。
- `model_directed.enabled`与`requirement_changes.blocked`使新直接执行路径不把一般追加变成旧审批；真实新增素材的持久化、输入游标、权限与原生资源校验依然生效。源码默认不能证明生产环境配置和全部存量会话都走该路径，本轮未查询生产任务分布。
- 收敛方案：新任务继续使用现有直接执行模式，不增加独立语义审批；旧路径只为原有任务恢复保留，不再扩展新规则。若后续真实样本证明旧任务频繁卡住，才针对该旧路径评估把语义意见改为非强制、同时保留原生来源和副作用账本；不能通过删除回执要求或把旧状态标记为已批准来“简化”。本轮未修改这些历史状态机。

## P1具体方案（尚未实施）

### 1. 尺寸：把“精确”与“可近似”分开

复现“约1920×1080左右，接近即可”与“必须精确1920×1080”当前都失败。原图739×981→3:4、1601×902→16:9和默认1K已有正式测试，正常，不应推翻。

建议：有近似/就近要求时映射注册供应商支持的比例与分辨率档，回执同时说明请求与实际档位；用户明确精确时才校验精确输出能力，不能承诺没有的像素保证。没有近似或精确说明的像素要求建议采用用户已表达的就近匹配偏好，并明确实际规格；这是一条本项目业务默认，不能冒称大厂统一规则。多目标/真实矛盾仍需澄清，不自行裁剪、拉伸或额外收费重买。

影响位置：`image_size_requirements.py`意图和归一化、`chat_image_request.py`快照来源、工具尺寸说明及回执显示。优先沿用已有ratio/档位映射，不加尺寸模型、不加新任务状态。若要记录近似请求，作为说明元数据，不能把近似像素写进严格输出验收的width/height。

验收：近似1920×1080能受理；精确不支持时明确说明；3:4/2K、只改比例、只改分辨率、双图目标图、默认1K、已付费恢复继续原断言；回执绝不伪报输出达到请求像素。

### 2. 文字/生图：收敛同一份意图边界

复现仅说明现有函数误分类，未执行图片供应商、未发生测试扣费。当前多个正则既控制工具可见性又影响执行叙述，容易因为提示词中出现“生图”而相互冲突。

建议：明确“只写/文字就行/不实际执行”等限制优先；引号/代码中的动作词是资料，不能当执行授权；同时有独立明确生成要求时允许执行。复用本轮用户原文、已持久化追加、已有Skill/任务状态；主模型处理一般语义，不新增一个意图分类模型，不再为每种词句叠加新工作流。唯一来源供工具投影、执行叙述及原生提交边界共用。权限/确认仍由现有Policy与操作账本决定，模型自称“已授权”不算授权。

验收：上述两种写作变体只有文字；“生成一张图，再整理提示词”仍可执行；“先写方案，选中后再做”不购买；运行中明确改成生图按已接收新版本处理；旧稿按编号、多轮改图和复合文件任务不被阻断。

### 3. 配置与重复校验的维护收敛

只在确认重复且无独立安全/恢复价值时删检查。后续逐步让模型注册/已验证执行配置成为单一事实来源；专业Skill保留必要方法合同，普通聊天不用强制格式。已有自动登记和原生方案投影不能重新交回模型操作。没有新证据，不引入评分器、工作流引擎、额外模型或数据库迁移。
