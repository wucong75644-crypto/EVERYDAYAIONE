# 历史图片检索、条目规格与请求执行窗口

本次按用户确认的三个问题修改当前任务工作树；新增调用统一走新合同，不增加旧调用格式兼容分支。历史图片、保存稿和已受理操作继续作为数据保留。

## 历史图片

新增模型工具`list_conversation_images`，JSON Schema由`image_history.ListImages`产生，参数为order（oldest_first/newest_first）、source（generated/uploaded/all）、limit（1—20）、cursor（后台回执）。说明中给出首查、翻页、view_image、resolve_request_target、show_image和编辑的完整JSON用例。

查询复用本会话身份校验和native_resolver的历史截止位置。每次最多扫描100条消息，组合平面查询完成按context_revision/id定位的分页，不使用LocalDB不支持的嵌套OR或select(head=...)。无图片的页面仍可继续翻页。来源轮次通过真实原请求计算；无法确认时保留null，不猜测标题或视觉内容。重新展示不是一次新的生成结果。

候选、分页游标及成功看图回执保存到`_historical_image_catalog_v1`，绑定当前输入快照。新候选追加到短引用表，不改变已有引用。`request_resolution.freeze`允许经服务器查询找到的历史资源；目录外候选还须成功view_image核图后才能选中。native视图、展示、编辑仍负责真实文件、权限、签名、哈希与版本检查。查询和看图不创建生图任务，也不新增用户授权。

旧图展示复用`read_conversation_text(show_image)`和原图片交付回执，前端仍使用现有图片缩略组件。新工具不返回让模型直接拼Markdown大图的结果URL。

## 条目规格

`ImageRequestContext.size_rules`明确scope=all或items；items须给出当前目标稿件的item_indices。size使用原RequestedCanvas类型。size_rules与非空size互斥，条目重复覆盖、整组和条目混用、越界以及与选中旧稿范围冲突均拒绝。

路由及resolve_request_target共享同一类型和案例；保存、正文自动登记、旧稿规格修订、批准版本桥接、单图编辑和原生准备使用size_for(item_index)。第三项要求不覆盖其他项，也不让共享画布继承间接改变其他项。auto仅应用指定条目。精确像素、近似像素和供应商能力沿用原校验，不解析用户或正文关键词决定修改范围。

更新工具的base/updates说明、完整JSON案例及纠错回执同步；修订时保留已激活参考图Skill的展示约束。案例同时通过JSON Schema、SaveContent和参考图方法的实际章节校验，避免“结构合法但保存必败”的案例。

## 执行窗口

长期累计model_rounds_used与correction_count保留审计；接续真实新输入时建立execution_window，记录input_message_id及本窗口消耗。旧累计值不阻止选择历史任务。窗口初值包含本次接续之前已消耗的模型轮次，恢复同一输入、自动纠错或异步回调不会重置。

Python预算门、计数、纠错及结束处理使用窗口计数；模型直接执行分支预算耗尽时也输出partial说明，不再空回复。不改变已有操作账本、效果键、未决操作或确认条件，不因新窗口重发生图。

迁移386修改当前read_agent_content_followup及adopt_agent_task_followup；read_agent_task_followup已是该读取函数的包装，不修改废弃的前身读取路径。接续入库原子比较新窗口的真实输入、已用次数、累计次数、检查点和历史资源记录，拒绝伪造/清零。附精确反向迁移；应用降级前须先排空新格式活动窗口，不能仅回滚SQL后让旧解析器接手新状态。

## 动作与资源统一合同（2026-11-27 补充）

原始wire证明：用户要求“第三个做成一张图，正方形，一千就行”时，分类模型先正确给出execute_saved+content，首个主模型请求也提供content_source。随后主模型调用resolve_request_target，把intent改成edit而仍选择content。后台原先接受了这个矛盾组合，工具投影转成image_ref+edit_instruction，但派发层仍要求保存稿来源，导致反复REQUEST_TARGET_CONTENT_REQUIRED。不是后台凭空把execute_saved改成edit。

新增action_target_contract作为最小共同约束：content目标不能搭配edit/generate。模型可见Schema、分类和后续目标纠正、工具参数投影与派发前检查共享该约束。用原生校验器也支持的not/required/properties枚举组合表达；不依赖不被原生校验器执行的if/then。无图片语义动作的通用文字或视频内容消费者保持原行为。

保存稿文字/规格修订仍是write，修订并出图是execute_saved，明确重画是repeat；实际图片编辑才走edit。图片作为新方案素材时write/write_then_submit_images仍合法。没有按用户文字、标题或关键词重新分类，也没有自动把冲突动作改成另一个动作。

resolve_request_target补完整保存稿仅改文字和改后出图JSON案例，短引用投影保留实际图片编辑案例并增加引用图片写新方案的案例。纠错回执带相同结构和说明。矛盾组合在冻结目标、保存workflow和批准信息之前拒绝；失败保持原目标和原状态。即使旧检查点已有矛盾动作，工具投影不再隐藏保存稿输入格式，执行门仍拒绝派发，不能靠过时状态绕过。

分类器对这个合同失败只做一次有界参数纠正。保留既有数字字符串归一化、Pydantic默认值及全部批准/等待规则；没有借此上线整份工具参数的严格模式。测试曾发现过早验证完整Schema会拒绝原本可归一化的image_count="1"与默认字段，已将新增预校验收窄到本次动作合同，并增加保留原行为的回归。
