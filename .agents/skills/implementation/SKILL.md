# 开发实施

共同约定：[共同协作规则](../../../docs/development/COLLABORATION.md)。本 Skill 的职责边界不构成新的用户确认门；已有授权与证据按共同规则继承。

## 目标

严格实现已确认的需求和技术设计，以最小、可维护、可验证的改动交付结果。

用户已经授权完整任务时，在确认范围内自主推进，不为每个机械子步骤重复请求确认。

## 开发前

确认目标、关键行为和必要设计已达到可实施状态；这些输入可以来自用户明确指令、当前对话与项目事实，不要求单独设计文档。缺少会实质改变结果的前置决定时补齐相应职责；需要用户选择时暂停依赖部分，不用代码替用户决定。

开始修改前确认当前目录是独立任务工作树，当前分支是 `codex/task/*`。如果不是，先使用
仓库根目录 `AGENTS.md` 的任务工作树流程 创建或切换到任务工作树；不得在主工作树或其他任务工作树直接开发。

优先复用同一任务已经取得的任务地图、文件、调用链、设计和测试证据；证据不足或相关状态变化时，再定向补充读取。确认技术设计与当前代码没有因后续变化而失效。

复杂或影响不明的任务在编辑代码前先形成最小任务地图：完成条件、相关文件与符号、主要调用链、运行约束、修改清单、实施批次和验证计划。缺项时先集中补齐调查，不得一边发现一个文件、一边零散修改。简单、明确的局部任务读取目标、必要上下文和验证入口即可，无需补齐不适用的栏目。

集中调查先批量获得目录、符号、调用方、目标片段和测试入口；局部证据不足时继续扩大，必要时读取全文。不得为了“一次看完”读取明显无关内容，也不得为了节省 Token 在证据不足时提前实施。

调查以能够判断修改位置、影响范围和验证方式为完成条件。调用方或共享契约受到影响时补齐对应链路；不为局部任务机械生成目录或符号大纲，也不在证据不足时提前修改。

通过 Git 状态和差异识别用户已有修改，保护无关工作，不覆盖、不清理、不重新格式化与任务无关的内容。

明确本次修改范围及可验证的完成条件。技术设计中的文件清单是计划范围，不是忽略真实调用方的理由；发现必须同步修改但未列出的范围时，说明证据和影响，重大扩展需暂停确认。

## 实施

根据任务地图中的依赖关系和实施批次，连续完成一个完整逻辑批次后再进入下一批。保持接口和行为向后兼容，只修改实现当前需求所需的内容。

不得把逐文件“读取—修改—测试”作为默认循环。只有新证据推翻计划、暴露未知依赖、扩大必要范围或使已有证据失效时，才暂停当前批次并定向补充调查；普通实现细节不触发重新规划。

遵循现有代码风格和错误处理方式。只在能解释意图或关键取舍时增加注释，不机械添加注释、异常捕获、日志或抽象。

发现以下情况时暂停：

- 新证据表明当前设计不可行或需改变已确认决定；
- 需要作出尚未授权的需求、公共接口或数据契约变化；
- 必须引入未确认的依赖或基础设施；
- 需要执行尚未授权的不可逆操作或其他超出授权范围的操作；
- 安全、隐私、数据或生产风险显著增加；
- 合理实现明显超出已确认范围。

局部、可逆、不会改变已确认行为的实现细节可以自主决定，并在结果中说明重要选择。

## 测试与验证

代码修改后由本 Skill 在同一执行轮基于现有任务证据选择最小充分的测试组合，不为阶段转换重新调查。只有用户明确要求独立验证、风险需要专门验证或现有证据不足时，才单独应用 `test-coverage`。

修改完成后先确定一次验证漏斗，再按“静态或结构检查、定向验证、受影响模块、必要时扩大”的顺序执行。不得默认在开发前、每个文件或每个子步骤后和结束时反复运行同一测试，也不得自行写死统一覆盖率目标。

测试失败时先判断是本次回归、测试预期过期、环境问题还是既有失败。只修复当前任务引入或明确授权范围内的问题，其他问题保留证据并报告。

根据实际改动执行必要的类型、构建、静态检查、迁移验证或链路测试。验证方式由风险决定，不为满足固定清单启动无关服务或外部系统。

## 质量与文档

检查最终差异的正确性、职责、兼容性与实际维护风险；影响签名或共享行为时核对调用方。遵循项目确有的静态检查门槛，不自行恢复旧的行数阈值。确认没有无关修改、调试输出、冒充完整实现的占位逻辑或敏感信息。

更新会因本次变更而失真的接口说明、架构、运行或问题文档；具体路径遵循项目约定。简单任务使用当前任务记录，不为未更新无关文档单独生成说明。

发现无关代码异味只报告，不擅自修复。

## 完成条件

只有在以下条件成立时才报告完成：

- 已确认范围全部实现；
- 相关调用链保持一致；
- 风险对应的验证已完成；
- 没有本次变更新增的失败；
- 必要文档已经同步；
- 尚未解决的问题和限制已经明确。

最终报告提供可核验证据摘要：结果、实际改动范围、关键测试或检查结果、风险和未执行验证。详细文件、调用方和日志通过 diff、路径或工具记录引用，不在对话中重复展开。

## 阶段边界

本 Skill 不负责：

- 擅自扩大产品范围；
- 修改未确认的 UI、API 或数据库契约；
- 顺手重构无关代码；
- 为了让测试通过降低标准；
- 在没有证据时宣称兼容或完成。

实现完成后由本 Skill 在同一执行轮自审最终差异和已有证据。只有用户明确要求独立审查、高风险变更、证据冲突，或独立性会显著提高质量时，才应用 `review`。

## 交付格式

遵循项目 `AGENTS.md` 的增量精简输出合同。过程更新只用于阻塞、范围变化或重大新证据；正常机械步骤不逐项播报。
