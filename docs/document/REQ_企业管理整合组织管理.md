# REQ：企业管理整合组织管理

> 版本：V1.0 | 状态：已确认 | 日期：2026-07-27

## 一、原始诉求

用户提出：“组织管理”不应继续作为独立功能入口，也不需要改名取代“企业管理”；
它应作为“企业管理”中的一个板块，并与企业管理内已经重叠的功能合并。

## 二、项目现状

- `/admin` 的“企业管理”已经包含 ERP 凭证、企业微信、AI 配置、成员管理、
  部门职位和企业信息。
- `/settings/organization` 以独立弹窗提供员工管理和群聊管理。
- “成员管理”“部门职位”和“员工管理”均围绕企业正式成员展开，但当前分成三套界面。
- 独立“员工管理”只展示已建立企微映射的正式企业成员，是全部正式成员的子集。
- “企业微信”管理接入凭证；“群聊管理”管理机器人被动收集的企微群聊，两者职责不同。
- 相关成员任职与群聊治理接口实际只允许当前企业的 `owner/admin`。

## 三、已确认需求

### REQ-ORG-01 信息架构

保留管理后台一级模块名称“企业管理”。“组织管理”作为企业管理内部板块，不取代
“企业管理”，也不与平台管理、用户管理等管理后台一级模块并列。

### REQ-ORG-02 统一入口

组织管理能力统一从管理后台的“企业管理”进入。聊天顶部不再保留独立组织管理入口。
旧 `/settings/organization` 地址需要提供兼容跳转，不能形成第二套长期入口。

### REQ-ORG-03 成员能力合并

将当前“成员管理”“部门职位”和独立“员工管理”整合为同一套“成员与任职”体验：

- 以企业全部有效正式成员为权威列表；
- 同时展示企业角色、部门、职位、数据范围和企微关联状态；
- 邀请成员、企业角色管理、成员任职编辑从同一成员上下文进入；
- “已与企微机器人交互”作为成员状态或筛选条件，不再形成第二套员工列表。

### REQ-ORG-04 群聊管理归属

现有群聊管理并入“组织管理”板块，但保持独立于企业微信凭证配置。群聊管理继续展示
机器人已收集的企业群聊，并允许授权管理员维护群名。

### REQ-ORG-05 其他企业能力保持独立

企业信息、企业微信接入配置、ERP 凭证和 AI 配置继续作为企业管理中的独立板块。
本次整合不改变这些能力的业务含义。

### REQ-ORG-06 权限边界

组织管理入口和操作以当前后端治理边界为准，仅对当前企业 `owner/admin` 开放。
本需求不新增主管级权限，也不放宽后端授权。

### REQ-ORG-07 数据与兼容性

本次合并不得生成第二份成员或任职数据。统一界面必须继续使用现有正式成员、
任职和企微映射数据。现有后端权限校验必须保留。

## 四、成功条件

1. 管理员只需进入“管理后台 → 企业管理 → 组织管理”，即可完成成员、任职和群聊管理。
2. 同一成员不会再分别出现在三套含义重叠的管理界面中。
3. 管理员可以从统一成员列表识别成员是否已关联企微，并按该状态筛选。
4. 企业微信凭证配置与群聊业务数据在界面上职责清楚，不发生混合。
5. 非 `owner/admin` 无法看到或调用组织管理能力。
6. 旧组织管理地址不会进入旧弹窗，也不会产生失效页面。

## 五、明确排除

- 不修改组织、成员、任职或企微映射的数据模型。
- 不新增主管或普通成员的管理权限。
- 不重新设计 ERP、AI 或企业微信凭证的配置流程。
- 不在本阶段决定 API、组件拆分和代码迁移方式。

## 六、后续阶段

本需求交由 UI 设计明确企业管理内部导航、统一成员列表、群聊管理及状态反馈；随后由
技术设计确定最小复用方案、兼容路由和测试范围。
