# 主图详情图片即时移除

适用：`DetailPage` 草稿及已结束任务的输入图片；不删除工作区原文件。

## 行为与状态

点击 × 后立即隐藏图片并更新数量，保留未确认删除记录。参数和文字继续编辑，可连续移除其他已就绪图片。可选择一批新图片，本地预览立即显示；该批上传尚未结束时不能再开启另一批上传。

同一项目的保存、图片关联与删除通过 `enqueueProjectWrite` 串行执行，每次请求读取最新已确认版本。自动保存保留现有防抖和 revision 跟踪；等待期间修改不被服务端表单快照覆盖。服务端图片列表与待删除记录、本地上传项共同形成显示列表，旧响应不能复活待删除项，也不能清掉待上传预览。

删除记录在 `pendingDeletes` 中保留原图片和恢复所需预览；`imageOrder` 保留本次编辑顺序。明确失败仅恢复对应项。未确认删除暂时占用服务端图片名额，避免删除回退后超过 9 张。

开始生成先等待上传/删除完成，再保存最新表单并提交。等待期间只受理一次生成；任一素材同步失败取消本次生成。任务切换、新建和归档在图片操作未结束时仍受保护。账号/页面重置通过 lifecycleVersion 忽略旧回执，清理当前会话队列和预览。

## 失败和结果确认

- 明确 4xx 拒绝恢复对应项并提示；404/409 先读取项目核实，已不含图片视为完成。
- 409 且图片仍存在时，任务仍可编辑才使用最新版本重试一次；不会采用服务端表单覆盖本地编辑。
- 超时、断网、5xx、无效成功响应保留删除记录，读取服务端确认；只有图片确实不存在才收敛为成功。
- 图片仍存在或读取失败时显示“重新确认”。阻止后续项目写入和生成，文字及参数仍可编辑。尚未发送的排队删除恢复自己的图片。
- 用户重新确认时先读取当前项目。图片仍存在且任务可编辑时以当前版本执行删除，使结果与可能晚到的原请求收敛；不能把一次读取到“仍存在”当成原请求失败。
- 后端 `remove_image` 显式使用连接事务，确保项目版本检查/行锁、移除关联、顺序压缩和版本递增在同一事务内完成。连接池读操作可能保留 autocommit=True，不能依赖默认事务模式。

## 修改边界

实现位于 `useDetailPageStore.ts`、`DetailPage.tsx`、`GenerationSettings.tsx` 和后端 `detail_project_service.py`。现有 HTTP 接口、数据库结构、生产发布流程不变，不增加依赖。非删除操作的跨会话持久化队列不在本次范围；离开页面后以服务端状态为准。

验证覆盖即时隐藏、连续删除、恢复顺序、旧响应、本地预览保留、保存/关联串行、超时确认、409/404、等待生成、失败取消生成、账号切换隔离与删除事务边界。前端模拟服务端响应，后端单测模拟数据库连接；不代表生产耗时或真实生产数据库锁等待已验证。回滚代码需前后端同批回滚，不回滚数据库数据。
