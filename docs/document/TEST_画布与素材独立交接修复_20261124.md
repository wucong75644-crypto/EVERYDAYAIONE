# 画布缺省与素材交接修复（本地，未部署）

## 已确认行为与职责

- 用户明确输出比例/尺寸：按现有规格规范化、近似匹配或精确约束执行。
- 新创作无输出规格：auto、默认1K，上传图片不自动把参考图比例变为输出要求。
- 编辑已有图片：以实际编辑目标的文件宽高匹配支持比例；改前次成图继承真实成图画布及原清晰度档。
- 不同比例图片可以一起作为输入。主体、风格参考和画布目标独立，不能用删除风格参考的方法解决尺寸选择。
- 模型理解意图、选择素材角色和目标、撰写正文；后台登记既有方案原文、素材真实引用及画布事实，按原编号执行并冻结请求。不新增审批、词表、分类服务或数据表。

依据是公开接口与源码，而非声称复制厂商全部内部系统：

- [Grok Build image edit](https://github.com/xai-org/grok-build/blob/2bdd1d6a6369de0e8c68132ea4539e9abd9e14a8/crates/codegen/xai-grok-tools/src/implementations/grok_build/image_edit/mod.rs)：prompt、图片数组和aspect_ratio分离，缺省auto，没有混合参考比例的统一拒绝门。
- [xAI多图编辑](https://docs.x.ai/developers/model-capabilities/images/multi-image-editing)：多图和输出比例独立，默认行为由供应商定义，不能概括为所有供应商都继承首图。
- [OpenAI输出配置](https://developers.openai.com/api/docs/guides/image-generation#customize-image-output)、[KIE Image2接口](https://docs.kie.ai/market/gpt/gpt-image-2-image-to-image)：支持auto。auto不承诺固定方图或固定像素。

## 改动与调用链

1. 正式请求/追加事件 → 现有workflow路由：当前附件携带真实message/content位置，追加项保留原事件及resource_ref。路由用短material_index选择，后台还原真实引用，模型不复制长签名来做控制决策。
2. 原文生成 → 保存/自动登记：复用现有Material及ContentDocument，为缺省材料条目绑定同次语义选择，保留主体和风格角色及input/analysis用途。原有条目明确材料优先；伪造的来源不接受。新语义路径不再从正文的尺寸词法推导执行参数，正文不变；用户结构化规格、明确条目options和缺省策略依次生效。普通文字稿不会因为共享上下文而得到图片参数。
3. 保存 → 下一轮编号执行：原artifact、item_index、原文、材料数组和画布绑定一起恢复。画布reference_index按执行输入实际顺序计算，与原消息序号分离。
4. 原方案/服务器专用方案 → native预检/受理：新创作auto可通过原有模型能力校验；移除服务器方案auto拒绝及auto字符串当数值比例解析的错误。新策划不继承无关历史画布；续接旧方案仍沿用其冻结规格。
5. 回执 → 连续编辑：以认证来源的实际文件尺寸为准，不能将供应商实际竖图因原请求auto再次交给随机auto。覆盖旧方案素材时清掉失效的参考索引和旧auto缺省。
6. 已受理请求/恢复：不改请求冻结、积分、去重、权限、确认或CAS机制。新增可选上下文字段在缺省时不进入旧序列化，旧任务兼容。

补充：原ImageSizeError缺code属性，但策划错误处理会读取code。补齐属性，保留原错误码与提示。明确inherit_reference且无图继续拒绝，不能降为auto；既有auto历史不能覆盖本次明确的目标继承。
