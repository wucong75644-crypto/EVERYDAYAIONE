状态：按用户授权补齐文本/图片/视频整理、语义召回、默认授权范围及历史资料回填；新增迁移331仅在一次性本地测试库验证，未部署。设计和首批记录保留，最新实现与验收见第17节。

## 1. 目标及不可破坏的约束

上传一次后，原文件立即可看，后台自动整理出可读知识；在“目录资料”（原“展开编辑”）入口显示，员工搜索和 AI 检索共用内容。子节点变化后，系统自动识别当前节点到同一知识空间根节点的全部真实祖先，逐层判断是否需要更新汇总；不固定三级或任何业务层数。用户仍只需提问，问答可返回文字及原文/图片/视频来源。

- 人工正文、人工标签、人工更正不得被任何自动任务覆盖；人工清空也属于有效修改。
- 原始附件固定版本、历史回答固定来源、权限隔离继续成立。
- 摘要与检索片段是源资料的派生数据，不作为事实原件，不把推测升级为业务规则。
- 只有明确 rule 节点继续承担现有显式规则语义。整理文件、上级汇总不能偷偷生成或覆盖 rule。
- 不沿关联线、概要成员或外框范围自动传播。只有真实 parent_id 构成汇总路径。
- 不自动把内部知识发给外部客户。本期设计输出回答及链接，外发行为另按现有授权机制执行。

## 3. 用户能看到的结果：目录资料与文件资料，标签放在文件资料内

按用户最新澄清，卡片保留 **目录资料 / 文件资料** 两个主按钮：“展开编辑”更名“目录资料”；在“文件资料”的展开区域设置独立的 **标签** 按钮。不是在卡片上增加第三个并列主按钮。标签入口与上传/选择文件等操作分开呈现，管理的是当前节点的标签，不是某一个附件的标签。

| 入口 | 用户行为与复用 |
| --- | --- |
| 目录资料（原“展开编辑”） | 打开卡片下方原有编辑框，显示人工说明、自动资料整理和分支汇总；保留自动保存、关闭、四边/角调整尺寸与权限控制 |
| 文件资料 | 保留按钮下方的上传/工作区选择/引用文件菜单、已绑定文件预览及合法移除；展开区域新增独立标签按钮，不重做存储 |
| 标签（文件资料内） | 点击文件资料展开区域内独立按钮，查看和编辑当前节点的人工标签、自动标签及隐藏决定；复用标签弹窗及原手动保存链路，自动标签另存；打开标签编辑器后的焦点返回文件资料入口 |

标签入口统一到文件资料内，移除工具条上的重复标签按钮，保留现有标签快捷键；只读用户可查看，编辑仍按原write权限。标签不是备注改个名字：当前note为自由文字、labels为数组，不把备注原文转换成标签，不覆盖既有标签。

“目录资料”仍在节点下方同一框内按顺序呈现：

1. **人工说明**：现有 body 原样保留、可编辑并自动保存。无内容时不占大块空间。
2. **资料整理**：本节点附件自动生成的结构化内容，按适用情况、具体步骤、注意/例外、来源展示；按实际资料出现小节，不编造空章节。
3. **分支汇总**：有子节点时显示其业务范围与差异，附进入子节点的链接；叶节点不显示空汇总。

不新增一个面向普通用户的“切片管理后台”。检索片段隐藏，用户看到连贯章节。来源用小图标/链接；处理状态只在处理中、失败、内容过期或冲突时短提示，正常状态不堆说明文字。

现有 textarea 无法安全混编人工与自动块，不能用 Markdown 注释分隔后依靠正则辨认。编辑器内部必须用 block_id/owner/provenance 分区；呈现可连续，但保存通道分离。自动区默认只读。需要改写自动内容时，提供轻量“修改此段”：创建该段的人工覆盖版本，自动输出不再覆盖这一段。

备注兼容边界：最新澄清只要求标签入口放在文件资料内、正文入口改名；原note文字与既有右键备注能力保留，不擅自转换、迁移或删除。标签入口调整不改变备注的数据语义。

人工覆盖存独立记录，以稳定 section_id 关联原自动段；普通重新分片不影响该关联。源文件变更导致段落无法明确对应时，保留人工更正，标注待核对，不能凭模型相似度自动迁移或删除。

## 4. 上传后的完整状态流

### 4.1 上传事务与后台处理分离

1. 保留现有文件接收、校验和固定字节逻辑。上传成功后原文件立即可预览。
2. 同一个成功文件命令事务写入 outbox：object_id、binding_id、binding_revision、version_id、actor_id、org_id、container_id、event_id。不能在事务外依赖一次 HTTP 回调 enqueue。
3. 返回附件及 `knowledge_status: queued`；“上传成功”不等于“AI 整理成功”。
4. 后台原子认领任务，建立租约，重新授权，读取当前绑定固定版本；抽取/调用模型在事务外执行，不长期锁住用户编辑。
5. 先解析，按结构切片，生成有来源的节点章节与自动标签，在 staging generation 保存。
6. 校验输入版本、权限、结构、人工覆盖版本及最新目标指纹；通过后原子发布 generation 指针与对应片段集。
7. 同事务记录完整祖先传播需求，使受变化影响的派生依赖失效；任务按叶到根逐级执行。每一级的目录资料与自动标签作为同一generation一起检查、一起发布，父级完成后继续检查更上层，不因处理满三级或父级文字未变化而漏掉祖先的来源/覆盖状态校验。输入变化批量去抖，同一祖先只保留最新目标。

任务状态：queued → processing → ready / partial / failed / blocked_permission / superseded。租约过期可恢复；结果未知时按同一任务键查回执，禁止无条件重复模型调用和发布。

### 4.2 幂等与并发

- 文件任务键：org/container/object/binding/revision + extractor/prompt/model 配置版本。
- 节点目标指纹：当前人工 body revision、标题、人工标签/覆盖修订、有效绑定版本列表、直属子节点有效 generation、树结构版本、配置版本。另存内容语义指纹与依赖清单指纹：前者判断是否需要重新生成文字，后者保证文字不变时来源、权限及覆盖仍及时更新。
- 任务运行时携带 claim_token + monotonically increasing fence；完成时旧 fence 不可写入。
- 发布要求 target_fingerprint 仍为最新，且所有源依赖仍合法。上传v2后v1晚完成，只记 superseded，不得覆盖v2。
- 重复事件可合并；重试沿用已完成 extraction，不反复 OCR 同一源版本。
- 自动发布只增加 derived_revision，不增加 object.current_revision、canvas_node.revision 或画布 container.revision。避免后台整理让用户正文保存和画布撤销不断冲突。业务源变化仍按原逻辑增加业务版本。
- 发布检查依赖时使用确定顺序锁（当前 container/objects/bindings/derived 指针），防止授权检查与发布之间 TOCTOU；耗时模型调用不持锁。

## 5. 自动内容与人工内容的存储建议

沿用原 body 和 canvas_data.labels，不改其既有含义。新增以下职责明确的数据对象（表名为设计名）：

| 数据对象 | 核心字段/职责 |
| --- | --- |
| `kb_derivation_jobs` | durable outbox + 任务：scope、actor、kind、object/source key、target hash、state、attempt、lease/fence、retry_at、error_code、配置版本；唯一键去重；不存密钥 |
| `kb_derived_generations` | 不可变发布快照：object/scope、generation_id、target fingerprint、来源清单、配置版本、结构化 section blocks、自动标签、coverage、完成状态；待发布结果不可被搜索 |
| `kb_derived_heads` | 每节点 desired_fingerprint、current_generation、derived_revision、status；原子切换，不原地改旧 generation |
| `kb_derivation_dependencies` | generation → 源object/body版本、绑定/version、子generation、人工覆盖版本；权限和失效检查所需的可查询有向依赖 |
| `kb_knowledge_chunks` | generation、稳定section_id、chunk_id、文本/结构/位置、title/path、source_refs、text hash、chunk策略版本、可选embedding状态；事实片段与汇总片段标记区分 |
| `kb_manual_knowledge_overrides` | 稳定section_id或tag key、人工替换/隐藏、revision、actor、时间；人工编辑可恢复，不能让后台覆盖 |

`kb_derived_generations` 可以共存“资料整理”和“分支汇总”两类 section。持久队列分 source_extract、node_compose、parent_rollup，复用一套表与执行器，不另建三套系统。

同一源字节的解析缓存只在明确相同租户/所有权边界内复用。不能按全局 sha256 跨企业查出文件存在与否。绑定关系与可见章节始终独立授权，即使字节相同。

### 5.1 读取契约（建议增量接口）

`GET /knowledge/objects/{id}/document` 返回：

- manual：body、原 object revision（供现有 save_document 使用）；
- generated：generation_id、derived_revision、sections、coverage、processing state；
- rollup：同一 generation 中已授权的汇总段落；
- tags：manual_labels、auto_labels、suppressed_auto_labels、effective_labels；
- source链接必须由服务端根据授权源生成，不能采纳模型生成的任意 URL。

不把组合显示内容塞回旧 `KnowledgeObject.body`。旧 `GET object`、保存正文、历史正文 API 保持兼容。新前端读 document，body 保存继续原命令；document 失败时可继续编辑人工正文，不能以空字符串覆盖。

新增受控命令：`set_knowledge_override`、`set_auto_tag_suppression`，都带 command_id、expected override/derived revision。需要重试时重用原命令参数。人工覆盖操作纳入新的人工知识历史；如果接入现有画布历史，必须扩展其快照边界和回放校验，不能把异步生成结果混入旧 canvas_data 快照。

## 6. 标签更新规则

- `canvas_data.labels` = 人工标签，原 API 与撤销重做保持。
- auto_labels 来自当前节点有效人工正文、已解析附件和适量目录上下文。建议每节点最多8个自动标签、上级最多5个；限额为初始可调参数。
- 模型建议经过归一化、去重与词表映射，例如“拼多多/PDD”选统一展示词；归一化不得把不同业务含义强行合并。
- 有效展示/搜索标签 = 人工标签 + 自动标签 − 人工隐藏的自动标签。去重时保留人工来源。
- 用户删人工标签只改人工列表；删自动标签写 suppression。输入一个同名人工标签可明确保留，不因重新生成而消失。标签编辑器需能辨认来源。
- 重新上传只替换自动标签；人工标签、隐藏决定、手写正文不变。
- 上传所在节点及每一个真实祖先直到同空间根节点，都必须检查并按输入变化更新自动标签；不是只更新上传节点或直接父节点。上级自动标签从本节点人工说明、资料整理、有效子分支覆盖与标签中提炼，并保留来源依赖。
- 父节点只选业务范围/平台等代表标签，不复制所有子标签，不凭次数把事实变成规则。
- 每一级目录资料章节、分支汇总、自动标签和对应检索片段属于同一个发布generation。资料不变但自动标签变化也要发布；资料和标签都不变时仍校验源版本/覆盖依赖，无变化则no-op。
- 子节点移出/删除、附件解绑、源版本替换或撤权时，依赖失效同时作用于上级资料和自动标签；避免摘要已隐藏、旧敏感标签却仍可搜。人工标签按人工决策保留，但不得混入原本未经授权泄露的自动标签。
- 原图片 alt、附件名、标签都是资料，不作为系统指令；标签内容不授予权限。

## 7. 分片如何设计和更新

### 7.1 用户正文与机器片段的关系

用户看到的是完整 section，后台按语义切成可检索 chunk。一条处理步骤及其适用条件/例外不得被机械拆散；长章节可以多个片段，但保留共同 section_id、相邻指针及标题路径。

- 文字：按标题/段落/步骤拆分；初始目标每片400–800中文字符，通常不超过1200字符，同时有模型token硬上限；这是待真实售后问题调优的初始参数。
- 表格：每片重带表头、单位、所属工作表及行范围；不能混用不同行的型号、金额、条件。
- 图片/扫描件：OCR文字 + 必要的图示说明；保留页/图、区域坐标或定位锚点。无法辨认必须标记，不靠摘要补全。
- 视频：语音转写按时间段/操作步骤分片，保留 start_ms/end_ms；纯屏幕操作需要关键帧理解，仅转写不能标完整已读。
- 原文片段用于具体事实，节点整理用于综合阅读，祖先汇总用于路由/概览。检索中不能让多层相同摘要挤掉原始依据。

每片必须有：scope、object_id、binding_id/源body revision、version_id、generation_id、section_id、chunk_id、source位置、完整目录路径、人工/自动/汇总类型、内容hash、处理版本及覆盖状态。内容hash用于局部复用，不单独充当片段身份，避免重复段落混淆。

### 7.2 更新与发布

- 以源版本为单位解析； unchanged text hash 可复用 embedding，重新绑定新 generation 的来源。
- 候选片段整批 staging，只有验证通过的完整manifest可发布。不能让用户同时搜到一半旧文件和一半新文件。
- 文件更新后，新问题默认不使用旧当前绑定版本的派生知识；新代未就绪时仍能查看原件/人工说明，并明确AI未处理完成。旧片段只可由已有历史快照按固定旧版本读取，且仍须当前授权。
- 从任意来源片段补读原文上下文，避免只凭生成摘要回答；生成章节点出的事实必须有可验证 source_refs。
- 删除附件、删节点、撤权、跨父级移动后依赖校验立即屏蔽失效片段及受影响汇总，后台物理清理可以稍后。不能等待重新总结完成才停止泄漏/使用失效依据。
- 没变的文件不重新OCR；移动仅更新权限/目录/汇总上下文所需部分，嵌入输入包含路径时必须按路径版本重建，不能复用错误上下文向量。
- 单批片段数、文件数、祖先处理数量、token和处理耗时均有资源预算；预算是调度边界，不是业务层级上限。达到单批上限保存持久游标并继续排队，直到根节点；未完成时显示 pending/partial，不把前三层完成当成整条链完成。遇到父子循环、断链或越过权限边界则停止对应路径并明确记录原因，不让模型猜测补全层级。

## 8. 任意层级上级汇总：自动识别、按职责详略、检查到根

### 8.1 系统决定层级与边界，AI决定表达

用户不用指定级数。服务端从当前object.parent_id逐级查找，得到同org/container内完整祖先链以及根节点；包括空目录、单子节点链和不均衡树。实际层级只用于导航、任务排序与循环检测，不能按“第1/2/3层”硬编码内容格式，也不由模型自行判断父子关系或权限。

模型输入包含节点标题/人工说明、直属子节点目录、带来源的知识章节、覆盖与冲突信息，必要时包含已授权的祖先路径。AI判断当前节点主要承担操作说明、分类组织还是整体概览职责，提出本层表达及详略；这是派生展示策略，不修改节点kind、真实parent_id或显式rule。

### 8.2 每层显示到什么程度

| 节点实际内容与职责 | 自动内容应展示 | 不应自动简化掉的内容 |
| --- | --- | --- |
| 有明确执行任务的业务节点，无论深浅 | 适用情况、步骤、注意/例外、直接来源 | 关键条件、金额/时效/平台差异、冲突 |
| 组织多个业务分支的分类节点 | 覆盖范围、共同点、分支差异和进入下级的入口 | 区分不同处理路径所需的条件 |
| 综合目录或根节点 | 业务地图、主要分支用途、查找入口、重要缺口 | 影响选路的重要限制，不把概览写成通用执行规则 |
| 单子节点、资料很少的节点 | 简短说明或直接指向子节点，避免层层重复 | 本节点独有的人工说明和约束 |
| 资料复杂、跨多个条件的节点 | 可按主题分段，必要时增加细节并链接原始依据 | 不能仅为字数短而抹平差异 |

同一节点可以同时有“本节点资料整理”和“下级分支汇总”，不因为它是父节点就把自身操作细节压缩没了。自动详略由任务、资料复杂度、重复程度和关键约束决定，深度只作辅助上下文；不按层数直接截短。结构化输出记录detail_profile、sections、source_refs、coverage、conflicts；服务端校验来源、结构和预算，不接受模型伪造事实或跳过权限。

内容少就短，复杂就展开；模型上下文和单次输出仍有预算。超过预算时按直属分支分批生成分节，再组合概览，保留未覆盖清单和可下钻入口，不能用一句“全部已汇总”掩盖截断。

### 8.3 汇总输入与溯源

叶节点整理自己的人工说明及附件；父节点整理自己的资料，并概括直属子节点的人工内容和已发布资料章节。祖先不反复全文读取所有后代，使用有来源的直属子generation + 目录引用逐级更新。每条汇总事实保留直接证据与传递依赖；底层事实的适用条件、例外和冲突作为受保护输入向上传递，不能只凭越来越短的摘要推导新的结论。

可以合并共同内容，但平台、产品、时间、金额和条件差异必须保留。冲突列出差异与依据，不擅自选择规则，不自动改写显式rule。下级未在上级概览中出现的细节仍能被原始片段搜索，AI需要时下钻。

### 8.4 更新传播与不重复生成

每次变更建立一次传播记录，保存起点、结构快照/指纹、完整待检查祖先、处理游标及状态。按叶到根处理；一个文件变化可合并同一传播批次内的重复祖先任务。

对每个祖先分别判断：

1. 分支范围、事实、条件、冲突或展示职责变化：重新生成受影响章节与自动标签。
2. 展示文字可复用，但source版本、依赖或coverage变化：发布新manifest/generation，复用已校验文字与可复用片段，不浪费一次模型生成。
3. 内容与依赖均未变化：记录no-op，不修改本层展示；仍完成更上层的目标核对，不能把本层无文字变化等同于整条链无影响。

只有确实变化的层级发布更新。后台自动发布不再次触发业务源事件；由显式传播任务推进，不形成无限循环。单批处理不完则持久续跑到根，不要求用户手动“再更新上一级”。

节点移动时按新旧真实祖先链的并集检查：旧父级移除该分支影响，新父级补充；共享祖先去重。移动过程中以结构指纹fence阻止旧任务发布到旧路径。删除/解绑/撤权先屏蔽受影响知识与汇总，再重算；人工内容始终不动。

### 8.5 失败与深层树

- 子任务失败：仅汇总合法已完成部分，coverage记下未处理分支，不能声称已覆盖全分支。
- 祖先尚未检查/重算：对应链路为pending；已有段落只在源依赖仍合法时继续展示。
- 旧gen依赖失效：先停止提供相关自动段；无法独立验证其余段落时暂停整个自动汇总。
- 单次调度配额耗尽：保存游标继续排队；永久不支持、人工暂停或权限阻断分别给出状态，不能悄悄止步某一级。
- 极深树以迭代遍历、持久队列与有界批次执行，检测重复object_id；不递归撑爆栈，也不通过放开租户边界来寻找“更高主节点”。

## 9. 权限设计：派生内容不能成为另一条通道

### 9.1 结合当前权限模型的收敛选择

当前主要按container授权，自动传播先限定同一org、同一container的真实祖先链。禁止跨空间关联线或reference源节点正文自动进入汇总；现有显式文件引用已经为目标节点建立了合法固定版本绑定，按该目标绑定的现有语义处理，不擅自收紧或扩大既有授权。

不要求本期新增节点级ACL。但所有依赖检查按真实源对象/绑定表达，未来若加入更细权限，旧汇总也必须因授权覆盖不成立而停用。不能先把私密信息扁平复制进通用body再尝试隐藏。

### 9.2 后台与读取端

- 普通runtime不能直接写派生表、任务状态或领取任意scope；通过受控数据库函数认领、发布、设置人工覆盖。
- 用户事件只提供任务引用，actor/org由服务端受信上下文写入。Worker从可信任务记录建立DbScope；不可从模型输出或客户端JSON选择actor/org。
- 后台首次读取、外部模型调用前、提交发布时都检查actor有效性、目标write、每个源read、绑定当前性和scope一致性。权限已撤回则 blocked_permission；允许有权限负责人重新排队，不使用超级账号绕过。
- 如果特权函数用于列举调度候选，只返回任务ID/租约必要元数据；读私有正文仍在任务scope里进行。SECURITY DEFINER固定search_path，明确owner及grant，并保留RLS。
- 文档读取、标签列表、搜索片段、命中总数、排序、AI工具、历史来源打开、缓存命中都检查目标和传递源依赖，授权过滤先于LIMIT/计数与返回。不能在普通结果返回后仅前端过滤。
- 在当前container统一可见条件下可安全共享同空间汇总。若源依赖的可读人群不能证明覆盖目标读者，禁止共享发布，保留仅授权用户可见的读取组合或提示范围不支持，不自动扩大权限。
- ACL变化不要求重新计算事实文本，但依赖有效性、可见性缓存立即失效；缓存键含org/actor或可证明等价授权指纹、源版本和ACL版本。
- 不能依靠 index 中某个旧permission字段作为授权事实。每次检索/读取回源复核，尤其搜索历史generation也一样。
- 模型输出先做结构和source_refs校验，文档里的“忽略规则/发送资料”等内容按资料处理；模型不获得数据库、密钥或其他Workspace权限。

已合法展示/发送的历史文字无法靠撤权从人的记忆中追回；本设计保证后续检索、读取、来源访问及新的发布不继续泄漏，不承诺追溯消除已发送内容。新回答输出前再复核来源；生成途中撤权应停止继续提供对应知识。

## 10. 员工搜索和AI共用检索内容与受控查询策略

### 10.1 总体规则：分级定位为主，精准直达为辅

问题 → 确定已授权知识范围 → 定位业务分支/明确对象 → 召回少量相关片段 → 补读条件与规则 → 判断证据是否充分 → 回答并返回来源；不足才补查或扩大范围。

“搜索”与“交给模型阅读”分离。数据库可以在允许的索引范围内查找，但模型只接收已授权、去重且有预算的目录摘要/候选片段，不把整个知识空间正文送入上下文。不要求每个问题从根目录逐级调用模型：明确问题可以跳到目标节点，模糊问题才逐层发现；层级再深也不改变业务范围与权限。

建议新增 `knowledge_workspace/retrieval.py` 供 `Repository.search`、`KnowledgeRun.execute(search/read)` 共用；新增 `retrieval_policy.py` 管理范围、查询计划状态、预算、补查与停止。检索字段：卡片标题、人工正文、人工覆盖、有效标签、目录路径、附件原文片段、资料整理、合法分支汇总。

### 10.2 入口范围：检索扩大不能成为授权扩大

当前 `runtime.py::prepare_knowledge` 只在已有knowledge_refs时启用，`KnowledgeRun.start`从持久用户消息读取refs并建立快照。当前最多8个引用根、所选空间元数据最多10000对象等既有上限继续保留，不通过模型自报root或org绕过。

查询策略运行于本轮服务端确定的allowed_roots/snapshot manifest内。显式选择分支时，扩大范围不能越过该选定根；无显式选择的默认问答，未来须由服务端的企业/个人知识范围配置生成合法manifest，再启用同样策略，不能把“默认全库”实现为扫描整个数据库。

在显式范围内没找到但其他空间可能有资料，只能说明当前范围不足，或使用已获授权且已纳入本轮manifest的其他根；不能静默添加未选根。当前manifest的容量限制要有明确错误/缩小范围路径；若未来要按需增量快照，单独设计权限与版本一致性，不在查询规则中暗改。

### 10.3 分级定位

1. 从问题和本轮必要对话上下文抽取平台、业务、产品/编号、状态、时间等条件；代词承接不表示永远沿用上一题的分支，换平台/业务时重新定位。
2. 首先在允许范围检索轻量路由记录：节点标题、路径、有效标签、合法简短摘要、覆盖状态、子节点数量。路由记录也受相同源依赖权限检查，不泄露私密标题或标签。
3. 确定性条件（平台/编号/显式目录）优先；摘要与语义相近只辅助选路，不能凭相似度覆盖明确的平台差异。
4. 模糊时使用outline查看候选分支下一级，在少数相关候选中继续定位；明确的完整路径可由服务端一次解析到深层节点，不强制每层一次模型调用。
5. 只读目录/上级摘要不算读过事实原文，也不能以摘要没提到某问题就排除整条子树。直接索引至少覆盖叶子原始片段，供路由不足时兜底。

### 10.4 精准直达

问题含合法节点/文件链接、明确路径、唯一文档名或唯一业务编号时，直接解析授权对象及固定快照句柄；不接受模型拼接的未授权对象ID。

- 同名对象多个：结合路径、平台、版本筛选；差异影响答案又无法消歧时询问用户，不默选第一个。
- 直达后只读取相关section/片段，但核对路径、版本、适用条件与必要规则。
- 图片/视频只有定位链接时可直接返回可打开入口；用户问内容时仍须合法解析/读取，不能以文件存在冒充理解。
- 目标不在manifest、已删、撤权或不支持解析：返回相应不可用/未处理状态，不用扩大搜索绕开该约束。

### 10.5 范围内检索与逐步扩大

初始在定位子树中搜索，优先召回原始资料/人工知识，补充自动整理；汇总主要辅助定位，避免每层重复摘要挤掉直接证据。

找不到或关键条件不完整时：

1. 先在同子树改写查询、使用已维护的业务术语/同义词，去掉不必要的措辞，不擅自删除平台、订单状态等硬条件。
2. 再扩大到最近祖先的相关兄弟分支，按路由候选选择，不遍历所有正文。
3. 仍不足时在本轮allowed_roots范围内进行直接片段检索；依旧过滤确定性业务条件和权限。
4. 命中后回到该片段所属章节补读，而不是把扩大范围内的所有资料都读进来。

每次扩大由服务端计算合法scope handle，记录起止范围和原因。查无命中、资料未处理、权限不可用、版本冲突与用户缺条件分别返回，不能统称“知识库里没有”。

若某个硬条件由用户未提供而确实决定业务路径，例如不同平台退款规则相反，应先追问或分别说明条件，不能为了不追问而读遍全库后假定一个条件。明确比较两个平台时分别检索、保留分支来源，允许在预算内并行，不把跨分支规则混成一个流程。

### 10.6 补读上下文与事实校验

召回片段只是候选。准备回答前检查问题涉及的每个关键结论是否有依据，以及是否缺少适用条件/例外。

- 补读同一section的前后相关段落；必要时扩大到其所属章节，而不是默认读取整篇文件。
- 表格补回表头、单位、相关行；图片保留文字/图示关系；视频补相邻操作步骤并保留时间范围。
- 沿真实祖先路径查找适用的显式rule与人工条件；父层级不限三级。服务端解析路径、模型只读与本题相关的有效条款；规则来源无法读全则返回rules_complete=false，不能宣称已遵守全部规则。
- 继续复用 `KnowledgeRun.read` 的来源、分页、规则冲突判断与读取回执，但扩展为片段/section范围。不能只截取开头一段就当完整读取。
- 不因为父子关系就认定父规则优先；沿用显式规则的适用语义。冲突保留来源，需要时追问，不由摘要或模型自行定优先级。
- 已有人工更正优先使用其有效展示内容，同时保留原来源；更正与显式rule冲突时明确报告，不把人工更正偷偷升级成rule。

### 10.7 停止、续查与回答规则

| 情况 | 动作与终态 |
| --- | --- |
| 请求的关键点都有合法来源，条件/例外完整，未发现影响结论的冲突 | 停止检索，`answered`，回答并附固定版本来源 |
| 明确只找某文件/图片/视频，已找到唯一且可访问对象 | 停止，返回入口，不额外阅读无关正文 |
| 已有相关片段但缺关键步骤/条件 | 先补读；仍缺则有限补查，不能先给确定业务结论 |
| 缺用户平台/状态等关键信息，候选结论不同 | `needs_clarification`，只问必要条件，不无限扩大 |
| 有同等有效依据的实质冲突 | `conflict`，列出分歧和来源，不能靠继续搜直到碰到喜欢的结论 |
| 合法范围内已经检索但确无依据 | `not_found`，说明本次范围与缺口，不把模型常识写成公司制度 |
| 候选存在但未解析/截断/过期/撤权 | `source_unavailable`或`partial`，指出缺口；不得借相似资料补造 |
| 重复查询未得到新证据，或工具/token/时限预算耗尽 | 停止，`budget_exhausted`或`partial`，保留已证实部分与未覆盖项 |

停止判断结合证据覆盖、来源有效性、条件匹配及检索进展，不能只问模型“你觉得够了吗”或依赖相似分数。每个答案所需事实点可以存轻量evidence map：问题子目标 → chunk/section/rule来源 → 已读范围 → 缺口/冲突；这是审计结构，不要求输出模型隐性推理。

服务端配置总工具调用、检索轮次、候选数、读取token、最大耗时与并发预算；具体初值经真实售后问题压测确定，不冒称已有最佳阈值。分页、补读、扩大、重试都计入预算。长目录可一次服务端解析路径并分页返回候选，预算不能被实现为“业务目录最多查三级”。全面总结/全分支审阅属于更大覆盖任务，要遍历必要分页或明确部分完成，不能按普通单事实问题提前停止。

### 10.8 结合当前工具契约的增量设计

当前工具定义在 `backend/services/tools/definitions/knowledge.py`，`KnowledgeRun.execute`严格拒绝未知参数。现有search按root范围匹配标题+全文，outline按parent_handle看直接孩子，read每次最多10句柄、按字符分页；这些事实意味着不能只改一段提示词宣称实现子树检索。

建议保留四个工具名，以服务端新增会话状态和可选字段扩展：

| 入口 | 建议扩展与边界 |
| --- | --- |
| `KnowledgeRun.introduction` | 从“必须先outline”改为明确目标可直达、范围模糊先outline；写明补读/扩大/停止策略，不让简单问题强制走完整目录 |
| `knowledge_outline` | 保留parent_handle分页；返回授权路径、轻量路由摘要、覆盖状态，不自动返回各子节点全文 |
| `knowledge_search` | 增加可选scope_handle（只能由本轮服务端签发）、mode=route/evidence；返回少量候选、路径、匹配字段、source/generation及coverage；cursor绑定snapshot/scope/query/mode |
| `knowledge_read` | 允许受控chunk/section句柄；支持必要context模式补同章/相邻片段，返回实际范围、关联规则和next_cursor；模型不可提交任意偏移SQL或私有路径 |
| `knowledge_follow_reference` | 保留显式链接授权与防循环；不能作为范围扩大捷径，关联线不等于自动读取授权 |
| 新内部检索策略状态 | 在既有snapshot旁关联计划/预算/已访问scope和片段、query指纹、终态；同一输入重试不重置预算绕过限制；结果查回与重试幂等沿用既有原则 |

scope_handle表达“授权集合内的哪条子树”，不表达新权限。签发/扩大范围由策略服务验证ancestor链和snapshot成员，不能让模型把scope_handle设成另一个租户/空间。

`Repository.search`同样使用retrieval.py，但员工搜索不强制走AI多轮计划，直接返回合法命中节点及片段；两种入口共用内容与权限，执行方式适应任务。

### 10.9 召回能力、来源和观测

第一实施批次保留现有中文子串召回，补充标题/标签/路径/人工更正/资料章节与分片，按命中字段、条件与来源去重。术语映射可用于有限改写，但不得承诺子串搜索已具备完整语义理解。

语义检索作为同一服务可选通道：实施前核实现有embedding提供方和数据库扩展，不新增未经确认的向量库/依赖。启用后关键词与向量召回合并、授权、重排，实体编号和平台精确条件优先；相似度不作为事实正确或授权证明。

人工搜索可定位目录资料对应段或打开原件。图片放大、视频播放、文件预览复用现有PreviewHost/ImagePreviewModal；页码/时间定位按真实预览器能力接入。AI返回已读依据的固定版本链接，摘要不得冒充原文完整阅读。

内部记录：合法scope、检索/扩大次数、候选与实际读取量、去重率、补读范围、来源有效性、停止原因、时延与费用；私有内容日志按现有权限留存，不向普通用户暴露工具句柄或过程长文。验收重点是答对、少漏、少读无关内容及合理响应时间，不能只以“调用轮数越多越智能”评价。

### 10.10 研究依据与适用范围

以下是公开产品行为，不宣称所有企业产品均采用同一内部实现：

- 飞书aily《知识空间问答》：标准检索直接召回切片；单轮深度检索改写问题；多轮深度检索规划后续查询，同时明确耗时增加。https://aily.feishu.cn/hc/1u7kleqg_askknowledgespaceskill
- Azure AI Search《Agentic retrieval overview》：复杂问题可拆成子查询、并行执行、排序合并并返回引用；LLM查询规划等标为preview，不直接引入为项目依赖。https://learn.microsoft.com/en-us/azure/search/agentic-retrieval-overview
- Amazon Bedrock《How content chunking works》：先召回child chunk，再以parent chunk补全上下文；这里是文档内片段层级，不等于业务目录树，也不构成我们目录层级上限。https://docs.aws.amazon.com/bedrock/latest/userguide/kb-chunking.html

本项目据此选择“分级定位+精准直达+有限扩大+按需补读”，属于结合当前代码的推荐设计，不把厂商说明当作当前已实现功能。

## 11. 固定版本、草稿、撤销重做的衔接

- `KnowledgeRun.start` 新快照额外冻结可用派生generation及其输入manifest；重试沿用同一generation，不中途切到新总结。
- `_authorize`、`_text`、`_source` 增加generated/chunk类型；读取回执记录确切generation/section/chunk和来源覆盖。旧快照没有这些字段继续旧路径。
- 历史正文API仍是人工body历史，另提供派生generation来源查看。来源查询同时验证当前权限与绑定；失效时如实显示不可用，不偷偷跳到最新版本。
- 自动更新只刷新生成分区，不重置正在输入的人工textarea，不触发人工草稿dirty；标签自动变化同样不覆盖正在编辑的人工标签草稿。
- 自动整理不进入用户画布撤销栈。撤销文件绑定/分支结构等原功能仍按原语义；源状态变化后派生数据失效并重新整理，不能从旧画布快照恢复无效自动内容。
- 手动覆盖的清除/恢复须有明确版本与回执；完整接入现有画布历史之前，不承诺该新操作可用旧undo恢复。实施时应作为单独受测人工知识编辑命令交付。

## 13. 必须覆盖的验收场景

1. 新上传/Workspace固定/其他节点合法引用/上传新版都恰好产生一个有效处理目标；事务回滚无孤立可见任务。
2. 大图片/视频原件立即可看，处理中仍可编辑人工正文；失败不影响原件、不清空正文。
3. v1慢、v2快：只发布v2；超时/断电/多worker重复领取/旧租约完成都不会重复覆盖或发布半套片段。
4. 人工输入与模型完成同时发生：输入和光标保留；人工清空、格式、草稿恢复不被自动结果“恢复”。
5. 人工更改/隐藏自动段，下一次上传不覆盖；无法匹配源段时保留更正并提示核对。
6. 人工标签保留、自动标签替换、隐藏不复活、同名去重、画布撤销后有效标签重新计算；从上传节点到根的每一级标签均与该级资料同代发布。文件资料内标签按钮面向正确节点、只读查看/写入隔离、编辑关闭后焦点返回；目录资料名称与入口一致，旧备注内容不丢失。
7. 多子分支汇总、部分失败、冲突条件、超预算、深层树、重排/移动/删除/撤销、无真实父子关系的关联均符合规则。额外覆盖1/3/10/50层、单子节点长链、不均衡树与跨批重启续跑：每个合法祖先均核对至根，无三级截断；根节点也可因复杂资料生成分节，深层操作节点仍保留步骤。测试本层文字相同但源版本/coverage变化、完全no-op、分支移动后的新旧祖先并集、循环/断链/权限边界，以及同祖先多事件合并。
8. 同账号跨企业、跨账号、个人/团队/项目、viewer/editor/manager、排队后撤权、模型调用后撤权、文件解绑、父权限更宽：正文/摘要/标签/搜索计数/缓存/来源都不能绕过授权。
9. 既有显式固定文件引用仍按目标binding合法读取；自动汇总不能从关联对象偷取未引用正文。
10. 搜索卡片标题、正文、标签、图片文字和视频时间片；没有解析的资料不假装全文命中。AI不只读摘要就声称已读全分支。
11. 长表格、扫描PDF、无语音操作视频、截断/乱码/低置信识别分别给出正确覆盖状态，不能编造缺失内容。
12. 新问题使用新generation，旧输入重试仍旧generation；历史链接能解释原依据，撤权后不可用；旧客户端和旧快照兼容。
13. Mac/Windows编辑、中文IME、减少动态效果、输入自动保存、慢网/未知结果重试和关闭重开草稿照常。
14. 附件文本中的指令注入不能改变工具权限、不能新建rule、不能自行外发；模型生成的伪造source id/URL拒绝。
15. 明确节点/文件/深层路径精准直达；含糊问题分级发现；同名不同平台必须消歧；追问与跨平台比较不能沿用错误上轮scope。
16. 子树未命中→同树改写→合法兄弟→本轮允许范围；路由摘要遗漏的叶子事实仍能直接检索；不得扩大到显式选定根之外、未选空间或其他企业。cursor与scope篡改必须拒绝。
17. 命中小片段后补适用条件/例外、表头单位、图片关系、视频时间段和任意深度祖先规则；不得只读摘要就声称完整依据。两分支规则矛盾不混用。
18. 依据充分提前停止、只找文件不读全文、缺用户条件追问、无依据明确说明；重复空查询/时限/token/工具预算停止且标部分。断线重试不能重置预算、换快照或把旧不可用依据当新依据。
19. 人工搜索与AI检索对同一授权scope返回一致的有效内容；检索可覆盖大索引但模型实际读取量受控；全分支总结任务分页覆盖不足必须显示partial。
20. 比较分级定位、精准直达与混合策略的真实问题集：记录答案依据正确率、相关事实遗漏、无关读取量、工具次数与时延，确定预算和召回参数；不把“少读”优化成漏读关键规则。

## 14. 上线、成本和回滚

新增总开关及按租户/空间灰度开关；先影子运行比较真实售后问题，审核人工区零改动、授权矩阵、引用正确性后才开放自动内容展示/问答。首次回填按空间批量、有配额、有进度，不启动全库无上限任务。

推荐初始任务并发1–2、短时合并连续上传、每文件只处理所需版本；OCR/视频独立预算与最长时长。实际模型、embedding、OCR、转写/视觉提供方和预算还未核验，不在本文选定外部供应商或授权传出私有资料；优先复用项目现有可用模型适配，实施前列明必要目的地及成本。

关闭自动处理开关即可停新任务；关闭派生展示/检索开关回到原人工body/标签/附件搜索。保留数据/任务证据，不删除原件，不回滚历史迁移。新generated回答尚在执行时需保持兼容reader或明确终止后再回旧版本，不能让旧worker把新快照解释成空知识。

## 15. 需要用户确认的产品边界

本设计推荐：卡片目录资料/文件资料两个入口，标签位于文件资料内部的独立按钮；同一目录资料框内人工区+自动区；自动段默认只读，可转人工覆盖；自动更新不改手写内容；父级只汇总同权限空间的真实子分支。这里不再新增与现有画布无关的员工操作流程。

仍需在实施前确认：是否接受上述同框分区和修改自动段的人工覆盖方式；OCR/视频等实际模型服务与预算在配置核验后确认。默认全库问答的知识范围与直接面向客户的外发身份另行接入，不与本次“上传整理”混成一次隐式权限扩张。

设计修订（2026-10-24）：按用户确认，取消固定三级的任何理解；系统识别全部祖先至同空间根节点，AI按节点职责及内容复杂度决定详略，分批执行不限制业务层数。

设计修订（2026-10-24，查询策略）：补充分级定位、精准直达、合法范围内逐步扩大、必要上下文补读及证据/预算停止条件；关联现有四工具契约、快照边界、默认范围入口限制与专项验收。仅更新设计。

设计修订（2026-10-24，卡片资料入口与逐级标签，以最新澄清为准）：明确“展开编辑”更名“目录资料”；卡片保留目录资料/文件资料两个主入口，标签在文件资料展开区域内作为独立按钮。上传后的每一级祖先目录资料与自动标签共同检查、共同发布、共同失效；备注历史内容及既有语义保留，不转为标签。


## 16. 第一批实现记录（2026-10-25，后续补齐见第17节，未部署）

### 已接通的链路

- 新增331前向迁移；原302–330未改。上传、固定引用、新版、人工正文/标签/备注、真实父子结构变动在同一数据库事务内使本节点及所有同空间祖先任务失效并排队；旧父链也更新。
- 持久任务以actor/org执行，短租约、dirty/token fencing、最多5次重试；两路有界后台调度。读取源前和发布前重新检查权限与源指纹；旧结果不覆盖新版本。
- 目录资料保留原人工正文及其自动保存，另显示带来源的自动章节；人工更正单独版本保存、命令幂等、草稿隔离与未知结果核对。自动标签独立于canvas人工labels；标签入口位于文件资料。

- 人工搜索能命中人工标签、自动资料及可提取附件。AI快照增加派生片段句柄，支持目录路由、精准证据查询、局部子树、一次向上扩大、同段上下文；扩大不能越出本轮用户显式选定的root。
- 查询持久预算默认32次工具、48000读取字符、180秒；相同请求两次后停止。字符额度按一次read正文8000及显式规则4000的上限合计12000预扣，属于保守字符预算，不声称精确token计费。现有运行时负责工具调用顺序，未新增自治搜索代理。
- 历史来源固定generation；原绑定移除、来源删除/撤权后重新拒绝读取。冻结人工更正同时记录其来源generation，历史读取也重新检查，不能借更正绕过来源撤权。

## 17. 剩余计划补齐与真实模型验收（2026-10-25，未部署）

### 功能闭环

1. **图片与视频**：复用原私有固定版本读取及SHA校验；图片有界缩放后进行文字/可见操作识别，扫描PDF最多10页；MP4稀疏画面采样最多12帧，音轨按60秒切片、累计最多600秒转写。均直接传Base64到现有配置的DashScope端点，不生成公开文件链接。图像默认`qwen3.8-flash`，语音`qwen3-asr-flash`。视频取样与扫描PDF明确partial，不能宣称逐帧/全页读完；超额度保留原件入口，不冒充完整解析。媒体解码总预算60秒、单节点后台预算280秒、租约300秒；依赖缺失/解析失败进入原持久重试状态，原件和人工内容不受影响。媒体缓存按固定文件版本及模型配置隔离，读取每次核对当前合法binding，原始版本清理时级联清理缓存。
2. **语义召回**：复用同一DashScope连接，`text-embedding-v3`、256维、每次最多10条，单代最多64段，优先自动章节再原文片段。其余内容仍保留字面检索，不能将向量上限理解为删除内容。向量和片段同代固定；人工更正后不复用旧文字的向量。混合排序保留明确平台约束；查询向量失败降级字面检索，写入向量服务失败不阻止已验证文字发布。未引入外部向量数据库或跨用户内容缓存。
3. **默认问答范围**：`knowledge_default_scope_enabled`随自动整理主开关生效。没有显式@引用时，从当前actor/org实际RLS可读的空间生成本轮快照；显式@优先，继续缩小范围；不加入其他企业或其他人的私有空间，不根据模型参数增加权限。快照与输入消息锚点绑定，重试沿用原范围；禁止个人上下文的运行模式仍不启用。默认可见空间最多100、对象仍受原10000上限约束，超过上限明确报容量问题，不能静默截断后声称已查全库。
4. **历史资料与去重**：后台每批最多32项，沿既有知识空间owner身份重新取得合法scope，再进入两路公平队列；不以worker身份读取正文。旧资料无任务时自动回填，新源更新继续合并dirty。已完成且源指纹、配置、子代generation及权限均不变时复用原代，不再次调用模型。需要重试/批量重新整理时，`POST /knowledge/containers/{id}/organize?cursor=...`每批最多50节点，须有写权限，返回queued/next_cursor。
5. **依赖失效补强**：人工更正所依赖的旧代来源也进入传递依赖。分支移走后即使不再是祖先，后续原件删除/解绑仍会使相关更正及汇总失效、重新排队；不允许借人工更正保留已无权读取的来源。GIN依赖索引用于定位受影响的当前代。
6. **多次外发前检查**：媒体识别每次图片/语音调用前、摘要前、每批向量调用前重新核对权限与源状态。源变化或撤权时丢弃旧处理结果，不向后续模型步骤继续传递旧资料。
7. **来源与连续查询**：相同分页条件的默认值采用统一表示，显式补上`mode=evidence/expand=false`不使游标误失效；改变条件的游标仍拒绝，并返回可操作的重查说明。模型说明要求原样引用站内source.url。最终回答另以快照内对象/版本/binding/generation/chunk参数做确定性校验：匹配的链接恢复为服务端站内地址，未知参数移除链接并提示未核验；流式Markdown中识别出的知识版本链接固定指向站内权限检查页面。服务端原有已读取来源页脚继续作为可信引用。模型工具视图将解析状态转为中文说明，不改写原始正文。历史来源面板按账号/企业/对象/版本/generation重新挂载，切换身份立即清掉旧内容。
