# 节点目录资料与内容输入

确认日期：2026-10-25。用户已确认以下交互；未授权生产发布。

## 阅读与输入

- 点击节点的「目录资料」（只读角色沿用「展开查看」），在节点下方 12 个画布单位处展开资料窗口，默认左侧与节点对齐，宽 860、高 640；没有遮罩，不调整画布视角。八个边/角支持调整大小，窗口随画布移动与缩放；打开期间拖动空白画布即可平移。
- 顶部显示资料名称、节点标题与真实祖先路径。正文以 Markdown 展示，支持标题、段落、列表和表格。资料正文不提供直接编辑；已有正文优先展示，文件和分支的自动整理结果折叠在下方；没有正文时直接展示自动整理结果。整理状态与来源链接保留。
- 节点底部与资料窗口顶部均提供「补充 / 修改」，只有可写角色可见。输入区用于说明新增事实或要修改的内容；提交后由 AI 整理，保留已有节点标题及无关有效内容。只读用户不能进入输入区。
- 新节点首次输入支持较长内容，AI 生成简短标题、完整正文，确有独立事项时创建直接子节点，单一事项不拆分。Enter 提交并继续同级、Shift+Enter 换行、Tab 提交后继续子级；「提交并整理」按钮提交后结束输入。空白占位节点沿用原创建逻辑。标题双击改名仍只改变名称。
- 模型整理与保存期间锁定输入。整理失败不写入；保存结果未知时保留并锁定原操作，重试使用同一操作编号与原始载荷，不再调用模型。草稿沿用账号和企业隔离、浏览器持久保存与恢复权限复核。
- 关闭只读窗口直接返回画布；有未提交输入时沿用草稿放弃确认。旧版直接编辑正文留下的草稿仍通过原编辑器恢复，避免升级后丢失未保存内容。

## 保存与兼容

`POST /knowledge/content-plan` 只准备结构化内容，不修改数据库。模型输入在当前用户的 RLS 范围内读取正文、当前自动目录和子节点标题；正文、目录及子节点数量超出容量时明确拒绝，不截断后冒充完整整理。模型必须返回受限的标题、完整正文和至多 12 个子主题。已有标题由服务端固定，模型输出不能改名。

`apply_content` 命令携带确定的生成结果、原始输入、版本和画布布局；数据库函数 `kb_apply_content` 在一个事务内校验权限/空间版本/正文版本，保存正文与子节点并记录同一操作的撤销信息。已有节点不删除、不改名；新节点在整理内容与原始输入不同时，第一版保留原始输入，第二版保存整理正文。旧正文版本继续保留。数据库迁移为 `336_knowledge_content_input.sql`，不会自动执行。

内容操作的撤销/重做额外恢复对应不可变正文版本，创建新的当前版本，不倒退版本计数。其他画布操作与项目删除恢复仍委托原恢复函数。新命令仍触发现有资料失效、分片、标签与祖先汇总链；无需新增后台队列。

验收覆盖节点锚定与自由平移、只读权限、显式提交、首输入拆分、标题保护、模型失败无写入、草稿恢复、未知结果幂等、原文版本、整组撤销/重做、权限拒绝、版本冲突及中途失败的事务回滚。模型生成用合成响应验证；未调用真实模型验收，也未发布生产。

回滚优先回退前后端代码，保留兼容旧命令的迁移与历史正文恢复函数，避免已经产生的内容操作失去完整撤销能力。不要直接删除版本、操作回执或历史数据。
